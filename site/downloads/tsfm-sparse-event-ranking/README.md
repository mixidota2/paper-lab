# When, Not How Much — 数量予測で「いつ発生するか」を順位付けできるか

## Overview

**Radar。時系列基盤モデル（TSFM）の出力を、用途に合う指標で確かめるための評価論文。** 12モデルの点予測が学習不要の参照を上回る幅は、AP skillで最大0.031だった。凍結した表現から発生を学ぶ線形probeは29/30組で自分の点予測を上回ったが、Favoritaでは6モデル全てが生の履歴を使うLightGBMに負けた。用途を先に決めたい。モデル採用を急ぐ根拠より、比較の設計に価値がある。

## Problem

巡回や人員配置では、数量より発生する日を先に選びたい場合がある。著者は次の64時点を、正の観測が出る可能性で並べる。Amazon購入、Favorita売上、M5売上、NYC taxi、Web trafficの5データセットを使用。対象系列は40%以上が0で、評価する窓は発生と0の両方を含む。全期間休眠する系列の検出は評価していない。対象は混合窓だけだ。

## Core Idea

著者の主張：点予測、凍結表現の教師ありprobe、生の履歴に学習するロジスティック回帰・LightGBM、ランダム初期化した同型モデルのprobeを並べて比較する。それぞれ出力の質、表現の利用価値、直接学習に対する利点、事前学習の寄与を問う。

このLabの解釈：発生確率と数量の予測を区別してからモデルを選びたい。E[Y|x] = P(Y>0|x) × E[Y|Y>0,x] なので、平均による順位には正の数量も混ざる。中央値は発生確率が50%未満なら0になり、1%と49%を区別できない。ただし、原論文で実際の出力が全て厳密な0だったわけではない。

## Why It Might Work

解釈：発生ラベルで学ぶheadなら、数量を当てるための出力変換を迂回できる。だが、headの改善だけでは事前学習の効果と断定できない。同じ教師情報で学ぶ直接モデルと、ランダム表現からのprobeが必要になる。

CrostonやTSBも発生間隔・発生確率と数量を分ける先行手法だが、一定の期間予測では窓内の順位を付けられない。原論文§2はこの系譜と、凍結TSFM表現を分類に使う先行研究を整理する。ここでの追加点は、同じ将来ラベルで予測出力と表現を比較し、ランダム初期化を対照に置いたことにある。

留保：Webの評価対象の0ラベルの68%は欠測由来。欠測のない窓ではLightGBMとの差の中央値が0.039まで縮むが、母集団も変わる。Favoritaの0は欠品を含み得る。系列を等重みにするとWebの全TSFM点予測が参照を下回る。区間は系列単位の2,000回bootstrapで多重比較未補正。NYC taxiは1分割で、事前学習データとの重複も一部ある。順位精度を費用削減や確率校正の証拠として扱わない。欠測は非発生とは違う。

## Executable Understanding

Y = B × (1 + NB)、B ~ Bernoulli(p) を生成する。正の数量は1以上で、pを発生確率と一致させる。真の分布の中央値・平均・9分位点平均と、特徴xから発生を学ぶロジスティックheadを比較。各seedで700窓を訓練、独立した300窓を評価する。pは全て0.5未満。数量平均を5個に固定する場合と、発生しやすいほど数量が小さくなる場合を分ける。

APは同点群をまとめた閾値で計算する。同点は分けない。AP₀はスコアと発生数を固定してラベルを並べ替えた期待値。AP skill = (AP − AP₀)/(1 − AP₀) を窓ごとに計算して平均する。AP₀は一般に発生率とは異なる。同点群bに含まれる位置の数をsᵦ、その群の発生数をaᵦ、その群までに並んだ位置と発生の累積数をそれぞれCᵦとAᵦ、窓全体の位置数をn、発生数をkと置けば、AP = Σ aᵦ Aᵦ / (k Cᵦ)、AP₀ = (k−1)/(n−1) + (n−k)/[n(n−1)] × Σ sᵦ/Cᵦとなり、スコアが全て同じ場合に限ってこの基準はk/nへ簡約される。負のskillも保持し、混合ラベルを持たない窓は除外する。

## Results

実測値はresults.jsonとページの人工実験表に記録。固定数量では全て0の中央値のskillは0、平均とheadは発生順位を残す。数量が発生確率と逆向きに変化すると、平均の順位は悪化する。この条件は説明用に選んだもので、現実のデータで同じ逆転が起きる頻度は測っていない。

## What We Verified

Mechanism CONFIRMED。n≤6の全同点構成と混合ラベルを列挙し、Appendix B.1のAP₀閉形式を照合。一定スコアのskillが0になること、窓を混ぜると見かけのskillが生じるAppendix B.3の例も検査した。人工分布で中央値の情報消失と、数量平均による順位の混同を確認した。

## What We Did NOT Verify

Performance / Scaling / Production applicabilityはNOT TESTED。TSFM本体、実データでのprobe、LightGBM、ランダムbackbone対照、GPU時間、校正、在庫費用、人員配置費用は再現していない。人工headはTSFM表現を読まない。中央値による圧縮だけで原論文の全モデルの弱さを説明できるとも主張しない。
