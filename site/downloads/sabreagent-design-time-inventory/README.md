# SabreAgent: Language Models at Design Time for Lost-Sales Inventory Control

LLMを発注のたびに呼ばず、設計した知識だけを運用に残せるか

## Overview — 要点

SabreAgentは設計時にLLMが作った季節性の事前情報と発注ルールを固定し、運用時は予測と在庫最適化で発注する。InventoryBenchのNRは0.6311。改善の大部分はORの基本部分から来る。

## Problem — 問題設定

単一商品・単一拠点の逸失販売を扱う。売れなかった需要は翌期へ繰り越さない。ただし需要そのものは欠品時も観測できる。納期は0、4、または{1,2,3,∞}で、∞は注文の消失を表す。仕入れ費用・発注固定費・残存価値はゼロ。NRは各事例の報酬を完全即時充足の売上で割って0で下限を設け、1,320事例を等重みで平均する。

## Core Idea — 著者の主張と解釈

著者の主張：商品説明から季節性の形を作り、検証データで上限付きbase-stockの方策族を選ぶ。運用時のLLM呼出しはゼロだが、統計予測の更新と方策パラメータの探索は続く。

Labの解釈：注目点はLLMを置く段階にある。需要が欠品時も観測でき、仕入れ費用と発注固定費がゼロという条件が、強いORの基準を支える。実店舗の観測打切りや有料発注へ、そのまま移せるわけではない。

## Why It Might Work — 効くと考えられる理由

解釈：売れなかった需要まで将来の在庫不足へ足すと、発注量を膨らませる。販売量で在庫を進める計算は、この二重計上を避ける。注文が消失する条件では上限が過大な追加発注を抑え、季節性の形は少数の需要履歴を補う。どちらも常に有利とは限らない。

## Evidence — 著者の報告

一次資料[Table 1・Figure 4・Table 2](https://arxiv.org/pdf/2609.19760v2)の著者報告。公開比較の最良値はGemini 3 Flash OR→LLMの0.5380、SabreAgentは0.6311。別のバッチ実行経路では固定OR部分が0.6180、季節性と探索を加えた差が+0.0138。公式の事例別実行へ移すと約0.0006下がるため、この2経路の値を単純に差し引かない。

ペア比較の季節性効果は実データ3セルでNR +0.0179（著者表記+1.79%）、探索は確率的納期2セルで+0.0230（+2.3%）。相対改善率との混同に注意。同じDeepSeek-V4-Flashを運用時の補正へ戻した124事例の比較では、決定的納期の4セルでNRが低下した。

## Executable Understanding — 手元で確かめる

`uv run papers/sabreagent-design-time-inventory/run.py` で同じフォルダーのresults.jsonを更新する。Python標準ライブラリだけで動く。

在庫を0・2・8から始め、同じ入荷と需要の経路で通常の在庫ポジションによる不足と、販売量で進めた不足を比較する。別の有限動的計画では、定常需要・即時無料補充の条件で近視眼方策と全期間最適化を比較する。

## Results — 人工例の結果

初期在庫0の例では、通常の不足が6、販売量からの不足が1。その差5は途中の逸失販売と一致する。初期在庫8なら途中の逸失販売がなく、差も0になる。定常需要の小問題では21状態で近視眼方策と動的計画の価値が一致した。

## What We Verified — 確認した範囲

CONFIRMED：同じ経路での不足差と逸失販売の恒等式、上限付き発注の形、有限な定常需要の例における近視眼方策の最適性。SabreAgent全体のMechanismはPARTIAL。

## What We Did NOT Verify — 未検証の範囲

Performance / Scaling / Production applicabilityはNOT TESTED。InventoryBench、LLMによる季節性生成、検証による方策族選択、確率的納期のrolloutは追試していない。最小実験は一般定理の証明でもない。
