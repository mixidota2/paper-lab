# EXAONE Demand：需要の振る舞いで小さな補正を分ける

## Overview
EXAONE Demand 1.0は、需要向けの学習データと、需要の出方で配分を変える低ランク補正を組み合わせた時系列基盤モデル（TSFM）である。22データセットのMASE幾何平均は1.0667。TiRex-1.1の1.0818との差は約1.4%にとどまる。Worth Readingとした理由は、この差の大きさより、古典的な需要分類を学習の手掛かりにした設計にある。

## Problem
売れる間隔と、一度に売れる量のばらつきは別の性質だ。欠品で販売数がゼロになる場合もある。一般的な時系列データだけで学習すると、こうした短く疎な需要系列の割合が小さくなる。ただし需要専用と呼ぶ本論文のコーパスも、系列数の39.87%、観測点数の67.51%がエネルギーで、小売はそれぞれ17.18%、1.33%である（Table 11）。

## Core Idea
**著者の主張。** 1,130万系列・484億観測点のコーパスを整え、47,500系列の合成需要を加える。凍結したbackboneに共有LoRAを1本、需要クラス別LoRAを4本付け、系列ごとに補正の配分を決める。LoRAは大きな重み行列を、小さな行列の積で補正する方法である。

**本Labの解釈。** 業種名で専門家を分けるより、需要が途切れる頻度と数量変動で分けるという設計が読みどころになる。分類境界の近くでは複数の専門家を混ぜる。ただし論文の推論時の配分は、分類式そのものではなく、8統計量から学習したrouterの出力である。

ADI = 観測期間数 / 非ゼロ期間数、CV² = 非ゼロ数量の分散 / 平均²とする。式5–6は対数軸上で境界を柔らかくする。

`a = sigmoid(log(ADI / 1.32) / 0.35)`

`c = sigmoid(log(CV² / 0.49) / 0.60)`

`π = [(1−a)(1−c), a(1−c), (1−a)c, ac]`

順番はSmooth、Intermittent、Erratic、Lumpy。式10の教師分布は`π̃ = π² / Σπ²`で、温度T=0.5により優勢な成分を強める。routerはゼロ比率、ADI、CV²、時間との相関、1次自己相関、増加割合、全期間のCV、系列長を読む。比率と長さは式4の対数変換を通す。π̃とrouter出力qは別物である。

式11は`y = W₀x + Σₑ gₑ (α/rₑ) BₑAₑx`。W₀は凍結し、共有枝の重みは0.5、残り0.5をqで配る。共有rank=16、各専門枝rank=4、α=8。24層×6投影=144か所へ付ける。式12はrank方向に枝を積み、行列積をまとめる実装である。

## Why It Might Work
推測：共有枝が需要全般の補正を受け持てば、専門枝はクラス間の差へ容量を使える。生の系列から計算した統計量は、正規化後の表現で見失う需要の特徴をrouterへ渡す。ただしbackbone比の改善には学習コーパスとadapterの両方が含まれる。1.1050→1.0667をrouterだけの効果とは読めない。

古典的なSyntetos–Boylan–Croston分類（2005）を教師信号へ転用した点が、容量拡張を狙うMoirai-MoEとの違いになる。Chronos-2、TiRex-1.1は直接の比較対象であり、Table 8にLightGBMなどの木モデルはない。

## Evidence
一次資料は[原論文v1](https://arxiv.org/pdf/2609.30880v1)のTables 8–9。以下は著者報告で、独立再現値ではない。

| モデル | MASE幾何平均 | WQL |
| --- | ---: | ---: |
| EXAONE Demand | 1.0667 | 0.1138 |
| 合成データのみ | 1.0742 | 0.1147 |
| TiRex-1.1 | 1.0818 | 0.1161 |
| Chronos-2 | 1.0885 | 0.1406 |
| 凍結backbone | 1.1050 | 0.1169 |

MASEは履歴の季節naive誤差で正規化した絶対誤差で、小さいほどよい。MASEが1を超えても、同じ未来期間で季節naiveに負けたと直接断定はできない。分母は過去期間の誤差だからだ。データセット間は幾何平均で同じ重みを持つ。

Car partsのMASEは0.828、TiRexは0.916。対照的にElectricity (H)では1.010対0.912で負ける。22行中、掲載7モデルの最良は10行。実データ併用は合成のみより16行で改善する。全比較モデルへの勝率91.9%は836組の比較に対する割合で、系列の91.9%で勝ったという意味ではない。

著者自身が36の比較TSFMを同一手順で実行している。値の重複検査で学習候補358,008系列を除外したが、既存モデルの事前学習データには同じ除外を適用できず、比較は非対称である。評価には電力・M4・計算資源が多く、販促共変量、在庫費用、サービス率の比較はない。

## Executable Understanding
`run.py`は5乱数seedで、4種類の人工需要を作る。各seedで別の160系列を使い、SES、Croston、SBA、TSBから全系列共通の手法を選ぶ。未使用320系列では150期間の履歴から30期間を予測し、同じ履歴とMASE分母で比べる。

比較する混合方式はSmooth→SES、Intermittent→SBA、Erratic→Croston、Lumpy→TSBという説明用の割当で、式5–6のπで平均する。この対応はLabの仮定で、論文の学習結果ではない。数量はGamma分布を丸め、Bernoulliで需要を間引く。論文の負の二項分布による生成器とは異なる。

ページの平面ではADIとCV²を動かし、πとπ̃を比較する。在庫図は潜在需要を固定して、販売数だけが在庫で切られる様子を見る。両者を分けて記録できることが、合成需要の利点である。

## Results
混合方式は5seed中4seedで、検証用データから選んだ共通手法よりMASEが悪化した。seed=19のみ0.8848→0.8702へ改善した。**安定した精度向上はNOT OBSERVED**。分類の重みが連続に変わることと、混ぜれば精度が上がることは別の命題である。数値はresults.jsonに保存する。

## What We Verified
MechanismはPARTIAL。式5–6の確率和、両境界での均等比率、数量を10倍してもADIとCV²が変わらない性質はCONFIRMED。古典予測器の混合を実行したが、学習routerやLoRAは実装していない。

## What We Did NOT Verify
Performance、Scaling、Production applicabilityはNOT TESTED。公開重みの推論、22データセットの成績、8GPU学習、在庫や利益への効果は未検証である。原論文も潜在需要の復元を将来課題とし、合成データで欠品を入れたことだけで実店舗の欠品補正を達成したとは言えない。

## Implementation
Python標準ライブラリだけを使う。リポジトリのルートで実行する。

```sh
UV_CACHE_DIR=/tmp/uv-exaone uv run --no-project papers/exaone-demand-routed-tsfm/run.py
```

`stats()`が式1–2の統計量、`membership()`が式5–6と10、`forecasts()`が4つの古典法を担う。乱数seed、検証方法、全22行の転記値はrun.pyに固定している。HTMLはlab.yaml、README、results.json、mapping.mdとwidget生成コードから作る。
