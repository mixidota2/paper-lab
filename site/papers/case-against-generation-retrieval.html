概要

Web 規模で生成推薦や zero-shot ranking を動かすと、計算量と grounding が問題になる。本論文は二塔モデルを LLM 時代の表現学習で更新する。

問題設定

二塔モデルはアイテム側を事前計算できる一方、ユーザーとアイテムの細かな相互作用を落とす。cross-encoder は強いが、候補生成には重すぎる。その隔たりを、教師からの蒸留で埋める。

核心

論文に書かれていること

著者は、ユーザーとアイテムで共有する LLM エンコーダ、EOS pooling、データセット横断の転移学習、cross-encoder から two-tower への蒸留、ユーザー塔だけの latent reasoning を組み合わせる。

アイテム表現は事前計算できるため、検索時はユーザー表現との内積と近似最近傍探索を使える。論文は、公開ベンチマークで cross-encoder が既存法を上回り、two-tower 学生も競争力のある retrieval 性能を示したと報告する。

読書メモ

LLM を使うことと、推薦を自己回帰デコードにすることは別の選択だ、と整理できる。意味表現の改善を取り込みながら ANN の運用特性を残す設計は、既存の候補生成をすぐ置き換えられない場面で読む価値がある。

なぜ効きそうか

読書メモ — 著者による因果の立証ではありません。

アイテム表現を前計算できれば、検索時に逐次トークンを生成しなくてよい。cross-encoder の候補集合内の順位分布を学生へ渡す蒸留は、二塔モデルが失う相互作用の一部を補う方法として読める。

根拠

論文は Amazon の3公開ベンチマークと社内の大規模データで評価する。公開実験では Recall@K と NDCG@K を使い、社内実験では retrieval の NE、staleness、データ・モデルのスケールを扱う。

公開コードは論文ページで示されていない。社内データの実験は、第三者が同じ条件で再現できない。

実行可能な理解

このライブラリは ANN と生成型 retrieval の性能比較を実装していない。効率についての議論は原論文 §4.3 を参照する。

結果

著者は、生成型 retrieval が逐次デコードを要するのに対し、提案法はユーザーを一度エンコードして、事前計算済みのアイテム表現を ANN で検索すると説明する。論文は社内実験で staleness への強さとデータスケールでの優位も報告している。

検証できたこと

このライブラリは独自の実験を行っていない。検証欄はすべて「未検証」である。

検証していないこと

公開ベンチマークの数値、蒸留の寄与、社内 NE、staleness、データスケールの結果は再現していない。
