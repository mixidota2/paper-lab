概要

推薦で LLM を使う流れの一方に、「推薦＝生成（セマンティック ID のデコード）」がある。 ただ大規模 retrieval では、自己回帰デコードのレイテンシと、トークンが実アイテムに 接地しない問題がボトルネックになる。

この論文は古典的 two-tower を LLM 時代の表現学習で立て直す。ユーザーとアイテムを 共有 LLM で別フォワードし、EOS プーリング、データセット横断の mid-train、 強い cross-encoder 教師（yes/no + ユーザー条件つき NTP）からの CE2TT 蒸留、 ユーザー塔だけの latent reasoning を積み上げる。アイテム側は事前計算可能なままなので ANN のまま配信できる。

公開 Amazon 三データでは CE が概ね SOTA。0.6B の TT 学生は 8B 級の OneRec-Think に R@10 で張り合う。社内では学習データの 0.5% で従来 DLRM two-tower と NE パリティ、 凍結時の staleness 耐性も強い、と主張する。

ラボの玩具は精度表を再現しない。カタログ上で「ANN/内積」と「SID 逐次デコード＋接地ミス」の コスト形だけを対比する。

問題設定

生成 retrieval は理論上はエンドツーエンドだが、出力は離散トークンであり、 アイテム ID への写像はモデルの外で起きる。そこで grounding 失敗が下流に伝播する。 一方 two-tower はアイテム埋め込みをオフライン索引でき、工業的 CG の標準になっている。

問いは単純で重い。LLM の意味の深さを表現バックボーンとして載せたとき、 古典 two-tower はまだ戦えるか。生成でファネルを置き換える必要があるのか。

核心

著者の主張

LLM-native two-tower: 共有エンコーダ + EOS、CE 教師を yes/no ヘッドとユーザー条件 NTP で強化し、 候補集合上のスコア分布を TT に蒸留（CE2TT）。ユーザー塔のみ Coconut 風の latent 1ステップ。 公開ベンチでは CE が多くの指標で最良、TT は R@10 で ORT を上回るケースが多い（バックボーンは 0.6B vs ORT の 8B）。 本番では DLRM と NE パリティを 0.5% データで達成し、凍結評価で staleness に強い。

Research Bot の解釈

「生成が retrieval を置き換える」より、「LLM の利得の多くは意味表現にあり、 デコード形式は必須ではない」という仮説を産業データで押している、と読む。 ANN を捨てない選択は、レイテンシ・接地・既存索引との互換で実務的だ。 一方、公開 Amazon は Web 規模 CG そのものとは限らず、生成系のオンライン勝ち事例との 正面比較も限定的。勝ち筋は「意味＋因数分解」側にあり、「生成だから」で説明しきれる話ではない—— このスレッドとの接続点はそこにある。

ラボでは grounding miss とコスト比の玩具のみ。NE や R@K は未検証。

なぜ効きそうか

推論 — 著者の主張ではない

内積 retrieval が安いのは、アイテムを一度埋め込んでしまえばクエリごとにデコード列を 伸ばさないからだ。接地ミスがゼロなのも、候補が最初からアイテム ID だから。 教師 CE が相対順位を持ち、それを KL で学生に渡すのは、双エンコーダが失う相互作用を ソフトラベルで補う定番の筋で、LLM 表現との相性も良い。この説明は自然に聞こえる。

根拠

論文: Amazon Beauty / Sports / Toys での SOTA 表と TT アブレーション（特に CE2TT の寄与大）、 社内 NE・セグメント・staleness・データスケール表。限界は公開コードなし、社内詳細の再現困難、 生成ベースラインとのサービング条件の完全一致ではない点。

results.json は合成カタログ上のコストと grounding_miss_rate のみ。

実行可能な理解

run.py はカタログサイズ固定の合成クエリで、(1) ユーザー1回エンコード + ANN 風コスト、 (2) SID 長ぶんの逐次デコード + トークン接地ミス確率、を並べる。論文 §4.3 の効率議論と 導入部の grounding 懸念を、数値のオーダー感だけで掴むための装置。

検証できたこと

玩具では ANN 経路の grounding miss は常に 0。生成 SID 経路は設定したミス率どおり欠測が出て、 平均コスト・レイテンシ段数が高くなる（Mechanism: PARTIAL）。これはサービング形の説明用で、 推薦品質の確認ではない。

検証していないこと

  • Amazon R@10 / NDCG や CE・TT の学習
  • CE2TT・NTP・latent reasoning のアブレーション
  • 本番 NE パリティ（0.5% データ）と staleness
  • 性能・スケーリング・本番適用性は NOT TESTED
