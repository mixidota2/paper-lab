generative-rec-vs-retrieval
01

概要

LLM を推薦に使うなら、候補も生成しなければならないのか。Meta のこの論文は、その前提に異議を唱える。LLM を二つの塔の表現学習器として使い、候補生成には ANN を残す設計を提案した。

共有 LLM、EOS 表現、cross-encoder 教師、蒸留、ユーザー側の latent reasoning を重ねる。それでも配信時はアイテム埋め込みの近傍探索で済む。公開 Amazon データと本番の双方で、この選択を検証している。

本ラボでは、学習品質を再現しない。事前に索引化した候補を引く経路と、semantic ID を一つずつ出す経路を並べ、配信時の形と接地失敗の違いを小さく可視化する。

02

問題設定

生成型の候補生成は、トークン列からアイテムを導く。表現力は魅力的だが、逐次デコードには段数があり、出した記号を実在アイテムへ結びつける処理も要る。

two-tower は逆に、ユーザーとアイテムを別々に埋め込み、アイテム側を前計算しておける。大規模な候補生成で広く使われる理由は、近似最近傍探索（ANN）で速く探せる点にある。

問いは、LLM の意味表現を使っても、この分離を保てるかだ。本論文は「生成か検索か」を二者択一にせず、意味理解と配信形式を切り分けた。

03

核心

論文が主張すること

著者は共有 LLM でユーザーとアイテムを別々に符号化し、文末の EOS 表現を用いる two-tower を構成した。教師となる cross-encoder には yes/no の判定と、ユーザー条件付きの next-token prediction を与える。教師の候補順位を CE2TT 蒸留で two-tower へ渡し、ユーザー塔だけに latent reasoning を加える。

公開 Amazon では、教師の cross-encoder が強い結果を出し、0.6B の two-tower 学生は R@10 で 8B の ORT に並ぶ、または上回る結果を報告した。本番では学習データの0.5%で既存 DLRM と NE の同等性を示し、データを凍結した条件でも staleness への強さを報告している。

このラボの読み

読みどころは「LLM を使うこと」と「生成すること」を分けた点にある。LLM の価値の多くが表現にあるなら、候補を出す最後の形式まで自己回帰にする必然は薄くなる。

ただし、これは生成型の推薦が常に不要だという証明ではない。公開ベンチと本番の詳細には距離があり、各方式を同じ配信条件で比べた完全な比較でもない。ここで強く支持されるのは、ANN を残す道が競争力を持ちうる、という判断だ。

04

なぜ効きそうか

ここからはラボの解釈です。著者の因果主張ではありません。

【ラボの解釈】アイテムを前もって埋め込めるなら、リクエスト時に重い処理をするのはユーザー側だけでよい。ANN は候補を実在のアイテムIDとして返すため、出力記号から商品へ戻す段階もない。

蒸留は、cross-encoder が候補ごとの組合せを見て付けた順位を、軽い two-tower へ移す手段になる。どの要素が公開結果や本番結果をどれだけ押し上げたかは、論文の主張を超えてこのラボが断定できる範囲ではない。

05

根拠

根拠は二層ある。公開側では Amazon のデータセットで cross-encoder、two-tower、既存手法を比べた。本番側では、0.5%の学習データで DLRM と NE の同等性、さらに staleness 耐性を報告している。

これらは論文の実験結果である。ラボが実行するのは、ANN と semantic ID デコードのコスト形、そして意図的に入れた接地失敗だけだ。R@10、NE、蒸留の効果を検証した結果ではない。

06

実行可能な理解

run.py は1万件の合成カタログに500件の問い合わせを投げる。Baseline の generative_sid は4トークンの semantic ID を順に出し、トークンごとに接地失敗の確率を持つ。Proposed の ann_two_tower は、ユーザーを一度符号化して索引を探す。

比べる指標は相対コスト、待ち段数、接地失敗率である。関連性のヒット率は合成の乱数なので、品質比較として読むべきではない。

08

検証できたこと

この設定では ANN 経路の接地失敗は0で、逐次デコード経路には設定した失敗が生じた。後者はデコード段数と相対コストも大きくなった。配信形式の違いを説明する確認としては PARTIAL である。

実験のコードが作った差は、パラメータを変えれば変わる。Amazon の検索品質や、LLM 表現の有効性を確かめたわけではない。

09

検証していないこと

  • Amazon の R@10、NDCG、cross-encoder の成績
  • CE2TT、yes/no 教師、latent reasoning の寄与
  • 0.5%データでの DLRM との NE 同等性と staleness 耐性
  • 性能、スケーリング、本番適用性
10

実装

run.py は外部データセットやモデルを使わない。ann_retrieve と generative_sid の小さなコスト模型を同じ乱数シードで動かし、results.json に集計する。

実行には uv run python papers/case-against-generation-retrieval/run.py を使う。接地失敗率は論文から転記した値ではなく、この模型だけの設定値である。
