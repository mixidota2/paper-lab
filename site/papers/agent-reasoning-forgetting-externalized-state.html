推論を消した後も、必要な状態を読み出せるか

このLabを読む

問いモデル / 手法どの記録を消したかで、次の行動が変わる総費用は、残る履歴と後続の要求回数で決まる根拠小実験限界

概要

Radar：状態の外部化という設計原則に注目する。 必要な制約や中間結論が推論にしか残っていない場合、後続で再導出・追加推論・再計画が起きる割合は67.31%。コードやファイルなどに移っている場合は36.15%だった。ただし、52状態と213状態を観察的に比べた値であり、差の31.16ポイントを外部化の因果効果とは読めない。

原論文のTable 3を優先して事前判断を訂正する。80課題ではICLRが0.7376、Delete All Thinkingが0.7178で、同点ではない。260課題でのICLRの0.717775と、別の課題集合の結果を混ぜない。手法の採用判断には、主評価のseed反復や信頼区間が足りない。

問題設定

長い作業では、過去の推論を毎回入力すると処理量が増える。しかし、その推論にしかない制約まで消すと、再調査が必要になる。次のtool呼び出しが変われば、その後に読む情報や作業の終了時点も変わる。削った文章の割合だけでは、作業全体の節約量を予測できない。

たとえば「このAPIはBearer形式では通らない」という結論が推論にだけある状態と、修正したコードやエラー出力に残る状態を区別する。ファイルが存在しても、次の判断で読み出せなければ代替にはならない。

核心

著者の主張 · 論文に書かれていること

著者の主張：Interaction Aware Compression for Long Horizon Reasoning（ICLR）は、凍結したQwen3.5-9Bで推論ブロックの予測エントロピーを採点し、低い80%を削る。実行役はDeepSeek-V4-Flash。action、tool引数、観測、最終回答は保存する。本文とAppendix Iは、導いた状態が外部へ移ると推論を置き換えやすくなると論じる。

解釈・批評 · 読書メモ

本Labの解釈：採用したい設計上の問いは「削除対象が、まだ唯一の情報源か」である。エントロピーはその判定の代理指標にすぎない。ACON、PACE、SelfCompact、SWE-Pruner、Self-GC、Context-as-a-Tool、ACMなど、文脈や記憶を管理する先行研究に対し、本論文は推論の価値を情報の保存先と後続行動から調べる（§2）。外部記憶そのものが新しいわけではない。

モデル / 手法

Fig. 2 / Eq. 1–9の処理では、直前に終えたstepの推論を空行で区切る。因果順の履歴をscorerに与え、各tokenの分布からエントロピーを求める。

Sₜ = (Rₜ, Aₜ, Oₜ₊₁)                  推論・行動・観測
hₜ = −Σᵥ pθ(v | cₜ) log₂ pθ(v | cₜ)    予測分布の不確かさ
H(Bᵢ) = Σₜ∈Bᵢ hₜ / |Bᵢ|               ブロック内平均
D = BottomK⌊0.8N⌋ {H(Bᵢ)}               低い順に[SKIP]へ置換

実際に出たtokenのsurprisalとは異なる。N=1なら削らず、scorerの42K入力上限を超えたstepは剪定を見送る。書き換えた履歴を以後の要求でも使う。Random対照はtoken単位、ICLRはblock単位なので、削除率を同じ尺度として並べない。

Appendix B.3の固定集合に関する情報量の上界は、観測したスコアで適応的に選ぶ削除集合の安全保証ではない。B.4の十分条件は、保存状態Zだけで次の行動分布を復元できることを要求する。

πₜ(a | Zₜ,Wₜ) = qₜ(a | Zₜ) = π̃ₜ(a | Zₜ)
TV(Pπ,Pπ̃) ≤ 1 − ∏ₜ(1−εₜ) ≤ min(1,Σₜ εₜ)

Wは消す推論、εは共通履歴での行動分布の差の上限。状態をファイルへ書くだけでε=0になるとは主張できない。

なぜ効きそうか

解釈・推論

解釈：同じ制約をコードと推論の両方に保持しているなら、コードを参照して後続の判断を進められる。一方、必要な結論が推論だけにある場合、消すと元の証拠から導き直すことになる。対話図はこの保存先の違いを、同じ要求列で比べる。

外部化は無料でも完全でもない。Table 16では、コード保存後の推論削除で評価値は0.7587のままだが、推論量は1,289から3,222へ増える。成功率が同じでも節約できるとは限らない。

根拠

実行可能な理解

4つの制約を、同じ6要求で再利用する決定的な状態機械を動かす。「保持」「推論だけ削除」「ファイル保存後に削除」「保存したが読めない」の4条件を比較する。再導出が必要なら元の規則から正解を計算し直すので、全条件の最終値は一致する。

労力は参照1、ファイル読出し2、再導出10という人工的な単位。LLMのtoken数ではない。図の実行履歴はresults.jsonから読み込む。論文の非単調な節約量は別の散布図に示し、このtoyで再現したようには扱わない。

検証できたこと

CONFIRMED：固定した6要求で4条件の最終値が一致すること、読める保存先が再導出を避けること、読めない保存先では避けられないことをassertで確認した。

PARTIAL：機構の検証は情報の保存先だけに限る。推論ブロック選択やエントロピー推定は実装していない。67.31%と36.15%、80課題の報酬値はPDFへ照合した転記であり、独立再現ではない。

検証していないこと

NOT TESTED：DeepSeek-V4-Flashの実行、Qwen3.5-9Bの採点、WorkBuddyBenchの性能、複数seedの不確実性、実token数、scorerの費用、長期の状態更新と陳腐化、本番適用性。論文の trajectory amplification はtoyの測定対象に含めていない。
