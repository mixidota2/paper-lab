このLabを読む

問いモデル / 手法判定時に見える情報と、後から評価する情報不自然さは1種類ではない検出能力は適合率と再現率を両方見る根拠小実験限界

概要

予測を作るモデルとは別に、履歴・予測図・販促の説明を読む批評器を置く。狙いは誤予測の自動修正より、点検すべき系列の発見。

問題設定

平均の誤差が良くても、個別には周期がずれた予測や、不自然に平らな予測が混じる。未来の実績がまだない時点では、通常の誤差指標でその失敗を測れない。

Forecast Criticは過去と予測の図、必要なら販促に関する文章を見せ、もっともらしい予測かをLLMへ尋ねる。将来の真値を先に見て良否を判定する使い方ではない。

核心

著者の主張 · 論文に書かれていること

著者はトレンド、水準、周期、急増を人工的に崩した予測で批評能力を調べる。販促の説明を加える実験と、M5上のChronos予測を点検する実験も行う。言語・画像の文脈から不自然な予測を拾う監視手段として提案する。

一次資料：合成実験 / 外生情報の実験 / 実データの実験

解釈・批評 · 読書メモ

これは予測精度を直接改善する学習法ではない。警告した後に誰が何を確認し、誤警告をいくつまで許すかが運用を決める。図の描き方や説明文の質に依存するなら、監視器自身も評価対象になる。

モデル / 手法

Forecast Criticは 予測図を読むマルチモーダルLLMの判定器。未来の正解値を受け取らず、過去の系列と予測線を画像で見て、予測が妥当かを判定する。販促予定などの文脈はテキストで渡す。予測を生成するモデルや、自動で修正する最適化器とは役割が異なる。

評価モデルはClaude 3.7 Sonnet、Claude 4.0 Sonnet、同reasoning版、Claude 4.0 Opus、Llama 4 Maverick。人工系列にはトレンド変更、上下の移動、周期の圧縮、スパイクを加える。500件を変更あり・なしに半分ずつ分けて検出を評価し、M5では Chronos が生成した予測を判定する。

「不自然」と「誤差が大きい」は別のラベル。販促で急増する予測は文脈があれば妥当かもしれない。現場で利用するには、正しい予測を誤って止める件数と、レビューへ回す量も調べたい。

一次資料：方法と実験条件

なぜ効きそうか

解釈・推論

数値の誤差だけでは説明しにくい「販促予定があるのに山がない」という矛盾を、文章と図から拾える可能性がある。一方、新しい現象が過去と違って見えるだけで誤警告することもある。

根拠

Abstractと合成実験では最良モデルのF1が0.88、人が0.97と報告される。F1は警告の適合率と再現率をまとめる値。実データの実験では、怪しいとされた予測群のsCRPSが少なくとも10%高い。これは群の誤差の違いで、監視を導入すれば誤差が10%改善するという結果ではない。

一次資料：合成実験 / 外生情報の実験 / 実データの実験

実行可能な理解

10件の合成スコアと正解ラベルを用意する。警告閾値を変え、適合率・再現率・誤警告・見逃しを再計算する。LLMを呼ばず、監視運用の判断を学ぶための実験。

実行：uv run papers/forecast-critic/run.py。合成データの作り方と比較条件はコード内に記載し、図の全条件の結果を results.json へ保存する。

検証できたこと

メカニズム：PARTIAL（部分的）。確認したのは、このLabで明記した仮定の下での計算と条件による変化。原論文の機構全体を確認した意味ではない。

10件の合成スコアと正解ラベルを用意する。警告閾値を変え、適合率・再現率・誤警告・見逃しを再計算する。LLMを呼ばず、監視運用の判断を学ぶための実験。

検証していないこと

人工的な破損と自然発生する失敗の分布は違う。実務では低い問題発生率の下で誤警告が増えないか、担当者の作業時間が減るか、警告後の修正で費用が下がるかを確認したい。LLMによる図の理解は今回検証していない。

実装

標準ライブラリだけで実行できる。入口は各Labの run.py、計算本体は papers/_toy_common.py にある。関数は論文IDごとに独立し、ブラウザー用の全条件と初期条件の表を同時に出力する。

意図して省いたもの：画像理解、LLM、販促の文章、Chronos、M5。
