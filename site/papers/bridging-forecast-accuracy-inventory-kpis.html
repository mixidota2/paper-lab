概要

MAEが最小の予測モデルが、在庫費用も最小にするとは限らない。TruckPartsは、トラック補修部品の人工需要、予測、在庫費用計算をつなぐ公開ソフトウェアである。著者実験では木モデルがMAEで強く、Crostonが総費用で最良だった。将来の比較実験に使う基盤として読む。

問題設定

需要がない日が多い補修部品では、誤差の小ささと欠品回避の価値がずれる。対象は48の人工シナリオ。4種類のドリフト条件、4種類の車両数範囲、3種類の部品寿命範囲を組み合わせ、4販売店で3年間を生成する。実測の需要系列による評価ではない。

核心

著者の主張 · 論文に書かれていること

統計的な予測精度と在庫KPIを結ぶ公開基盤を提供する。人工実験では、精度改善が費用改善へ直結せず、シナリオごとに両者の関係も変わる。

解釈・批評 · 読書メモ

Accuracy Is Not Serviceの問題意識を、費用と充足率を測る再利用可能な試験環境へ進める仕事と読む。現場での優位性の証拠はまだ薄く、需要生成と在庫方策の仮定を差し替える将来の実験基盤として位置づける。

モデル / 手法

需要発生から業務指標までをつなぐ

原論文の需要生成はDealer → Truck → Partの階層を持つ。1日ずつ進める。部品の故障確率は、生存時間に応じるハザードhを積分し、P(故障 | 現在まで生存) = 1 − exp(−∫h(u)du)で決める（式1、Figure 1）。Exponential、Weibull、Log-logistic、Gompertzを使い、季節と車両の使用条件を重ねる。故障した部品の年齢をゼロへ戻し、販売店・部品型ごとに日次需要を集計する。

Figure 3では、この需要を予測モデルと在庫費用シミュレータへ渡す。予測は最初の730日で学習し、次の365日を評価する。XGBoost、Random Forest、SVR、ARIMA、Croston、SBA、TSBのハイパーパラメータはMAEで選ぶ。

説明用コードは予測と費用のずれだけを残す

run.pyの需要は確率0.1で4個、それ以外はゼロとなる独立な人工系列。Crostonは非ゼロ需要の量zと間隔aを平滑化し、予測をf = z / aとする。平滑化係数は0.1。学習後は固定する。Zeroは全日をゼロと予測する説明用の比較対象である。

両者の在庫規則は共通で、目標在庫S = ceil(5f)、初期在庫0、納期1日。入荷、需要への即時充足、残在庫の保管費計上、翌日着の補充発注の順で進める。欠品は販売機会損失として処理する。MAE = mean(|d − f|)に対し、C = Σ在庫 + p × Σ欠品数量で費用を測る。目標係数5や費用係数は説明用の設定で、論文から推定した値ではない。

なぜ効きそうか

解釈・推論

解釈：MAEは過剰予測と過小予測を同じ単価で数える。一方、在庫費用は保管、発注、緊急便、輸送、サービス不足の費用を通じて予測を評価する。ゼロ需要をよく当てても、稀な需要で補充が足りなければ費用が増える。この接続を固定条件で調べられる点に価値がある。

根拠

一次資料の著者報告（v2 Table 1）：XGBoostとRandom ForestのMAEは丸め値で0.43、Crostonは0.52。総費用はそれぞれ約8.2×10⁵、7.5×10⁵、7.4×10⁵である。MAEはシナリオ平均と標準偏差、費用は全シナリオの合計。図では平均MAEと総費用を切り替え、同じモデルの順番を見る。

Figure 6のMAE–費用の順位相関は全体0.95に対し、シナリオ内の平均が−0.16。本文はRMSEでも平均−0.06と報告する。集計すると関係が変わるため、需要規模が異なるシナリオをまとめた相関だけでモデルを選ばない。これらは著者の報告値であり、Labで再計算した相関ではない。

検証できたこと

CONFIRMED：人工実験の各日で在庫の収支と需要の分解を照合した。欠品単価50でのMAEと費用の順位逆転も確認した。MechanismはPARTIAL。論文全体の需要生成と費用計算の一部だけを、独立した説明用コードで扱っている。

検証していないこと

Performance / Scaling / Production applicabilityはNOT TESTED。公式の48シナリオ、7予測モデル、費用シミュレータは再実行していない。実験は全て人工需要で、論文も在庫方策のパラメータを全販売店・部品で固定する。価格、初期在庫、納期なども共通で、供給者の容量は無制限。販促と欠品を含むTSFM対GBDTの比較や、実店舗の棚割りRCTの証拠には使えない。

実装

run.pyはPython標準ライブラリだけで動く。croston()が非ゼロ需要量と間隔を学習し、simulate()が共通の補充規則と費用を計算する。results.jsonは論文の転記値reportedと人工実験framesを分けて保存する。ページはlab.yaml、method.md、mapping.md、results.jsonから生成する。
