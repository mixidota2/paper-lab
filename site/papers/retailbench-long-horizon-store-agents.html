概要

RetailBenchは、価格・補充・棚・仕入先・資金繰りを180日間つなぐ店舗運営の評価環境である。LLMの最良選択実行でも、最終純資産は特権情報を使うOracle Policyの約19%だった。個々のツール操作が正しくても、店を続けられるとは限らない。

問題設定

Dominick’sの実データを基に96商品・20カテゴリを構成する。各商品には5仕入先があり、棚は40商品、在庫容量は15,000個。初期資金30,000、家賃は1日600である。需要やニュースの内部効果は隠され、エージェントは照会ツールで状態を調べる。価格変更、発注、棚の変更が、その後の販売・返品・現金残高に影響する。

核心

著者の主張 · 論文に書かれていること

データに基づく部分観測の店舗環境で、長期の一貫した意思決定を評価する。不完全な情報収集、表面的な判断、継続する方策の欠如という3種の失敗を診断する。

解釈・批評 · 読書メモ

研究地図では「運用中に複数の店舗業務を操作するLLMの評価」に置く。InvEvolveの設計時の発注方策探索や、SabreAgentの設計後に固定する在庫制御とは、LLMの役割も評価単位も異なる。

モデル / 手法

店舗を部分観測の意思決定過程として扱う。照会ツールで観測し、ReAct、Reflection、Plan-and-Actが発注・価格・棚を操作する。end_todayで入荷、販売、返品、経年、資金を更新する。Oracle Policyは特権情報を使う規則ベースの参照方策である。

なぜ効きそうか

解釈・推論

解釈：仕入れの安さだけを選ぶと、返品による将来の収入減を見落とす。棚へ載せない商品は販売機会を失い、売れない日も家賃はかかる。こうした遅れて現れる結果を同じ環境で測れる点に価値がある。行動診断と成績の関連は、各失敗要因の因果効果を単独で証明するものではない。

根拠

一次資料の著者報告（v3 Table 1）：Oracle Policyは純資産131,510.42、販売数量267,998。GPT-5.5 ReActは純資産24,350.98でLLM中の最高値、DeepSeek-V4-Pro Plan-and-Actは販売数量164,417で最高値だった。販売数量の単位は個で、売上金額ではない。両モデルは180日を完走し、Kimi-K2.6は130日、残る4モデルは58〜73日で終了した。

各モデルにつき、利用可能な枠組みから生存日数を優先し、同点なら純資産、販売数量の順で選んだ実行を掲載する。全実行の平均ではない。GPT-5.5は費用の制約でReActのみ。Oracleは隠れた情報を使う非LLMの参照方策であり、同じ観測条件のエージェントではない。

§4.3・Figure 3の診断では、選択されたLLM実行の平均QualityFirstは21.5%、PriceFirstは55.6%。行動対象商品数は1日0.95〜7.89商品で、Oracleの38.00商品から離れている。この商品数は販売された商品数とも異なる。

実行可能な理解

UV_CACHE_DIR=/tmp/uv-cache uv run --no-project papers/retailbench-long-horizon-store-agents/run.py

人工的な30日間の収支を、同じ需要・家賃・初期資金で比較する。PriceFirstは原価4・返品率30%、QualityFirstは原価5・返品率5%。価格10、対象商品当たり需要10個/日とし、毎日即時補充する。対象商品数を1・8・20・38から選び、仕入先選択と日々の対象範囲が収支へどう重なるかを読む。これらの仮定は論文から推定した値ではない。
