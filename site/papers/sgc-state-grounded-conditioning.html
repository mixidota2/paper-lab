このLabを読む

問いモデル / 手法3つの状態と、生成前に決める内容状態を文章生成の前提へ変換する1ターンの正しさを、セッション全体で保てるか根拠小実験限界

概要

SGCは、利用者の今の状態に応じて、何を調べ、どの制約を説明し、いつ提案するかを生成前に決める設計である。Tencentのゲームコーチを対象に、200セッション・約1,000回答の人手評価を報告する。Full SGCのTGAは96.7%、SGAは83.5%。製品の利用継続率や勝率を改善したA/Bの数値は開示されていない。

問題設定

図鑑では正しい技でも、その利用者が未解放なら戦術として使えない。回答が質問に沿って完結していても、現在の所持品や直前の助言に反する方向へ進む失敗を、著者はdirection driftと呼ぶ。静的な事実の誤り、未所持品の誤認、反復による疲労は重なる場合もある。分類の名称より、判断時点の状態を評価の参照先に含める点が実装上の焦点になる。

核心

著者の主張 · 論文に書かれていること

Perception / Grounding / Interactionのwrapperへ状態に応じた制御を移す。LLMはその制御変数に従って文章を生成する。3つを順に加えた比較で、速度とgroundingの改善を報告する。

解釈・批評 · 読書メモ

IGPOが候補の存在を検索して誤った不在判断を減らすのに対し、SGCは利用可能な候補をどう説明し、いつ再提案するかまで扱う。これはLabの比較であり、両方式を組み合わせた実験はない。著者の「promptはlive stateに対応できない」という強い表現も一般的な不可能性としては読まない。比較対象の設計と調整条件を確認する必要がある。

モデル / 手法

W1は状態がそろった時点でtoolを確定する

W1の生成は4区分に分かれる。

  1. INTENT：第一段階の意図
  2. SUB_INTENT：具体的な意図
  3. NARRATION：音声へ送る前置き
  4. PLAN：fallback用のtool呼び出し

§4ではSUB_INTENTの終了時に現在のsnapshotと約50組の意図表Φを参照し、登録に一致した場合はPLANの完成を待たずにtoolを確定して、残りの生成や音声再生と並行して実行する。状態がなければ待つ。未登録の意図もPLANへ進む。

順序には原典内の不一致がある。Fig. 4のcaptionはNARRを先に列挙しているため、本Labは§4の明示順序を採用した。図中の時間は模式的なものだ。

W2は不足条件を残し、矛盾する段落を除く

W2は専用のLLM呼び出しで要求slotを抽出し、現在満たせるslotとの差をhard / soft / hintへ分類する。hard conflictでは該当制約を満たしたとするpraiseを除き、制約の説明を必須にする。

候補化と選択は別である。同じ制約について互いに矛盾する段落は同時に選ばないが、別の制約を褒めながら不足条件を説明する組み合わせは許されるので、praiseとapologyという種類だけで回答全体を排他的に扱う実装は論文の規則より強すぎる。

所持だけでは足りない。Aを持っていてもskill-Xが未解放なら、小実験はその不足を残す。

W3は履歴を読み、次の提案を選ぶ

W3は履歴から待機状態を復元する。待機中の候補を除いた後、候補ごとの確率pで残すBernoulli抽選と重みwに比例する選択を行い、選択結果やseedなどをanswer.metaへ保存して、次のターンの制御入力に戻す。

候補がなければ見送る。再生の保証は、候補・状態・設定・乱数源を固定した場合に限られる。

モデルの具体名は未開示

著者は同じLLMを5構成に使ったと記載するが、公開版に具体的なmodel IDはない。PE-AgentはPlan-and-Execute方式の名称だ。最小実験はLLMを使わず、規則の境界だけを切り出した。

なぜ効きそうか

解釈・推論

解釈：制約の判定を明示すれば、自然な文章が書けたかと、助言の前提が満たされるかを別々に調べられる。履歴を入力とする規則は、同じseedで選択を再生できる。ただし、誤ったslot抽出や古いsnapshotを与えれば、決定的な規則も誤った結論を安定して返す。生成文の意味まで保証する方法ではない。

根拠

一次資料 §7 / Table 3–4 / Appendix G の著者報告。約4週間の本番ログから200セッションを抽出し、同じLLM・tool schema・参照証拠で比較する。2名の独立評定と第3者の裁定を用い、テスト集計にはLLM judgeを使わない。

TGAは各セッション内の正解率を平均する。SGAは全回答が正しいセッションの割合である。TGQは助言の質、DGPは対話を通じた進展、CCCはターン間の一貫性を1–10で評価する。SGAの失敗率は73.5%から16.5%へ下がり、相対減少は約78%。これは製品障害の発生率ではない。

PE-AgentにはSGCと同じ量の製品固有prompt調整が行われておらず、差には設計と調整の両方が含まれる。累積追加の比較からwrapper単独の効果や追加順序への不変性は分からない。LLMの具体的なmodel ID、全評定者の一致度や一部の統計表は公開版では未開示。

実行可能な理解

uv run papers/sgc-state-grounded-conditioning/run.py。人工的な所持品A/B/Cを固定し、Aに必要なskill-Xだけを未解放にする。固定優先順、所持条件の照合、照合と履歴制御を同じ12ターンで比べる。LLMを呼ばず、W1の分岐、W2のhard conflict、W3の抽選と履歴更新を小さく切り出す。

検証できたこと

Mechanism PARTIAL。hard conflict時の候補除外、同一seedでの再生、直前候補の除外、候補が空のときの見送りを確認した。これらの局所規則はCONFIRMED。W1ではsnapshotがない場合と未登録intentの場合にfallbackへ進むことを確認した。

検証していないこと

Performance / Scaling / Production applicability NOT TESTED。自然言語のintent・slot抽出、streaming parser、実toolの並列実行、生成文の整合性、200セッションの人手評価、1.5秒の速度、本番A/Bは再検証していない。本文の製品A/B改善量は未開示。IGPOとの統合、ECの在庫推薦やコード補完への転用も未検証である。

実装

標準ライブラリだけで動く。freeze_tools()は状態付きlookup、ground()は必要slotと所持slotの差分、schedule()はhard filter→Bernoulli抽選→重み付き選択を担う。replay()が選択を履歴へ書き戻す。待機期間は1ターンに固定し、soft/hint、複数段落の完全なmutex表、自然言語生成を省いた。
