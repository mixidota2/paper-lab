01

概要

同じモデルを使っても、周囲の進め方が変われば成績は別物になる。Starace は GAIA で、モデルを動かす実行枠組み（scaffold）の差を測った。3種類の枠組みと5モデルを組み合わせ、モデル以外の条件をそろえて比較している。

最大差は28ポイントだった（原論文 §4.1）。このラボでは、「このモデルは何点」と単独で読むより、どの実行枠組みで引き出した点かまで記録しないと比較を誤る、と読む。

このラボは論文の精度表を再計算しない。途中で道具が失敗する小さな合成タスクを使い、構造化した進め方が行動数と復帰にどう関わるかだけを動かす。

02

問題設定

エージェント評価では、モデルと一緒にプロンプト、ツール、ループ、停止条件が走る。それでもランキングは、しばしばモデル単体の性質として受け取られる。

このずれが厄介なのは、比較する二者が別々の scaffold を選んだときだ。数字の差がモデル由来なのか、仕事の分け方や失敗時の戻り方によるのか、表からは分からない。

GAIA のように複数ステップを要する課題では、最初の誤りを後で回収できるかも成績を左右する。そこで本論文は、scaffold を操作する変数として扱った。

03

核心

論文が主張すること

著者は、ReAct、Planner–Actor–Rater、planner-then-executor の3方式を、5モデル、GAIA の2レベルで比較した。事前登録した H1 は「少なくとも一つのモデルで、最良・最悪 scaffold の差が10ポイント以上になる」という仮説で、支持された。

H2 の「強いモデルほど scaffold 差が小さい」という方向は支持されなかった。H3 の「Planner–Actor–Rater が L2 では ReAct を上回る」という仮説は Anthropic 系モデルに限って条件付きで支持された。H4 の「planner-then-executor はファイル読みで有利」という仮説は反証された。構造化した scaffold では、行動数が少なく、中盤で失敗した後の復帰が良い傾向も報告している。

このラボの読み

この論文が変えるのは、どの方式が普遍的に勝つかという結論より、能力値の読み方だ。評価結果はモデルの通知表ではなく、モデルと実行枠組みの組に付いた測定値として扱うほうが安全だ。

実務では、候補モデルを決める前に、少なくとも別の scaffold を一本走らせたい。首位が入れ替わるなら、調達の判断はモデル選びから harness 設計へ移る。

04

なぜ効きそうか

ここからはラボの解釈です。著者の因果主張ではありません。

【ラボの解釈】構造を分けると、失敗を「次の行動を考え直す契機」として扱いやすい。計画、実行、点検の役割が混ざっていないため、同じ操作を惰性で繰り返す余地が減る。

ただし、この説明は因果の特定ではない。成績差には、各 scaffold が触れるツール面や実装の細部も影響しうる。論文は方式間の差を測ったのであって、復帰率が上がる唯一の理由を示したわけではない。

05

根拠

主な根拠は、GAIA 上の 3 scaffold × 5 models の制御比較と事前登録である。原論文は最大28ポイントの差と H1 の支持を報告した。H2 の方向は棄却され、H3 は Anthropic 条件下でのみ支持された。H4 は反証された。

行動面では、構造化した方式ほど少ない行動で進み、中盤失敗から戻りやすい傾向が示された。このラボの results.json は、その傾向だけを合成タスクで確かめた別の結果である。GAIA の成績表ではない。

06

実行可能な理解

run.py は、必要な手順数が異なる200件の合成タスクを作る。各方式には同じ確率で中盤のツール失敗を入れる。

比較するのは Baseline の react と、Proposed の planner_actor_rater / planner_then_executor だ。見る値は平均行動数と、失敗が起きた試行の復帰率。精度を競わせる実験ではないので、ここで28ポイントを再現しようとしてはいけない。

07

08

検証できたこと

合成タスクでは、二つの構造化方式が ReAct より少ない行動数で終わり、中盤失敗後の復帰率も高かった。これは、あらかじめ定義した方針規則と失敗確率から計算される結果である。

失敗確率と復帰規則は実験用に固定したもので、実モデルの軌跡ではない。したがって、このラボは動作模型を提供するが、方式が復帰を良くする因果を検証していない。メカニズムの状態は NOT TESTED とした。

09

検証していないこと

  • GAIA L1/L2 の正答率、最大28ポイントの差、H1〜H4 の統計的結論
  • H3 が Anthropic 系に限って現れる条件
  • コスト、ツール面の違い、SDK の不具合などの交絡
  • 性能、スケーリング、本番適用性
10

実装

run.py は標準ライブラリだけで動く。react を Baseline、二つの構造化方式を Proposed として同じシードで実行し、results.json を書き直す。

実行コマンドは uv run python papers/scaffold-effects-gaia/run.py。この実装は scaffold の働きを説明するための模型であり、論文のエージェント、GAIA、外部APIを含まない。
