# Pinterest：shopping 候補生成を呼ぶ価値を測る

## Overview — 呼び出すリクエストを選ぶ

Pinterestの研究チームは、推薦の候補を集める段階で、買い物向けの商品を探す処理を呼ぶかどうかをリクエストごとに決めました。一部のリクエストでは、その処理を呼ぶかどうかを無作為に割り付けました。著者はこの記録に異なるしきい値を当てはめ、どれを本番で試すかを決めました。本番の主方式が使うのは、呼ぶ場合の予測値だけです。呼ぶ場合と呼ばない場合の予測値の差を、そのまま判断に使ったわけではありません。

本番実験のうち、呼び出しが約40%減った群では、サイト全体のSuccess Curation件数が0.26%、ピンの詳細画面での保存件数（Repins）が1.10%増えました。購入に近い行動の指標には統計的に明確な差が出ていません。呼び出しを最大85%減らしたのは別の群で、これらの改善率が同じ条件で得られたわけではありません。

## Problem — 買物と保存の目的が競合する

リクエストごとに区別せず候補生成器を呼び出すと、買物行動は増える一方、Pin保存などは減ります。買物と保存の両方を増やせるとは限りません。

## Core Idea — 学習と配信を分ける

著者は結果の予測と、二重に頑健な補正（DR）で行動による結果の差（uplift）を見積もる学習を同時に行います。本番の主方策は、呼び出した場合の結果確率 μ₁を使うsingle-value（SV）です。呼び出さなかった場合との差を使うdelta policy（DP）は診断に使います。

## Why It Might Work — 呼び出さなかった結果もログに残る

対象リクエストを50:50で無作為に割り当てているため、呼び出した群と呼び出さなかった群の結果を比べられると考えられます。これはLabでの解釈です。

## Results — 補正と閾値の結果

補正値を切り詰める前のDR平均は、真のuplift 0.02、0.20、0.05と一致しました。δ=0.3でのreplayの報酬率も真値と同じ0.426667です。

## What We Verified — 限定した機構

仕組みは一部確認済み（Mechanism PARTIAL）です。割当確率が分かっているときの補正と、均等割当のログから配信ルールと行動が一致した行を選ぶ手順を確認しました。

性能、規模を広げたときの挙動、本番適用（Performance / Scaling / Production applicability）は未検証（NOT TESTED）です。ニューラルモデルの学習、補正値の切り詰め、本番A/B、遅延は再現していません。
