# ハーネスを替えると、成績と費用のどちらが変わるか

## 概要

著者は、同じ言語モデルで課題を解くとき、システム指示やツール、履歴の扱いを決める仕組み（ハーネス）を替えると、成績と費用がどう変わるかを調べました。難しいコード修正45課題では、構成を変えずにやり直した場合もハーネスを替えた場合も、成否が入れ替わった課題は中央値で約13%でした。モデルを替えた場合は約26%でした。これは成功率の差ではなく、同じ課題の成否が変わった割合です。

ただし、組み合わせによって結果は変わります。OpenCodeは、別の447課題でQwen3.8を使うと他の二方式より約8〜9ポイント低く、難しい45課題でDeepSeek-V4.1-Flashを使うとmini-SWE-agentより約14ポイント高くなりました。同じモデルでの費用差も、比較によって1割未満から3〜4倍まで開きました。著者は、使ったモデルを明記し、ハーネスを替えた結果と同じ構成をやり直した結果を並べて評価するよう勧めています。

## 何を比べたか

同じモデルでも、システム指示、ツールに渡す入力、履歴の残し方、打ち切り後に続ける方法はハーネスによって変わります。一度ずつ実行した成功率だけでは、構成を替えたために差が出たのか、やり直すだけでも出る差なのか分かりません。

著者は難しい45課題と残り447課題を分けました。主要試行では実行環境から外部のネットワークを使わず、先にネット接続ありで試した条件は、既存の修正が混ざったため本比較から外しました。失敗や出力の上限に達した試行は失敗として数え、インフラの都合で成績を測れない場合だけ該当ペアを外しました。

## 著者の結論と、他の研究との違い

著者は三つのハーネスを比べ、どれも全モデルで一貫して首位にはならなかったと報告しました。ハーネスの差は組み合わせによって向きが変わり、費用は事前の指示、履歴、呼び出しの回数にも左右されます。

[Scaffold Effects on GAIA](scaffold-effects-gaia.html)や[Harness-Bench](harness-bench.html)は、別の課題や実行条件でより大きな成績差を報告しました。GAIAも繰り返し実行を扱っています。課題、ツールのつなぎ方、失敗からの戻り方、比較の方法が違えば結果は両立し得ますが、この論文からどの違いが原因かは決められません。

## 比較方法

## 同じ課題がどちらで成功したかを比べる

著者は同じモデルをClaude Code、mini-SWE-agent、OpenCodeで動かし、ハーネスだけを替えた場合と、何も替えずにやり直した場合を比較しました。SWE-bench Verifiedの難しい45課題と、残りの447課題（pool447）は別の集合です。第2版では三つのハーネスで比較できるモデルが七つあり、pool447の主要比較は四つのモデルで行いました。旧Claude Opus 5の試行はClaude Codeだけの参照です。[第2版 §3〜4](https://arxiv.org/html/2610.04433v2#S3)

二つの試行に有効な結果がある課題を `n` 件とします。最初だけ成功した課題を `b` 件、もう一方だけを `c` 件とすると、成功率の差は `(b−c)/n`、成否が入れ替わった割合は `(b+c)/n` です。片方だけが成功した課題が同じ数なら、入れ替わった課題が多くても成功率の差はゼロになります。著者は、勝ち負けが偏ったかを両側の正確McNemar検定で確認しました。

差が小さい範囲に収まるかは、別に90%区間を使って読みます。第2版の表2は、区間全体が±2、±3、±5ポイントのどこに入るかを示します。著者は許容幅を当初±10とし、447課題の実行後に検出できる差を踏まえて±5へ狭めました。値がゼロかを調べる比較と、意味のある大きさを除けるかを調べる比較は同じではありません。[表2・付録F](https://arxiv.org/html/2610.04433v2#S4.SS1)

## 何件の課題があれば、どの程度の差に気づけるか

検出力は、仮定した成功率差が本当にあった場合に、検定が差を見つける確率です。このLabは第1版の条件に合わせ、成否が異なる課題の件数を二項分布で動かします。異なる課題の件数を平均値に丸めて固定しないため、45課題で起き得るばらつきが残ります。

まず、課題数を `n`、成否が異なる確率を `q` とし、成否が異なる件数 `M` を `Binomial(n,q)` で表します。その `M` 件のうち最初だけ成功する確率は、仮定した成功率の差を `Δ` として `(1+Δ/q)/2` です。差がないとする検定では確率を1/2にして両側のp値を出します。仮定した差のもとで `p≤0.05` になる場合を足すと、検出力が求まります。Labが示す値はこの条件での計算で、追加された第2版の試行を再解析した結果ではありません。

## 使ったトークンと請求額を分ける

トークンはモデルが処理するテキストの単位です。毎回送るハーネスの定型文を `P`、課題文を `U`、一回の呼び出しで履歴に加わる量を `g` とします。履歴を削らない近似では、`k` 回目の入力を `Iₖ ≈ P + U + gk` とし、`N` 回分を足すと `N(P+U)+gN(N−1)/2` になります。定型文が短くても、呼び出す回数が多ければ処理量は増えます。

著者の費用は、キャッシュを使えた入力、使えなかった入力、出力のトークンを別の単価で計算します。Labの計算欄は入力に限った説明用の近似です。履歴を削る時点を変えても、著者が測った履歴や請求額を再現したわけではありません。[第2版 表3・付録G](https://arxiv.org/html/2610.04433v2#S4.SS5)

## 検出力と費用を別々に見る

何も替えずにもう一度実行すれば、構成を替えなくても成否が変わる課題の数を測れます。45課題では、成否が異なる課題が6件未満だと、そのすべてが一方で成功しても、5%の両側検定で差を検出できません。課題数が少ない比較で「差を見つけられなかった」ときは、この限界も読みます。

同じ定型文を一回ごとに送ると、短い差が積み重なります。反対に定型文を短くしても、モデルが何度もツールを呼べば履歴と入力が増えます。DeepSeek-V4-Flashではmini-SWE-agentが141回、Claude Codeが104回だったため、定型文が最も短い方式でも使うトークンが最も多い条件がありました。

## 第2版の著者報告

一次資料：[著者論文第2版 §4、表1〜3、付録M・Q](https://arxiv.org/html/2610.04433v2)。[論文の書誌情報](https://arxiv.org/abs/2610.04433)。

### 入れ替わった課題と、成功率の差を分ける

難しい45課題では、第2回の実験まで含めた不一致率は、再実行22組とハーネス交換21組でいずれも中央値13.3%、モデル交換70組で25.6%でした。第1版のモデル交換の中央値22%は、初回の実験に限った値です。どちらも成功と失敗が入れ替わった課題の割合で、成功率の差ではありません。

残り447課題では、四つのモデルを使った12比較のうち、8比較の90%区間が±5ポイント内でした。Qwen3.6ではClaude Code−mini-SWE-agentの差は−1.8ポイント（90%区間 −4.7〜+1.1）、Qwen3.8では−1.4ポイント（−3.7〜+1.0）。四つのモデルを等しく平均する別の集計は+0.2ポイント（−0.9〜+1.2）です。この範囲は平均に対するもので、個別のモデルの差まで±2ポイントに収まるという意味ではありません。また、著者は最初に±10とした幅を447課題の実行後に±5に狭めています。

### 同じハーネスでもモデルによって優劣が変わる

Qwen3.8の447課題では、Claude CodeがOpenCodeを7.9ポイント、mini-SWE-agentが9.2ポイント上回りました。著者はOpenCodeで応答が上限で打ち切られたことも調べています。打ち切られた課題を除くと差は縮みますが、後から除いた比較だけで差の原因をすべて説明することはできません。

一方、DeepSeek-V4.1-Flashの難しい45課題では、OpenCodeは2回とも27件成功し、mini-SWE-agentは21件と20件でした。著者の比較ではOpenCodeが約14ポイント上回りました（90%区間7〜23）。同じ二つを残り447課題で2回ずつ実行してまとめると、差は1.8ポイントで、Holm補正後のp値は0.16です。一回の結果を、別のモデルや課題へそのまま広げません。

### 費用の差もモデルに依存する

表3は、同じモデルと課題で測ったトークンを、各提供元の当時の公表単価で費用に換算しています。GLM-5.3-Flashの難しい45課題では、一番高い方式の1試行当たり費用が一番安い方式の初回3.2倍、再実行4.0倍でした。DeepSeek-V4.1-Flashの447課題では1.03倍、Claude Opus 5.5の難しい45課題では1.08倍です。GLMで成功した課題1件当たりの費用は、2回の合算でClaude Codeが4.28元、OpenCodeが1.36元でした。単価だけの比較でも、成功率の倍率でもありません。

### コード修正以外の確認は一つのモデル

DeepSeek-V4.1-Flashを使い、著者は表計算のSpreadsheetBench Verifiedとデータ分析のDABstepでも各方式を2回実行しました。表計算では、どの2方式の90%区間も±2ポイントに収まりました。DABstepではClaude Codeが1回目で最も高く、2回目で最も低い値でした。いずれもこのモデルの結果です。

## 第1版を使った実験

Labの計算欄は第1版のデータを使います。課題数と不一致率を選ぶと、50%または80%の検出力で見つけられる最小差を示します。Pythonは二項分布の全範囲を足す計算と、12,000回の乱数試行を照合します。

費用の操作欄では第1版の定型入力、履歴の増加、呼び出し回数を出発点に、入力トークンだけを概算します。履歴を削る操作は説明用で、著者の実行ログを再生しているわけではありません。

## 計算の結果

第1版の著者コードでは、難しい45課題の検出力計算に0.1400894188、447課題には0.1439280360の不一致率を使います。Labの計算では、45課題で50%の検出力に届く差は約12.90ポイント、検出力が最も高い場合は61.69%でした。447課題で80%の検出力に届く差は約5.159ポイントです。第2版も丸めた値として12.9ポイント、約62%、5.2ポイントを別に報告しました。

不一致率を0.14と置くと447課題の境界は5.088ポイントです。計算欄では丸めた値と著者コードの値を選べます。差は入力の丸めで生まれ、第2版の追加試行から再計算した数値ではありません。

## Labで確かめたこと

Labは第1版の不一致率を使うと著者の検出力の計算に近い値が得られ、12,000回の乱数試行と厳密計算との差も2ポイント未満になることを確認しました。第1版のGLMの値を使う入力トークンの近似では、Claude Code、mini-SWE-agent、OpenCodeの順に多くなりました。

## Labで確かめていないこと

Labは著者のモデル、SWE-bench、課題別の等価性の検定、完全な課金、現行バージョンのハーネスを再実行していません。第2版は比較したモデルを増やしましたが、コード修正以外の二つの評価は一つのモデルに限ります。一部のモデルではハーネスによって時間上限も違います。過去に課題を学習した可能性は、この比較だけではなくなりません。

リポジトリのルートで `uv run --no-project papers/harness-buys-tokens-not-pass-rate/run.py` を実行すると、同じ場所に `results.json` ができます。Python標準ライブラリだけを使い、外部APIに接続しません。`official-check.json` は第1版の著者コードで照合した入力値です。
