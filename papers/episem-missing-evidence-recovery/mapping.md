# 論文の条件を教材のどこで確認できるか

| 原典 | 教材の参照先 | 教材が表すこと、表さないこと |
|---|---|---|
| §3.1、図1 | `run.py` の `TASKS` と `pair`、`model.js` の `tasks` と `pair` | 同じ依頼・同じ入出力を使う許可側と禁止側を作ります。論文の300組は使わず、仮想の支払いとデータ提供で試します。 |
| §3.2 | `rollout` の `hidden`、`visible`、`read_again` | 通常の読み取りをやり直しても、指定した事実は得られません。可否に関わる事実と、可否にも入力値にも関わらない事実は別々に隠せます。別経路から漏れて見える場合は扱いません。 |
| §3.3、付録E | 履歴の `audit` と `audit_not_executed` | 別の照会が使えるREで、有効な照会を行うと、隠れた事実がすべて正しい値で返ります。教材では実行を確定するか停止を選ぶと処理が終わり、そのあとに予定した照会は行いません。 |
| §3.4、式(1)、付録B | `boundary` と `metrics` | 事実を隠さず失敗した場合は0、そうでなければ失敗が見つかった最小の欠落数を使います。すべて試して失敗がなかった場合だけc+1とします。教材は全組み合わせを列挙し、論文のハッシュによる探索順は使いません。 |
| §3.4、式(2) | `pair` の `paired` と `metrics` の `pur` | 重要な事実を1個以上、両側で同じように隠します。事実を取り戻してから禁止側では止まり、許可側では完了できた場合だけ成功です。課題ごとに成功割合を出し、各課題を同じ重みで平均します。 |
| 表1、付録C.2 | `evidence.md`、`results.json` の `reported` | ここに載せたのは、著者の報告値の一部です。教材が計算した `synthetic` とは別です。表の順位を根拠に、実運用で使うモデルを勧めるものではありません。 |

Pythonは参照用の結果を作り、ブラウザーではJavaScriptが同じ教材の規則を動かします。テストでは全480条件と全方策の結果を比較します。計算が合い、ブラウザーで操作できることと、実際のモデルを評価することは別です。教材には外部通信、認証、課金、実際のデータ送信を組み込んでいません。
