# EpiSEM-Bench：情報が足りないとき、操作してよいかを確かめる

操作の許可を判断するには、ツールが正しい情報を返すだけでは不十分です。たとえば金額の上限を確認できなければ、支払いを進めてよいかはわかりません。EpiSEM-Benchの著者は、同じ依頼が許可される側と禁止される側を組にして、両方で同じ事実を隠しました。著者は、許可を見分ける手がかりを別の手段で取り戻せると、エージェントの行動がどう変わるかを測っています。Labは、この評価方法には読む価値があると判断しました。ただし、実運用で使うモデルの推薦や、安全性の保証ではありません。

このLabの教材では仮想の支払いとデータ提供を使います。どの事実を隠すか、5種類の判断規則のうちどれを使うかは自分で選べます。通常の読み取りだけが使える設定をSE、別の照会手段も使える設定をREと呼びます。同じ依頼を両側で一歩ずつ進め、何がわかった時点で実行するかを見比べてください。実際のモデルを動かしたり、支払い・データ提供・外部APIの呼び出しを行ったりする教材ではありません。

## 教材を作り直して確かめる

次のコマンドはLabの全記事を含むリポジトリのルートで実行します。既に使っている出力先は上書きせず、新しいパスを指定してください。

```bash
uv sync --locked --extra dev --python 3.12
uv run --locked python papers/episem-missing-evidence-recovery/run.py
uv run --locked pytest -q -ra --fail-on-skip
uv run --locked paper-lab build --out /tmp/episem-new-full-site
uv run --locked python tests/review_103.py --preflight \
  --site /tmp/episem-new-full-site --out /tmp/episem-new-preflight
```

`run.py` は標準ライブラリだけで `results.json` を作り直します。サイトのビルドは `model.js` と `interactive.js` も教材として配布します。一部の記事だけでビルドして、公開サイト全体を置き換えないでください。

ブラウザーの検査では既存のmacOS CIで保護を有効にし、幅360・768・1440pxでの操作、ステップ送り、初期設定への戻し方、JavaScriptを無効にした場合の案内を確かめます。Node.jsで計算が合ったことは、実ブラウザーで画面を操作できた証拠ではありません。CIではChromeの署名、ループバックだけのCDP接続、Seatbelt、ProtectionStopを確認し、保護に失敗したLinux経路で再試行しません。

## この教材で確かめたことと、確かめていないこと

- **確認済み（CONFIRMED）:** この教材では、事実が通常の再読では戻らないこと、別の照会で戻ること、処理が終わってからは照会しないことをテストしました。テストでは、PythonとJavaScriptで全480条件の計算結果と集計が一致しました。実ブラウザーの検査は別に行います。
- **一部を扱った（PARTIAL）:** 論文の評価方法の一部を、2課題の真偽値による規則と、隠した事実をすべて正しく返す照会で表しました。論文のように探索を打ち切らず、教材では決められた組み合わせをすべて計算します。
- **公開を確認できなかった（NOT OBSERVED）:** 著者コードと試行記録の公開先は、参照した資料の範囲では確認できませんでした。
- **未検証（NOT TESTED）:** 著者の300課題や実モデル、認証・照会先の障害、実際の操作や本番での安全性、信頼区間、繰り返した結果のばらつきは検証していません。
