# DSI：視聴時間の平均から分からないこと

## 論文の概要

動画を平均で何秒見るかが同じでも、見終える人の割合や、動画の長さを超えて見る人の割合は異なり得ます。DSIの著者は視聴時間の分布を予測し、平均の秒数に加えて、動画を見終える確率なども推薦に使えるようにしました。

公開データ3種類では、各データで最も成績が良かった比較手法より、視聴時間の平均絶対誤差が1.9〜8.5%小さくなりました。これは既存のデータを使った視聴時間予測の比較です。実際に推薦を切り替えて、利用者の視聴時間が増えたかを調べた結果ではありません。

## 同じ平均でも、視聴の内訳は違う

10秒の視聴は、12秒の動画なら終わりに近く、60秒の動画なら序盤です。そこで動画の長さも渡すと、平均でどこまで見たかは比べられます。

それでも、平均を出す前のばらつきは分かりません。たとえば全員が10秒見る場合と、0秒と20秒に半分ずつ分かれる場合は平均が同じです。後段のモデルが平均と動画長しか受け取らなければ、終わりに近い視聴や長い視聴がどのくらいあるかを区別できません。

## 分布をまとめて、別の予測にも使う

著者は、学習を終えた分布推定器を固定し、その出力を27個の値にまとめます。視聴秒数を予測するモデルと順位を付けるモデルは、要約と元の特徴を共通の入力にして、別々の目標で学習します。

後段のモデルに視聴状態ごとの確率を渡しておけば、予測する項目を変えても、同じ分布を使えます。視聴秒数を出したい場合と、動画の長さを大きく超えて見た候補を上位に置きたい場合では、使う情報が異なります。

付録Eでは、視聴状態を明示せず時間だけを学習するモデルや、四つの区分を使わずに作る27個の要約値でも、成績はおおむね同じでした。四つの状態に分ける方法は確率の内訳を読みやすくしますが、この比較だけでは精度向上の原因とは言えません。

状態を分ける式と操作図は [method.md](method.md) にあります。

## 著者は何を比べたか

[一次資料の表1](https://arxiv.org/html/2609.28383v1#S4)で、著者は完全なDSIと9種類の比較手法を評価しました。表の比較相手は、データごとに平均絶対誤差（MAE）が最も小さかった方式です。値は乱数を変えた3回の平均±標本標準偏差で、MAEの単位は秒です。

| データ | 既存方式で最小のMAE | DSIのMAE | DSIのXAUC |
| --- | --- | --- | --- |
| KuaiRec | EGMN 3.8327±0.1617 | 3.5059±0.0044 | 0.6827±0.0004 |
| KuaiRand-1K | D2Q 12.5668±0.0251 | 12.3244±0.0362 | 0.7367±0.0010 |
| WeChat21 | D2Q 13.2964±0.0301 | 12.9278±0.0062 | 0.7020±0.0004 |

XAUCは、実際の視聴秒数が異なる二つの記録の順序を、予測値がどれだけ正しく付けられたかを見る指標です。DSIは2データで最も高く、WeChat21ではCREADの0.7054を下回りました。著者は1回の表示を単位に8:1:1で無作為に分割したので、同じ利用者や動画が複数の区分に入ることがあります。入力した履歴は表示時点より前のものですが、将来の動画や利用者へ時間をずらした評価ではありません。WeChat21では動画長60秒未満かつ視聴時間と動画長の比が10未満の記録を使いました。


図3では、既存方式もDSIと同じ順位付けモデルを使います。元の特徴量や入力幅、学習に使う100万件の表示もそろえました。既存方式の検索指標も上がったので、表1で見えた差の大部分は、分布の要約ではなく順位付け側の学習目標に由来すると著者は解釈しました。

表2では、同じ分布推定器の出力を「平均の対数変換と、平均を動画長で割った値」または「27個の要約値」にして比べました。後者を使うと、110%を超える視聴を上位に集める指標（OP-N@5）は3データとも高くなりました。一方、終了付近の視聴も正解に含める指標（Long-N@5）は、3データ中2つで前者が上回りました。分布を渡せば評価項目がすべて改善するわけではありません。

表3・4では分布を推定するモデルを学習し直さず、新しい目標に合わせた小さなモデルを学習しました。視聴時間から作った別の目標のほか、あらかじめ別に記録された「いいね」「フォロー」「コメント」「共有」も調べました。本番で推薦を切り替えた結果や、売上・継続率への効果は報告していません。

## Labの合成例で確かめる

Labは、平均視聴時間と動画の長さが同じ二群を作りました。図の選択欄で、視聴が0秒と20秒に分かれる群の割合を変えられます。また、どちらの群かを区別できない場合と、先に決めた分布をそのまま受け取れる場合で、110%を超える視聴の確率がどれだけ外れるかを計算します。

ブライアスコアは、予測確率と実際に起きたかどうかを表す0または1の差を二乗した値です。ここでは、その値を人工分布の確率で重み付けして平均することで、予測した確率の誤差を比べます。モデルは学習しません。

二群を同数とすると、平均だけから得られる最良の共通予測は0.25で、ブライアスコアは0.1875になります。Labが先に決めた分布をそのまま使い、群ごとに0と0.5を予測すると0.125になります。

どちらも平均視聴時間は10秒と予測します。差が出たのは110%を超える視聴の確率です。これは、モデルが実際の視聴データから確率を推定できたという結果ではありません。

## 検査した範囲

Labは合成例で二群の動画長と平均が等しいこと、110%を超える視聴の割合が異なることを確かめました。また、各状態で取り得る時間だけに確率を置いて合計が1になること、終了付近を動画の終端にまとめること、状態の境界を確認しました。

Labは、論文の分布推定器、27個すべての要約、順位付けと秒数予測に使うDCNv2のモデルを学習していません。公開データでの比較、別の予測目標への転用、推論負荷、本番の効果も再現していません。

## 実行して保存結果を作り直す

`run.py` はPythonの標準ライブラリだけで動きます。保存した場所で `python3 run.py` を実行すると、同じ場所の `results.json` と図を含む `method.md` を書き換えます。`state()` は視聴を四つの状態に分け、`summarize()` は状態ごとの確率と平均を求め、`expected_brier()` は確率予測の誤差を計算します。各状態が取り得る時刻は、0〜20秒を1秒刻みにした格子で確認します。

リポジトリのルートから実行する場合は、次のコマンドが使えます。

```sh
uv run papers/beyond-scalar-dsi-watchtime/run.py
uv run paper-lab build
```
