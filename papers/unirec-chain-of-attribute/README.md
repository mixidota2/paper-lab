# UniRec：SIDで失った属性を、生成の途中に戻す

Shopeeの研究チームは、商品を直接当てる代わりに、まず利用者が選びそうな商品のカテゴリなどを予測する推薦モデルを提案しました。UniRecは、予測した属性を手掛かりに商品の識別子（SID）を順に生成します。候補を探してから別のモデルで順位を付ける方式に対し、商品の特徴を生成の途中に入れ、候補を探す処理と順位付けを一つのモデルで扱います。

Shopeeはメイン画面とランディングページで、各群に利用者トラフィックの20%を割り当て、従来の多段推薦と比べました。著者は全体でページビューあたりのクリック率が5.37%、注文数が4.76%、取引総額が5.60%増えたと報告しています。ただし、ランディングページ単独のクリック率は報告していません。論文は、生成モデルと判別モデルが同じ順位を出すと説明しています。その式で省いたのは、利用者に対して各商品の特徴が現れる確率です。この確率が商品ごとに違えば、式をそのまま使って同じ順位になるとは言えません。

一次資料：[2604.12234v4.pdf](https://arxiv.org/pdf/2604.12234v4)。PDFのSHA-256と対応する節・表は[mapping.md](mapping.md)、モデルと式は[method.md](method.md)に記す。サイト本文の原本は[lab.yaml](lab.yaml)。

## 実行

```bash
uv run papers/unirec-chain-of-attribute/run.py
```

Labは属性が正しく分かる4-token分布で、属性ありと属性なしのentropyを比べる。露出の上限を超えたcluster（商品のグループ）から商品を移す貪欲法も試す。商品1個の露出が大きすぎて上限を守れない例を含めた。Bayesの式では2商品の確率表を使い、分母の補正を省いた順位と補正した順位が逆になることを確かめる。
