# UniRecはカテゴリを予測してから商品を表すコードを生成する

Shopeeの研究チームは、商品を直接当てる代わりに、まず利用者が選びそうな商品のカテゴリなどを予測する推薦モデルを提案しました。UniRecは、予測した属性を手掛かりに商品の識別子（SID）を順に生成します。候補を探してから別のモデルで順位を付ける方式に対し、商品の特徴を生成の途中に入れ、候補を探す処理と順位付けを一つのモデルで扱います。

Shopeeはメイン画面とランディングページで、各群に利用者トラフィックの20%を割り当て、従来の多段推薦と比べました。著者は全体でページビューあたりのクリック率が5.37%、注文数が4.76%、取引総額が5.60%増えたと報告しています。ただし、ランディングページ単独のクリック率は報告していません。

[原論文の第4版PDF](https://arxiv.org/pdf/2604.12234v4)のSHA-256と参照箇所は[対応表](mapping.md)、モデルの構成と式は[方法](method.md)に記した。サイト本文は[lab.yaml](lab.yaml)で確認できる。

## 実行

リポジトリの最上位から次のコマンドを実行すると、スクリプトは同じフォルダーの `results.json` を更新する。

```bash
uv run papers/unirec-chain-of-attribute/run.py
```

Labは、属性を正しく観測できる4トークンの人工分布で、属性を知る前後の不確かさを比較する。次に、露出の上限を超えたクラスタから別のクラスタへ商品を移す。商品1個の露出が上限を超え、どこに移しても制約を満たせない例も扱う。最後に2商品を例にして、ベイズの式で分母を省くと順位が逆になることを確かめる。

## 検証範囲

Labは人工分布で仕組みの一部を確認した（Mechanism: PARTIAL）。[結果ファイル](results.json)の `checks` に記したCONFIRMEDとNOT OBSERVEDは、個別の計算や反例に対する判定だ。実運用での性能、規模を大きくした場合の挙動、本番への適用は検証していない（NOT TESTED）。

Labは、属性を誤って予測した場合の影響や、ビーム探索で候補を拾う割合を測っていない。モデル全体を学習させる試験、RFT・DPOの学習、ShopeeでのA/Bテスト、推薦の各段を単独で外した試験も行っていない。人工分布で不確かさが小さくなった結果だけでは、クリック率の改善や生成と判別の順位の一致は判断できない。
