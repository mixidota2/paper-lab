# FlashVector: Agent for Hierarchical Model Serving Stack Optimization

WuらはUnityの広告配信で、モデルが遅い原因を調べ、変更を試す仕組みを作りました。FlashVectorはGPUの演算だけでなく、モデルサーバーでの入力変換や、要求を受けてから特徴量を作る処理も調べます。変更後の出力を確かめ、実際の配信要求を再生して、応答時間と処理件数の変化を測ります。

著者らの比較では、ある順位付けモデルの処理件数が同じ時間で2.00倍になりました。別の候補検索モデルでは、入力の変換だけは最大30倍速くなりましたが、配信全体の処理件数は1.10倍でした。どちらも同じ測定環境でモデルごとに変更前後を比べた結果です。全モデルの平均や、広告のクリック率の改善を示した結果ではありません。

## 教材で確かめること

一部の処理が速くなっても、配信全体が遅くなったり、応答時間が上限を超えたりする変更を見送れるでしょうか。Labは架空の変更案5つを使い、どの条件を満たさないと見送るかを示します。実際の配信を再現する教材ではありません。

## 実行方法

```bash
uv run papers/flashvector-unity-serving-stack-agent/run.py
```

スクリプトはPythonの標準ライブラリだけで動きます。単体で取得した場合は、保存した場所で `uv run run.py` を実行します。結果はスクリプトと同じ場所の `results.json` に保存されます。

## 読む順序

`lab.yaml` に論文の概要と比較の根拠があります。計測から採用までの手順は `method.md`、教材の条件と結果は `run.py` と `results.json`、原論文から省いた処理は `mapping.md` にあります。記事のHTMLは `uv run paper-lab build` で生成できます。
Labが確認したのは、与えられた値から採用の可否を決める規則の一部です。配信性能、規模を広げた場合の動作、本番で使えるかは確認していません。
