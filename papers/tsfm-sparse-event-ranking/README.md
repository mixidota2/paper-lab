# 数量予測で発生する時点を選べるか（When, Not How Much）

## 研究で分かったこと

著者は、販売数や乗車件数が0を超える時点を、次の64時点の中で上位に並べられるかを調べました。5つのデータセットを使い、0と正の値が両方ある区間だけを採点しています。すべての時点が0になる区間を見分けられるかは、この実験では分かりません。

12種類の時系列基盤モデルでは、公開時の点予測を使った順位が、学習不要の方法より最大0.031高くなりました。指標は、偶然の得点を補正した平均適合率（AP skill）です。別の比較では、著者は6モデルの本体を固定し、途中の出力から発生を学ぶ線形分類器を追加しました。同じモデルの点予測との差は、30組中29組で95%区間全体が0を上回りました。一方、Favoritaの売上では、6モデルすべてが過去の観測値から直接学ぶLightGBMを下回りました。

## 何を順位付けするか

巡回先や人員を置く日を絞るなら、「どれだけ発生するか」より「いつ発生するか」を先に知りたい場合がある。著者は次の64時点を一つの評価区間（窓）とし、観測値が正になる時点が上位に並ぶかを調べた。対象はAmazonの購入、FavoritaとM5の売上、NYC taxiの地点別の乗車件数、Web trafficの5データセットだ。

著者は0が40%以上を占める系列を選び、将来部分に正値と0が両方ある窓だけを採点した。将来64時点がすべて0の窓を見分けられるかは調べていない。観測が0なら非発生として採点するが、記録の欠測や欠品も0に含まれ得る。

## 著者の主張とLabの解釈

著者は、時系列基盤モデルの点予測を、学習不要の順位付けと比べた。次に、モデルの内部表現を固定し、発生ラベルで学ぶ線形分類器（probe）を追加した。生の履歴を使うロジスティック回帰とLightGBMも発生ラベルで学ぶ。最後に、同じ構造をランダムに初期化したモデルでもprobeを学び、事前学習済みの場合と比べた。

Labでは、数量を当てることと発生する時点を選ぶことを分けて考える。非負の数量では E[Y|x] = P(Y>0|x) × E[Y|Y>0,x] なので、平均の順位には発生時の数量も効く。中央値を使うと、発生確率が50%未満なら0になり、発生確率1%と49%は区別できない。これは分布の性質で、原論文のモデルが常に厳密な0を返したという結果ではない。

採点方法は [method.md](method.md) にまとめた。

## 発生を学ぶと何が変わるか

需要が発生したかを教師として学ぶ出力部（head）は、数量に変換する前の内部表現を受け取る。点予測との違いには、内部表現を使ったことと発生ラベルで追加学習したことが含まれる。この差だけでは、事前学習の効果は分からない。著者は、生の履歴から同じ発生ラベルで学ぶ直接モデルと、同じ構造のモデルをランダム初期化して得た表現も比べた。

CrostonやTSBは、発生間隔や発生確率を数量と分けて扱う。予測期間内でスコアが一定なら、同じ窓に入る時点に順位は付かない。原論文§2はこうした先行手法と、時系列基盤モデルの凍結表現を分類に使う研究を整理している。今回の比較では、点予測と教師あり分類を同じ発生ラベルで採点し、ランダム初期化も別の対照に置いた。

## 著者が報告した結果

[一次資料：原論文v1](https://arxiv.org/pdf/2609.39386v1)のTables 3–4に基づく。各モデルを著者が実データで検証した結果で、Labの再実験ではない。表は窓に同じ重みを付けたAP skillの差を示す。点予測の列の「最大」は、同じテスト集合で比較したモデルのうち最大だった差で、あらかじめ選んだモデルの成績ではない。

| データ | 点予測−参照の中央値 / 最大 | probe−点予測の中央値 | probe−生の履歴を使うLightGBMの中央値 |
| --- | ---: | ---: | ---: |
| Amazon | −0.002 / +0.002 | +0.006 | 0.000 |
| Favorita | +0.007 / +0.023 | +0.082 | −0.020 |
| M5 | −0.005 / +0.013 | +0.032 | +0.002 |
| NYC taxi | +0.013 / +0.031 | +0.015 | −0.001 |
| Web traffic | +0.003 / +0.006 | +0.047 | −0.115 |

probeからLightGBMの得点を引いた95%区間について、正・0を含む・負の順にモデルを数えると、Favoritaは0/0/6、M5は3/0/3、Webは0/0/6だった。M5の最良probeはLightGBMを0.012上回った。どのモデルも同じ程度だとは言えない。

著者がprobeを学習したモデルは、Chronos-2、Chronos-Bolt、Sundial、TimeMoE、Timer、Toto-2.0の6件だ。事前学習済みとランダム初期化の表現を同じ条件で比べると、26/30組でAP skillの差の区間が正だった。Favoritaでの差の中央値は+0.070。TimerではFavorita、M5、Webで、ランダム初期化した表現を使うprobeのほうが高かった。

著者は表20で、64時点のうち上位8時点に含まれた発生数も比べた。売上のデータで、1区間あたりの平均を下表に示す。例えばFavoritaでは、点予測で上位8時点を選ぶと、実際に販売数が正だったのは平均4.79時点だった。

| データ | 無作為 | 学習不要 | 最良の点予測 | 過去の履歴から学ぶLightGBM | Chronos-2の線形分類器 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Favorita | 4.34 | 4.80 | 4.79 | 5.01 | 4.98 |
| M5 | 2.87 | 3.18 | 3.16 | 3.22 | 3.27 |

「最良」は同じテストデータで比較した12モデルの最大値だ。全時点が0の区間などを除いた集計なので、実際に8時点を確認したときの平均件数とは言えない。ここでいう発生は観測値が正になったことで、欠品などで記録されなかった需要は数えない。

著者は0.1〜0.9の9分位点を平均した値でも順位を付けた（Appendix F.2）。標準出力が中央値だった7モデルで比べると、35組中27組は、9分位点の平均に替えたときの得点差の95%区間が正だった。参照を上回った幅の最大は、NYC taxiのChronos-2で0.057だった。9分位点の平均は、分布全体の平均ではない。M5とNYC taxiでは、最も高い得点を出した分位点平均が大半のprobeを上回った。9点だけを平均しても、分布の端まで反映する予測平均にはならない。

Web trafficで採点した0ラベルの68%は欠測に由来する。履歴と将来の両方に欠測がない窓だけに絞ると、LightGBMがprobeを上回る差の中央値は0.039まで縮む。ただし、残る窓の構成も変わるので、欠測だけの影響とは言えない。各窓ではなく各系列を等重みにした場合は、Web trafficの全TSFMの点予測が参照を下回った。Favoritaでは、商品が欠品して売れなかった日も0になり得る。

著者は系列単位で2,000回再抽出するbootstrapで区間を求めた。多重比較の補正はしていない。NYC taxiはデータを1通りに分割して評価しており、事前学習データと評価データにも一部重複がある。この実験で測った順位の良さは、確率校正や在庫・人員配置の費用削減を示さない。

## 人工データと採点方法

Labの人工データでは、確率pで発生する指標Bを用いて `Y = B × (1 + NB)` と表す。BはBernoulli(p)に従い、NBは負の二項分布に従う。発生した時点の数量は1以上なので、Yが正になる確率はpと一致する。すべてのpを0.5未満にし、発生時の平均数量を5個に固定する条件と、発生しやすいほど平均数量が小さくなる条件を比べた。

真の人工分布から求めた中央値、平均、9分位点の平均をそれぞれ順位付けに使う。発生を教師として特徴xから学ぶロジスティック回帰も比べる。乱数の初期値ごとに700窓で分類器を学習し、学習に使わなかった300窓で各方法を評価した。

平均適合率（AP）は、スコアを高い順にたどるとき、発生した時点がその時点までの上位にどれだけ集まるかを測る。同点は一つの群とし、同点を恣意的に並べ替えて成績を上げることはしない。スコアと発生数を固定し、発生ラベルの位置だけを無作為に並べ替えたときのAPの期待値をAP₀とする。

同点群bの位置数をsᵦ、発生数をaᵦとする。CᵦとAᵦはそれぞれ群bまでの位置数と発生数、nとkは窓全体の位置数と発生数だ。すると `AP = Σ aᵦ Aᵦ / (k Cᵦ)`、`AP₀ = (k−1)/(n−1) + (n−k)/[n(n−1)] × Σ sᵦ/Cᵦ` になる。採点対象の窓でスコアが全て同じならAP₀は発生率k/nと一致し、同点群が複数あれば一致しない。

`AP skill = (AP − AP₀)/(1 − AP₀)` は各窓で計算してから平均する。負の値も残し、発生と非発生のどちらかしかない窓は採点しない。

## 人工データで確かめた結果

人工データでは、発生時の平均数量を5個に固定すると、全時点に0を付ける中央値のAP skillは0だった。平均と発生を学んだ分類器には、発生時点を並べる情報が残った。一方、発生確率が高いほど発生時の数量が小さくなる設定では、平均で付けた順位の得点が下がった。数値は `results.json` とページの人工実験表で確認できる。この条件は仕組みを示すために選んだもので、現実にどれだけ起きるかは測っていない。

## Labで確認した範囲

**仕組みは確認済み（Mechanism CONFIRMED）。** n≤6の全同点構成と、発生・非発生が混ざるラベルの配置を列挙して、Appendix B.1のAP₀の式と一致することを確かめた。スコアが一定ならAP skillは0になる。窓ごとの順位に情報がなくても窓を混ぜると正のスコアになるAppendix B.3の例も検査した。人工データでは、中央値が発生確率の違いを残さない条件と、平均の順位が発生時の数量に影響される条件も確かめた。

## Labで確認していない範囲

性能、規模を広げた場合の挙動、本番適用性は未検証（Performance / Scaling / Production applicability: NOT TESTED）。Labの分類器は時系列基盤モデルの表現を使わない。TSFM本体、実データのprobe・LightGBM・ランダム初期化との比較、GPU時間、確率校正、在庫や人員配置にかかる費用は再現していない。中央値で発生確率の差が消えることだけで、原論文の各モデルの結果を説明できるとは限らない。

uv run papers/tsfm-sparse-event-ranking/run.py
