# 原論文とLabの対応

Labは人工データを使い、どの商品がIDの生成中に候補から消え、どの商品が最後の並べ替えで順位を変えるかを別々に見る。Amazonのデータで論文の精度を再現したわけではない。

| 原論文で扱うもの | Labの対応 | どこまで確認したか |
| --- | --- | --- |
| [§2〜3・表1〜2](https://arxiv.org/html/2607.24995)：IDの役割と近傍の変化 | `method.md` と `geometry.svg` | 図の点は概念を示すために作った。実際の商品の埋め込みではない。 |
| [式15〜17](https://arxiv.org/html/2607.24995)：ビームを絞る前と、生成した後の順位融合 | `run.py` の `decode()`、数式の図 | 固定した8商品の確率で、順位を使う段階を切り替えた。 |
| [§5.1](https://arxiv.org/html/2607.24995)：別の商品順位を作る | `ranker()` | Labは人工の遷移回数を使う。論文の式14やSASRec、UniSRecを再現していない。 |
| [式10](https://arxiv.org/html/2607.24995)：生成中の残存率 | `evaluate()` と `beam.svg` | 論文は別モデルが正解を上位k件に置いた履歴に限る。Labは人工の評価9件をすべて数える。 |
| [表5](https://arxiv.org/html/2607.24995)：二つの介入段階の比較 | 4通りの有無の組み合わせと、外部順位を逆順にした条件 | データも集計する履歴も論文とは異なる。 |

一次資料はarXiv第1版。著者は論文にコードの公開先を記している。Labは公式実装との行単位の照合をしていない。論文本文のIdentity@1は99.57%、表1のSentence-T5は99.51%と記されている。どの集計条件に対応するか分からないため、一つの数にまとめない。

[GLIDE](glide-spotify-sid.html)は本番のR-KMeansとIDが重なる場合の処理を、[TGR](tgr.html)は候補生成の経路を扱う。どちらも、この論文でAmazonの商品を使ってSIDを比較した条件とは異なる。
