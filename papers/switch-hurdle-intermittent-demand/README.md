# Switch-Hurdle: A MoE Encoder with AR Hurdle Decoder for Intermittent Demand Forecasting

売れない日が多い商品で、売れる確率と、売れた日の数量をどう予測するかを説明します。

## 概要

著者は、売れない日が多い商品で、いつ売れるかと、売れた場合に何個売れるかを分けて予測しました。Switch-Hurdleは入力ごとに複数の処理の候補から一つを選び、その出力を使って、販売が起きる確率と起きたときの数量を別々に求めます。M5データの比較では、複数の集計単位の予測誤差を重み付きでまとめた指標（WRMSSE）は0.6307で、TSMixerの0.6403より小さくなりました。ほかの指標では最良ではないものもあり、在庫費用や欠品が改善したかは調べていません。

## 著者は何を予測したか

著者は、日ごとの販売数について、M5の30,490系列と社内データの約40,000系列で予測を比較しました。どちらも過去56日から次の28日を予測します。販売数をならして一つの平均で表すと、売れる日がどれほど少ないか、売れる日にどれほど多く売れるかが分かりにくくなります。

## Switch-Hurdleの仕組み

著者のモデルでは、学習した振り分け器（router）が過去の時点ごとに送り先を選び、入力を1つの処理ネットワーク（expert）に渡す。デコーダーは、売上がゼロでない確率と、売れた場合の数量を別々に予測する。売れた場合の数量には、ゼロを除いた負の二項分布を使う。

デコーダーは、エンコーダーがまとめた履歴と前日の予測などから当日の予測を作ります。

Labはこの分け方に注目しました。売れる頻度が変わっても、売れる日の数量分布をそのままにできます。逆に、売れるときの数量が変わっても、売れない日の確率を変えずに済みます。ネットワークは人が「常にゼロを扱う担当」などと決めて割り当てたものではありません。

## 論文では、どの指標で誤差が小さかったか

[論文の表4・表5・図4〜5](https://arxiv.org/pdf/2602.22685v1)を確認しました。M5のWRMSSEはSwitch-Hurdleが0.6307、TSMixerが0.6403、TFTが0.6932、DeepARが0.7895でした。RMSEではSwitch-Hurdleの2.4744よりPatchTSTの2.4562が小さく、MASEではSwitch-Hurdleの0.8992よりTFTの0.8983が小さくなりました。著者の社内データ全体では、WAPEはSwitch-Hurdleが53.99%、TFTが55.60%でした。MASEはTFTの方が小さく、Switch-Hurdleが0.5865、TFTが0.5803でした。在庫や欠品を測った結果ではありません。

著者は学習後のモデルが入力をどこへ送ったかも、検証データで集計しました。第0層では、需要ゼロの入力の67.5%をネットワーク3に送り、少ない需要の90.8%と急増の94.0%をネットワーク1に送りました。集計は、同じ需要区分の入力のうち何割を各ネットワークに送ったかを示しています。著者がこの区分を使ってネットワークを割り当てたわけではありません。

## 人工例を実行する

リポジトリのルートで `uv run papers/switch-hurdle-intermittent-demand/run.py` を実行すると、スクリプトが同じフォルダーの `results.json` を更新します。計算にはPython標準ライブラリだけを使います。

平均μとばらつきのパラメータαを固定し、1個以上売れる確率p⁺を0.1、0.5、0.9に変えます。通常の負の二項分布と、発生確率を別に指定した分布について、各数量の確率を足して全体が1になるか確かめます。

μ=2、α=0.5の通常の負の二項分布では、0個の確率が0.25で、1個以上の場合の平均は約2.6667個です。p⁺=0.5にすると、0個の日も含めた平均が約1.3333個になります。売れる頻度だけを変えたので、売れた場合の平均は変わりません。

`nb()` は通常の負の二項分布の確率を計算します。`hurdle()` は0個を除いたうえで、1個以上に残った確率を合計が1になるように調整してから、売れる確率を掛けます。計算では0〜999個を足し合わせ、図には0〜20個と、その外側に残る確率を示します。

## Labが確認したことと、確認していないこと

Labは、分布全体の確率が1になること、売れる頻度だけを変えられること、0個を除いたときに平均が変わることを人工例で確かめました。確認したのは、予測の出力を確率分布にする計算の部分だけです。

Labは、どのネットワークに入力を送るかを学ぶ部分や、1日ずつ予測するデコーダーを実装していません。M5の予測精度、処理の規模を増やした場合、本番での利用、欠品、需要数量の充足率（fill rate）、在庫費用も検証していません。
