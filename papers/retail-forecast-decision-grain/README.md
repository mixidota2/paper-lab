# 需要予測モデルを選ぶとき、どの単位で何の費用を比べるか

商品ごとの予測誤差が最小のモデルでも、カテゴリの売上計画や発注の費用を最も抑えるとは限りません。Labの画面で集計の順序や余り・不足の費用を変え、評価の選び方でモデルの順位が入れ替わる理由を確かめられます。

この教材は *World Models, Trees and Foundation Models for Retail Forecasting: Evidence from Four Public Data Sets* の初版（arXiv 2610.25170v1、Labの評価は Worth Reading）を扱います。著者は、同じ販促計画を使うモデル同士でも評価方法で順位が変わりうると報告しました。Labは人工例で初版の計算を説明します。第3版（v3）の異なる評価と結果は根拠の節に分けました。Labはどちらの版でも、著者モデルを学習し直したり著者の元の実験を再現したりしていません。

## 教材を再生成する

依存関係を準備したあと、リポジトリのルートで次のコマンドを実行してください。

```sh
uv run python papers/retail-forecast-decision-grain/run.py
uv run pytest -q -ra --fail-on-skip tests/test_retail_grain.py
uv run python -m paper_lab.build --out /tmp/retail-grain-preview
```

著者の公開CSVが手元にある場合は、次のコマンドで初版の結果表を集計できます。Python標準ライブラリを使ったLabのコードが動きます。著者のコードは実行しません。

```sh
uv run python papers/retail-forecast-decision-grain/run.py --tables /path/to/official-csvs --out /tmp/table-counts.json
```

Labは `category_cost.csv` から `variant=dollars` を、`decisions.csv` から `set=rolling, decision=replenish_0.8` を選びます。旧式の `category_planning` は集計から外します。8つの評価単位で、どの方法の費用が最小だったかを数えます。統計的に優れていた回数ではありません。配布物には第三者のCSV・コード・PDFを同梱していません。

## 何を確かめたか

- 確認済み（CONFIRMED）：自作の式の計算、境界値、結果を生成し直したときの保存値との一致、範囲を限定した公式CSVの集計。手法全体の確認は一部（PARTIAL）です。
- 未確認（NOT TESTED）：著者モデルの学習・推論、実店舗への効果、運用費用。著者コードは読みましたが実行していません。学習済みモデルと著者の実行環境も確認していません（NOT OBSERVED）。
- 画面操作：ブラウザーの画面要素を模した環境でイベントを検査しました。実ブラウザーの表示や操作は未確認です。画面は図の横幅を親要素に収め、狭い幅では操作欄が縦に並ぶよう設計していますが、実機の描画は確認していません。

ブラウザーの画面に入力できるのは、0〜10000の有限な数です。空欄や負数は入力として受け付けません。分母が0のときは「未定義」と表示します。Python版は非負の有理数で計算し、結果をJSONの数値に変換します。

公式CSVを集計すると、Labのコードは入力ごとにバイト数、SHA256、Git blobのハッシュを記録します。2つのファイルが両方とも既知のblobに対応すると分かった場合だけ、`source_snapshot` に版を記録します。対応を確認できない場合は `source_snapshot` がnullになり、`unverified_inputs` を返します。完全に一致した場合と、保存時に末尾の改行LFが1バイト増えただけの場合は区別します。確認できるのは対象2ファイルの対応だけです。任意のCSVの入手元やリポジトリ全体を保証したり、元の実験を再現したりはしません。

## 条件を保存し、後から再開する

「現在の条件をJSON保存」を押すと、集計単位、売上や予測、評価期間、発注量、余りと不足の費用を決める比率など、7項目の入力と計算結果を保存します。JSONは画面下の欄にも表示されます。再開するときは保存したJSONを貼り付け、「JSONの条件を読み込む」を押します。入力に誤りがあれば現在の条件は変わりません。

保存形式は schema 1、`kind` は `retail-grain-scenario`、`model_version` は `retail-grain-1` です。`synthetic=true` は自作例を表します。読み込み時は保存された `output` を使わず、`inputs` の7項目から計算し直します。配布物の `results.json` や他のLabのJSONはこの形式ではありません。入力に誤りがある間は保存できず、初期値に戻すと貼り付け欄も空になります。条件を外部へ送信しません。

## 条件を一つ変えたときの差を見る

「現在の条件を基準にする」で、7項目の入力を固定してから条件を変えます。旧式と訂正式、期間ごとの比率の平均と全期間をまとめた比率、単期発注損失と不足単価について、基準と現在の値を並べて表示します。差は「現在−基準」です。分母が0の指標は差も比較できません。3つの実験で測るものが違うため、値を合計しません。売上や集計単位、費用条件を変えた差から、予測モデルの改善や施策の因果効果は判断できません。

基準を置き直すには同じボタンを押します。比較を止めるときは「基準を解除する」を押してください。入力に誤りがある間、画面は古い比較結果を表示しません。ただし、基準は開いているページ内だけに残ります。ページを再読み込みするか初期値に戻すと、基準も消えます。

比較を残すなら「基準と現在をJSON保存」を使います。比較用JSONは保存形式1の `retail-grain-comparison` で、`baseline` と `current` に各条件を格納します。同じ貼り付け欄から読み込むと、両方の入力を検証して結果・変更項目・差を計算し直します。保存された `output`、`changed_inputs`、`delta` は使いません。片方でも不正なら両方とも変更しません。単独条件のJSONを読む場合は、基準を保持して現在の条件だけを戻します。外部送信は行わず、著者モデルや配布物の `results.json` も書き換えません。
