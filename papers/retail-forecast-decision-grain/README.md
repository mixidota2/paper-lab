# 発注とカテゴリの計画では、同じ売上予測をどう評価するか

IyerとDabbeeruは、売上を商品・店舗ごとに予測する場合と、カテゴリなどにまとめて予測する場合を比べた。[初版（v1）](https://arxiv.org/pdf/2610.25170v1)では、商品×店舗の予測で3モデルの平均がよく当たったが、費用の式や集計の単位によって最小の方式は変わった。[第3版（v3）](https://arxiv.org/html/2610.25170v3)では、調整した2モデルが比較の中心になった。どちらの版でも、Labは著者モデルを学習し直していない。

この教材では初版の評価式を使い、架空の売上と予測を入れる。商品の集計方法、期間を平均する順番、不足の費用を変えると、同じ予測でも評価が変わる理由を確かめられる。

## 教材を再生成する

依存関係を準備し、リポジトリの最上位で次を実行する。サイトの出力先には未使用のディレクトリを指定する。

```sh
uv run python papers/retail-forecast-decision-grain/run.py
uv run pytest -q -ra --fail-on-skip tests/test_retail_grain.py
uv run python -m paper_lab.build --out /tmp/retail-grain-preview
```

初版の著者CSVを入手済みなら、Labの標準Python実装で、方式ごとに費用が最小だった件数を数えられる。著者のコードは実行しない。第三者のCSV・コード・PDFは配布物に入っていない。

通常の実行で作る `results.json` は、論文の結果ではなく教材の初期値を使った計算結果である。各項目は [results.json の読み方](mapping.md#resultsjson-の読み方) を参照。下の `--tables` は著者のCSVを集計する別のコマンドである。

```sh
uv run python papers/retail-forecast-decision-grain/run.py --tables /path/to/official-csvs --out /tmp/table-counts.json
```

Labは `category_cost.csv` の `variant=dollars` と、`decisions.csv` の `set=rolling, decision=replenish_0.8` を使う。旧式の `category_planning` は集計しない。この8単位の件数は、統計的に優れていた件数ではない。

集計時に、入力した各CSVのバイト数、SHA256、Git blobの値を記録する。両方が既知のファイルに対応した場合だけ、`source_snapshot` に版を記す。確かめられなければ `source_snapshot` は `null` となり、`unverified_inputs` に入力を記す。完全一致と、末尾のLFが1バイト増えただけの場合は区別する。確認の対象は2ファイルだけであり、任意のCSVの入手元やリポジトリ全体を保証しない。

## 一つの条件を保存して、後から再開する

「現在の条件をJSON保存」を押すと、集計単位、売上や予測、評価期間、発注量、費用の比率など7項目の入力と計算結果を保存する。JSONは画面下にも表示する。保存したJSONを貼り付け、「JSONの条件を読み込む」を押すと、7項目の入力から結果を計算し直す。保存された `output` は読み込まない。入力が不正なら、保存できず、読み込みでも現在の条件を変えない。

保存形式はschema 1、`kind` は `retail-grain-scenario`、`model_version` は `retail-grain-1` である。`synthetic=true` は人工例を示す。`results.json` や別のLabのJSONは、この形式ではない。初期値に戻すと貼り付け欄も空になる。入力を外部へ送信しない。

## 基準を固定してから、条件を変える

「現在の条件を基準にする」を押し、どれか一つの条件を変える。画面は旧式と訂正式、期間ごとの比率の平均と全期間の比率、1期分の発注損失と不足単価を並べる。差は「現在−基準」である。分母が0の値は差を出せない。3つの実験は指標が異なるため、結果を合計しない。条件を変えた結果から、モデルの改善や施策の効果を測るわけではない。

同じボタンを押すと新しい基準に置き換わる。「基準を解除する」を押すか、再読み込みするか、初期値へ戻すと基準が消える。入力に誤りがある間は古い比較結果を表示しない。

「基準と現在をJSON保存」で比較を残せる。形式はschema 1の `retail-grain-comparison` で、`baseline` と `current` に入力がある。同じ貼り付け欄で両方を読んだ場合は、入力から結果、変更点、差を再計算する。保存された `output`、`changed_inputs`、`delta` は使わない。どちらか一方でも不正なら両方とも変更しない。単独条件を読み込んだ場合は、基準を残して現在の条件だけを戻す。著者モデルや配布済みのファイルは変わらない。

## 確かめたこと、まだ分からないこと

画面は0〜10000の有限な数を受け取り、空欄や負数を受け付けない。分母が0なら「未定義」と表示する。Pythonは非負の分数で計算し、最後にJSONの数値にする。

Labが確認したのは、教材の式と境界値、再生成した数値が保存値に一致すること、対象を限定した初版のCSV集計である。著者のモデルや実店舗での効果と運用費用は検証していない。学習済みモデルや著者の実行環境も確認していない。この改訂の実ブラウザー表示は、画面要素を模した検査の結果とは区別する。
