# ORPR：最適化で補充の目安を作り、モデルに教える

ORPRは、在庫を抱えすぎず、売り逃しも抑える発注を学ぶ方法です。数理最適化で求めた補充量を教師データにし、約93万パラメータのモデルを事前学習するのが最初の段階です。その後、強化学習で業務に合わせます。著者はJDの菓子を対象に現場評価を報告しています。

## 何が分かったか

売り逃しを増やさずに在庫を減らしたいとき、何日分を補充すればよいでしょうか。ORPRは、数理最適化でその候補を選び、発注を決めるモデルに教えます。その後、ルールやシミュレーションで評価しながら強化学習で調整します。

著者が報告したJDの現場比較では、菓子3カテゴリで保有費用が29.95%低く、在庫回転日数が5.27日短くなりました。対象は担当者が選んだ、自動化の度合いが高い商品です。全商品を無作為に割り付けた実験ではありません。Labで動かすのは、補充の教師データを選ぶ計算と、強化学習で使う報酬差の計算です。JDでの効果は再検証していません。

## 補充量は「需要の何日分か」で比べる

需要や商品属性、販促、目標とする在庫回転日数から、商品の補充量を決めます。商品によって販売数量が違うため、数理最適化では数量を「需要の何日分か」にそろえ、整数の日数から選びます。満たせなかった需要は翌日以降に繰り越さず、売り逃しとして扱います。最適化で補充の目安を決める単位はカテゴリ、方策を調整する単位は個別の商品（SKU）です。

## Labの人工実験

Labでは、人工の12日分の需要を使います。2カテゴリそれぞれで1〜10日分から選ぶので、候補は100通りです。発注は3日ごと、入荷まで1日、単価は1に固定します。グラフで売り逃しの上限を切り替え、その上限を守る候補の中で、各日の期末在庫の合計が最も少ない組合せを探します。候補集合は変えず、制約だけを変えます。

別の計算では、4つの固定報酬について、それぞれから自分以外の報酬平均を引いた差を求めます。全報酬に同じ定数を足しても、他候補との相対的な差は同じです。これで確認できるのはRLOOの基準値の計算までで、TransformerやVAE、代わりのモデルは学習しません。

## 売り逃しの上限で、選べる補充量は変わる

売り逃しの上限を厳しくすると、選ばれる在庫日数と在庫の累計が変わります。初日は入荷が間に合わず、上限を十分に下げると、100候補のどれも条件を満たしません。「条件を満たす候補なし」は制約を守れないことを示す結果です。RLOOでは候補同士の報酬差を計算しただけで、学習後の補充が改善したかは測っていません。

## 確かめたこと

**確認済み（CONFIRMED）**：需要が販売と売り逃しに分かれること、在庫の収支が合うことを確かめました。100候補の上限判定、在庫最小の選択、すべての報酬に同じ値を足したときに差が変わらないことも検算しました。

**部分的に確認（PARTIAL）**：論文の仕組みのうち、補充候補をシミュレーションで評価し、教師データにする部分を扱います。ニューラルネットで学習した補充方策が、毎回制約を守るとは保証していません。

## 確かめていないこと

**未検証（NOT TESTED）**：TransformerとVAEの学習、RLOOでモデルを更新する処理、事前学習した方策からのずれを抑えるKL制約、販促の判断への専門家ラベルの利用。JDの総費用、現場への効果、大規模運用も再検証していません。菓子3カテゴリ・約30日の比較を、DeepStockで報告されたTmallの全カタログ展開と同じ範囲とみなしません。欠品費用は原論文の現場評価にも含まれません。
