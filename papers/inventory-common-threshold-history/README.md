# 共通の閾値で発注し、各期の費用比率を残す

予測を更新したとき、新しい情報で過去の費用も計算し直すと、発注の時期が変わることがあります。このLabでは、3期間の合成データを使ってその違いを確かめます。著者のコードや実店舗の結果は再現していません。原論文の保証とその前提は `evidence.md`、発注規則は `method.md` にあります。

配布された `run.py` はPython標準ライブラリだけで実行できます。`python run.py` を実行すると、コードと同じフォルダーに `results.json` を保存します。リポジトリでは、ルートから次のコマンドを実行できます。

## 合成需要と、閾値を変えたときの平均費用

需要は3期間で合計最大3個です。需要の経路を4本用意し、それぞれに確率1/4を割り当てます。追加信号の有無、納期0または1、固定の閾値ρを3通り、需要経路を4通り、履歴の残し方を2通り組み合わせると、表示用の96条件になります。固定したρごとの結果とは別に、ρの取り得る範囲を、どの発注判断も変わらない区間に分けます。各区間の費用に、閾値がその区間に入る確率を掛けて足すと、閾値の分布全体で平均した費用になります。乱数を使うシミュレーションは行いません。

計算コードが扱う需要木は、最大4期間、8経路、合計需要4個です。仕入費と初期在庫は0で、容量制約はありません。確率と各期の費用、比率の累計は有理数で計算します。閾値の分布関数（CDF）の指数計算は、Decimalの精度50桁とROUND_HALF_EVENを使い、その後にfloatに変換します。OSごとの数学ライブラリで最下位桁が変わるのを避け、同じJSONを再生成するためです。分数の桁数を極端に大きくした場合でも同じ計算資源で済む、という保証はありません。

最適費用の計算では、その時点までの履歴ごとに、発注なしから残りの最大需要までを試します。将来の期待費用を遡って求める動的計画法（DP）を使い、その履歴から選べる発注のうち最も安いものを選びます。選んだ経路の未来をあらかじめ知る方策とは比べません。

## `tight(epsilon)` が受け付ける範囲

関数は `epsilon` をまずPythonの `float` に変え、`sys.float_info.min <= epsilon < 0.5` のときだけ計算します。通常の64ビット浮動小数点数では下限は約2.225×10⁻³⁰⁸です。正の値でもこの下限未満だと、丸めた費用で倍率を計算する際の相対誤差が大きくなるため、`ValueError` を返します。ゼロ、負数、0.5以上、NaN、無限大も受け付けません。

正の値がとても小さいと、指数関数の値から1を引く計算では有効な桁が失われます。その場合、CDFは級数で差を直接計算します。この入力制限は`tight()`だけに適用します。任意の需要木について、極小の期待費用で割っても倍率の相対精度を保てるという保証はありません。CDFと期待費用の返り値は `float` です。画面の選択肢と保存した実験値は変わりません。

CDFでは、内部計算の設定を呼び出し元のDecimalの桁数・丸め方・指数範囲・例外設定から切り離します。この関数を呼び出しても、呼び出し元の設定や計算状態は変わりません。
