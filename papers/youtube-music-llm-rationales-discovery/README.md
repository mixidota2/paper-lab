# YouTube Music：曲の候補を増やすことと、理由を添えること

## 概要

YouTube Musicの研究チームは、ホーム画面の「Your Daily Discover」で、知らないアーティストを見つけやすくする方法を試しました。従来は、よく一緒に聴かれるか、音などの特徴が似ているかを基準に候補を探し、「好きなアーティストのファン向け」のような定型文で理由を示していました。新方式では、利用者の好みのまとまりごとに、大規模言語モデルが新しい候補と推薦理由を事前に作ります。理由文は、新しい候補だけでなく従来の候補にも付けられます。

2週間の本番実験で、著者はこの推薦欄での反応が22.43%増え（95%信頼区間は16.93〜27.93%）、発見や継続利用に関する指標が8.07%上がったと報告しています。候補と画面を変えずに理由文だけを外すと、候補の追加と理由文の両方を外したときと同程度に、利用者の反応が減りました。新しい候補を増やす機能だけを外した場合、反応に明確な差は出ていません。これらはこの推薦欄での結果で、YouTube Music全体の利用継続率ではありません。

## 手元で確認する

このフォルダーで `uv run --no-project python run.py` を実行します。Pythonの標準ライブラリで計算し、`results.json` に保存します。

3候補から、辞書に載っている、まだ聴いていない1候補だけが残りました。プロフィールがない場合は従来方式を選び、保存済みのプロフィールがあれば、その候補を返しました。理由を隠した場合にも候補IDは変わりません。利用者の反応がどう変わるかは、この計算では分かりません。

## 論文との違い

教材は、候補の絞り込み方と理由の表示を分ける小さな例です。画面を開いたときに従来方式を選ぶことは示しますが、従来の推薦モデルも言語モデルも動かしません。実際の反応や配信速度は再現していません。

`method.md` は論文の処理を説明し、`mapping.md` には引用元と、どこまで教材で扱ったかを書いています。 `lab.yaml` は記事と図、`run.py` は計算、`results.json` は結果です。
