# Constrained Deep Inventory Management Using Forward-Backward SDEs

## 何を調べたか

倉庫の空きが足りていても、輸送中の商品が届けば容量を超えることがあります。この研究は、発注から到着までの時間差を取り入れ、在庫の推移ごとに容量と排出枠を守る発注を考えます。平均だけを制約するのではなく、需要などの変動がどのように起きたかに応じて、上限を超えない条件を設けます。

ただし、著者が50商品で行った人工実験では、充足率は0.562 ± 0.031、手元在庫の容量違反率は0.815でした。上限を守れるという理論の前提と、数値実装で実際に起きたことを分けて読みます。著者はKeunwoo LimとAmazon所属のMichael Bloemです。Amazonの実店舗で評価したわけではありません。

## どんな在庫を、何の上限で管理するか

商品ごとに、手元在庫をX、輸送中在庫をL、これから決める発注率をuとします。入荷率は b_in=min(L⁺/τ_in,g)、販売率は b_out=min(X⁺/τ_out,d) です。手元在庫は入荷で増えて販売で減り、輸送中在庫は発注で増えて入荷で減ります。これに確率的な変動を加えた式が、dX=(b_in−b_out)dt+σ_X dW_X、dL=(u−b_in)dt+σ_L dW_L です（式1–2）。τ_inは指数的に入荷するときの平均時間で、発注した商品が一律に何日後に届くという設定ではありません。

商品を重み付きで合計し、手元と輸送中のそれぞれに容量Hˣ,Hᴸと排出枠Hᴱˣ,Hᴱᴸを置きます。上限は切替時点でだけ変わります。SCOPEやOR-Transformerの期待値制約と比べると、「平均で守るか、実現した在庫の推移ごとに守るか」という違いに注目できます。これはLabの読み方で、両手法との直接比較はしていません。

## 著者の方法とLabの読み方

**著者の主張**：在庫費用を最小にするためのHJB方程式を、前進後退確率微分方程式（FBSDE）に置き換えます。ニューラルネットは価値と、在庫の変化に対して価値がどれだけ変わるかを表す勾配を学びます。発注時は、4つの集計制約と商品別の制約を含む二次計画（QP）を解きます。発注の影響が現れるまでの微分の回数は、輸送中在庫で1回、手元在庫で2回です。

**Labの解釈**：学習した費用の勾配と、到着の遅れを考慮した上限とを、同じ発注計算に入れる点が参考になります。現場で使えるかは、初期在庫や上限変更時に定理の条件を満たすか、実装がどの制約を緩めるか、実際にどれだけ違反したかを見て判断します。

## 到着までの遅れを発注計算に入れる

発注率uは、まず輸送中在庫Lを増やし、その一部が入荷して手元在庫Xになります（u→L→X）。輸送中の空きhᴸ=Hᴸ−wᴸ·Lを1回微分すると、発注率uが現れます。一方、手元の空きhˣ=Hˣ−wˣ·Xを1回微分して現れるのは入荷と販売です。uが出るのは2回目です。この微分の回数を相対次数と呼びます。

高次のバリア条件では、h₁=∇h·f+γh と置きます。hは今の空き、h₁は空きの変化を織り込んだ指標です。必要な条件は2つです。式11–16では、開始時点でh≥0とh₁≥0をともに満たします。上限が変わるときも、新しい上限でこの拡張安全集合の条件を満たす必要があります（定理5）。

実装では、式20の二次計画を解いて発注率を選びます。目的関数は min ½uᵀR_cu+q_linᵀu+ρ(1ᵀs_a+1ᵀs_u)。制約は u≥u_lower、u≤u_upper+s_u、W_agg u≤r_agg+s_a です。s_a,s_u≥0 は集計予算と発注上限をそれぞれどれだけ緩めるかを表します。緩めるほど目的関数の罰則が増えますが、在庫を負にしないための発注下限は緩めないので、集計予算を超えることはあり得ます。

## なぜ今の空きだけでは足りないか

【Labの解釈】現在の在庫だけでなく、入荷と販売の差にも目を向けると、容量超過の兆候を早く捉えられます。棚に空きがあっても、到着を待つ商品が多ければ空きは減っていきます。手元在庫に対する相対次数2の条件は、今の空きと在庫が増える速さの両方を見ます。

ただし、定理は時間が連続する設定のものです。著者の実装は、Euler–Maruyama法で時間を週単位に区切り、流量の式を滑らかにし、一部の制約違反を罰則付きで認めます。こうした実装でも上限を守れたかは、報告された違反率や超過量を見て判断します。

## Labで手元容量を変える

Labでは、学習や雑音を省き、1商品だけを扱います。入荷率は b_in=L/τ、販売率は一定のdです。手元在庫X=7、輸送中在庫L=4、τ=2、d=1、γ=0.5、輸送中容量6を固定し、手元容量だけを動かします。確認するのは、この設定で発注率の上限がどう変わるかです。

輸送中在庫から決まる上限は u≤L/τ+γ(Hᴸ−L) です。手元在庫から決まる上限は u≤L/τ−γL+γτd+γτh₁ で、h₁=d−L/τ+γ(Hˣ−X) です。二次係数を1とし、両方の上限を守る非負の発注率の中から、調整前の発注率4に最も近い値を選びます。この選び方を区間への射影と呼びます。共通する区間がなければ実行不能です。

例えば手元容量が10から8に下がっても、手元在庫7と輸送中在庫4はその瞬間には変わりません。空きhは3から1に減り、入荷2と販売1の差まで見込むh₁は0.5から−0.5になります。今の発注を止めても、すでに輸送中の商品は届くためです。

## 容量10・8・6で何が変わったか

手元容量が10なら、輸送中在庫から決まる発注率の上限は3、手元在庫から決まる上限は1.5です。厳しい方に合わせると、発注率は4から1.5に下がります。容量8では在庫7が収まっていても、h₁=−0.5なので、定理の初期条件を満たしません。容量を即座に6に下げると、両上限を守る非負の発注率はありません。

著者実験の違反率0.815は頻度、M1=0.050は平均超過量です。超過の頻度が高く、平均超過量は小さい結果と読めますが、個々の在庫推移でどの程度超えたかまでは分かりません。図では著者の指標と、Labの1商品での計算を分けて表示します。

## Labで確かめたこと

**PARTIAL — メカニズム**：発注率を変えた影響が、輸送中在庫では1回目、手元在庫では2回目の微分に現れることを計算しました。手元容量10では発注率が手元側の上限に一致し、容量8では定理の初期条件を満たさず、容量6では発注率を選べないことを、コード内の検査で確かめました。

**CONFIRMED — 数値転記**：表II・IIIの充足率、違反率、M1、M3を区別して転記しました。この確認は、論文の実験を再現したという意味ではありません。

## Labで確かめていないこと

**NOT TESTED**：deep FBSDEの学習、確率的な安全性を示す定理、50・100商品での性能、現場への適用は検証していません。雑音を入れない小さな計算から、ブラウン運動による雑音があるときに上限を守れるかは分かりません。特に、上限が急に下がった場合に、全制約を満たす発注が存在することは保証していない点に注意してください。
