# Constrained Deep Inventory Management Using Forward-Backward SDEs

## 概要

複数の商品を補充するとき、倉庫にある在庫と輸送中の在庫には、それぞれ容量や排出量に基づく上限があります。著者は、需要が変わってもこの上限を守りながら、保管や欠品の費用を抑える発注方法を調べました。モデルは発注が将来の費用にどう影響するかを学び、発注のたびに上限を考慮した最適化で数量を決めます。

50商品のシミュレーションでは、輸送中の在庫が容量を超えたのは、需要のシナリオと週の組み合わせのうち0.001%未満でした。一方、倉庫にある在庫は同じ集計で81.5%が容量を超えました。この方法は両方の上限を同じように守れたわけではなく、店舗や倉庫で実地に確かめた結果でもありません。

## 問題設定

商品ごとに手元在庫をX、輸送中在庫をL、発注率をuとします。手元には入荷で在庫が増え、販売で減ります。輸送中の在庫は発注で増え、入荷で減ります。欠品で販売できない需要は、翌期に届ける注文としては残しません。

原論文の入荷率は b_in=min(L⁺/τ_in,g)、販売率は b_out=min(X⁺/τ_out,d) です。式(1)・(2)は、この流れに雑音を加えた dX=(b_in−b_out)dt+σ_X dW_X、dL=(u−b_in)dt+σ_L dW_L です。τ_in は指数的に入荷するモデルの平均時間で、すべての注文が固定の日数で届くわけではありません。

著者は商品別の在庫を重み付きで合計し、手元と輸送中のそれぞれに容量 Hˣ、Hᴸ と排出枠 Hᴱˣ、Hᴱᴸ を設けます。各上限は定めた時点で切り替わります。この研究は、平均で制約を守る設定と異なり、実現した在庫の経路ごとに制約を守ることを目指します。SCOPEやOR-Transformerと同じ条件で比較したわけではありません。

## 発注を決める仕組み

著者は、初期の価値と在庫が変わったときの価値の勾配をニューラルネットワークで学びます。発注時は輸送中の在庫の価値と発注費用を使い、4つの集計枠と商品別の制約を考慮する二次計画で発注率を選びます。

到着待ちの商品を考えに入れると、今ある空きだけを見て発注する場合とは判断が変わります。連続時間の定理、上限を一部緩める数値実装、実験で測った違反率は分けて読む必要があります。

## 到着に遅れがあるときの発注計算

## 輸送中の在庫と倉庫の在庫

発注率を上げると、まず輸送中の在庫 L が増えます。倉庫の手元在庫 X に影響するのは、その一部が入荷してからです。原論文は、入荷率を輸送中の在庫に比例させ、入荷設備などの上限で頭打ちにします。時定数 τ_in は指数的に入荷するモデルの平均時間で、ある日に注文した商品が一律に同じ日数で届くという意味ではありません。手元の在庫が足りず販売できない需要は失われ、翌期の注文として持ち越しません。

輸送中の空き hᴸ=Hᴸ−wᴸ·L を時間で1回微分すると発注率 u が出ます。手元の空き hˣ=Hˣ−wˣ·X を1回微分すると入荷と販売が出ますが、発注率はまだ出ません。手元の空きの式をもう1回微分すると、輸送中の在庫を通じて発注率が出ます。発注率が式に現れるまでの微分回数を相対次数と呼びます。

### 今の空きと、空きが減る速さ

手元在庫のバリア条件には、現在の空き h と、その変化を加えた h₁=∇h·f+γh を使います。h が正でも、入荷が販売を上回って空きが急速に減れば、h₁ は負になる場合があります。連続時間の定理は、最初に必要な条件を満たし、制御が必要なバリア不等式を守り続ける場合の保証です。上限が切り替わったときも、実際の状態が新しい上限での h と h₁ の条件を満たす必要があります。予算の大きさが論文の設計条件を満たしても、各需要経路の切り替え時に条件を満たしたことの証明ではありません。

### 発注率を選ぶ二次計画

著者は前進後退確率微分方程式（FBSDE）を使い、初期の価値と、在庫が変わったときに将来費用がどう変わるかを学びます。発注時の二次計画では、輸送中在庫を増やしたときの将来費用の変化と、その発注の単価を費用に入れます。式(20)では二次の費用も加え、在庫と排出枠の条件を考慮した発注率を求めます。

実装は、4つの集計上限を `s_a` で、商品ごとの発注上限を `s_u` で緩め、どちらにも罰則をかけます。一方、在庫を負にしないために設けた商品ごとの発注下限には緩和を認めず、上限と衝突したときは下限を優先します。下限を計算する際は、分母の β が0に近づかないように下限値を設けます。流量の平滑化や週単位のEuler–Maruyama離散化も使うため、二次計画に解があることは、元の上限を連続時間で守ったことと同じではありません。

Labは1商品の線形な例だけを計算し、上限を緩めません。手元容量8では、その時点の二次計画で発注率0.5を選べますが、h₁=−0.5なので定理の開始条件は満たしません。これだけで、この後に必ず容量を超えると分かるわけではありません。

## 今の空きだけでは足りない理由

手元に空きがあっても、すでに輸送中の商品が販売より速く入荷すれば、空きは減ります。手元在庫のバリア条件は、今の空きと、空きが減る速さを両方見ます。ただし、これらの条件を満たさないことから、実際に容量を超えると直ちに結論づけることはできません。

連続時間の定理は、初期状態と上限が切り替わった後の状態が条件を満たし、制御が必要な不等式を守り続ける場合の保証です。著者の実装は週単位で計算し、流量の式を平滑化します。さらに、集計上限と商品ごとの発注上限には罰則つきで超過を許し、発注下限は緩めません。実装に解があることと元の上限を守ったことは異なります。報告値だけでは、どの変更がどれだけ違反に影響したかは分かりません。

## 論文の実験結果

一次資料は[原論文v1の§III〜V、図1〜3、表I〜IV](https://arxiv.org/html/2609.11817v1)です。著者は50商品について、年に1回の季節変動を持つGamma分布の需要を作りました。2年を8季節・104週に分け、乱数の初期値を変えた8回の学習を、各512本の需要経路で評価しました。

| 著者が報告した指標 | 50商品での値 | 何を数えたか |
| --- | --- | --- |
| 充足率 | 0.562 ± 0.031 | 需要数量のうち実際に満たした数量の割合。±は乱数の初期値を変えたときの標準偏差 |
| 手元容量の違反率 | 0.815 | 需要経路と週の組のうち、手元容量を10⁻⁶より多く超えた割合 |
| 手元容量のM1 | 0.050 | 超過した量を容量で割り、超過しなかった組の0も含めて平均した値 |
| 手元容量のM3 | 0.083 | 手元容量を10%より多く超えた需要経路と週の組の割合 |
| 手元容量の平均利用率 | 1.02 | 容量に対する手元在庫の比の平均 |
| 手元排出枠の違反率 | 0.077 | 同じ需要経路と週の集計で、手元の排出枠を超えた割合 |

手元容量の違反率0.815は、少なくとも一度違反した需要経路や、超過した商品の割合ではありません。輸送中容量の違反率は10⁻⁵未満、輸送中の排出枠は10⁻⁴未満でした。表IIの0.000は厳密なゼロではありません。

図3では、一部の計算で4つの集計上限を10⁴に引き上げてから、すべての方式を元の上限で評価しました。集計上限を考慮した方式で手元容量のM1は0.050、引き上げた方式では8.69でした。単位は容量で割った超過量で、費用ではありません。

表IVは4種類の乱数の初期値を使った別の比較です。商品数を50から100へ増やすと同時に、ネットワークの幅を256から512に広げました。充足率は0.561から0.601に上がる一方、手元容量の違反率は0.815から0.875、手元の排出枠の違反率は0.078から0.150に上がりました。規模を広げても、すべての指標が改善したわけではありません。

## 図で確かめること

Labの図では、雑音や学習を除き、1商品だけを扱います。手元在庫X=7、輸送中在庫L=4、時定数τ=2、販売率d=1、γ=0.5、輸送中容量6を固定します。入荷率はL/τです。手元容量を変えて、その時点で選べる発注率の上限を比べます。

輸送中の条件から決まる上限は u≤L/τ+γ(Hᴸ−L)、手元の条件から決まる上限は u≤L/τ−γL+γτd+γτh₁ です。h₁=d−L/τ+γ(Hˣ−X) とします。Labは、二次係数を1として、両方の上限を守る非負の発注率のうち、調整前の4に最も近い値を選びます。共通する区間がなければ実行不能です。原論文のような、罰則を払って上限を緩める仕組みはありません。

手元容量を10から8へ下げても、その瞬間の手元在庫と輸送中在庫は変わりません。今の空きhは3から1に減り、入荷2と販売1の差も含めたh₁は0.5から−0.5になります。発注を止めても、輸送中の商品は引き続き入荷します。

## Labの人工例

手元容量6では、両方の上限を守る非負の発注率はありません。容量8では、計算上は発注率0.5を選べますが、h₁=−0.5なので定理の初期条件には入りません。条件に入らないことは、実際にその後の在庫が容量を超えると確定したことではありません。

容量10では、輸送中の制約からの上限は3、手元の制約からの上限は1.5なので、発注率は4から1.5に下がります。容量14では、輸送中の上限3の方が厳しく、発注率は3になります。図は一時点の計算であり、著者の50商品実験の充足率や違反率は別に表示します。

## 確認したこと

CONFIRMED（限定した計算）：Labは、発注率の変化が輸送中在庫では1回目、手元在庫では2回目の微分に現れることを計算しました。手元容量によって、発注率を選べない場合、発注率は選べても初期条件を満たさない場合、両方を満たす場合を区別しました。

PARTIAL（一部確認）：Labは1商品の線形計算と、原論文の表からの指標の転記までを行いました。確率的な過程や学習を再現したわけではありません。

## 確認していないこと

NOT TESTED（未検証）：Labは深層FBSDEの学習、確率的な経路での安全性の定理、50・100商品での性能、現場導入を検証していません。雑音のない一時点の例では、各時点で上限を守れるかは分かりません。特に、上限が急に下がった後に全制約を満たす発注が存在することは保証していない点に注意が必要です。
