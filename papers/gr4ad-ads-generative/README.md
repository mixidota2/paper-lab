# Generative Recommendation for Large-Scale Advertising

Kuaishouの著者は広告候補を生成して収益を増やすことと、配信に必要な処理件数を保つことを同時に扱いました。GR4ADは広告を意味IDで表し、利用者の反応と広告価値に沿って候補の出し方を学びます。配信時はIDの各記号について、前の記号に依存しない計算を先に済ませ、残りは順に計算します。負荷に応じて、生成の途中で残す候補の数も変えます。

著者が報告した最終構成では、広告収益が従来方式のDLRMより4.28%増え、1秒当たりの処理件数は生成型のOneRec-V2より117%増えました。DLRMとはGPUや運用の条件が異なるため、著者は処理件数には別の比較相手を使いました。二つの差はどちらも、複数の変更を組み合わせた構成で測ったものです。また著者は、4億人超の利用者を抱えるKuaishouの広告システムに導入したと報告しています。

## 読み方と実行

本文は `lab.yaml` と `method.md`、論文とLabの対応は `mapping.md` にある。下のコマンドを実行すると、Pythonの標準ライブラリだけで人工広告を作成し、`run.py` と同じ場所に `results.json` を保存する。

```sh
uv run papers/gr4ad-ads-generative/run.py
```

このコードは、IDの最後の段をハッシュに置き換えた場合の衝突を比べる。学習済みモデルや広告配信のデータは使わず、論文の収益や処理件数は再現しない。
