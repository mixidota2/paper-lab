# セール価格の予測と実現利益を分けて読む

## Overview

Zalandoのセール価格を、日次LightGBMの需要予測と商品別の割引選択で決める研究。著者は2023〜2024年の12市場・23件の無作為化A/Bテストを統合し、利益貢献PCIIが+6.00%（95%区間0.79〜11.03%）と報告した。純売上NMVと返品後販売数SIARの区間は0をまたぐ。売上の同等性が証明された、とまでは読めない。

Must Readとする理由は、複雑なモデルの新規性より実地の価格決定で得た証拠にある。Table 2では評価指標でモデル順位が反転し、Table 3では予測利益と実現利益が離れる。モデル、損失、意思決定を一続きで点検したい。

## Problem

通常期の週次Transformerと手動補正では、平均6.2日続くセールの変動に追いつきにくい。セールは年間の約35%を占める。割引を増やせば販売数は増えても、今売らずに残す商品の将来利益を失う。

商品ごとに決める。顧客ごとに異なる価格を付ける実験ではない。売れた数量には在庫の上限があり、返品率とVATを引いた金額を収益として扱う。

## Core Idea

著者の主張：市場・予測日ごとのLightGBMで割引×日の需要表を作り、在庫で切り詰める。長期利益LTPと純売上NMVの加重和を最大にする割引を商品別に選ぶ。割引に対する予測の単調増加を制約する。

本Labの解釈：予測と最適化を分けた設計はFerreiraら（2016、Rue La La）やCaro–Gallien（2012、Zara）の延長にある。本論文の価値は、日次運用への縮約と実地検証、評価指標の選び方を同じ事例で追える点。既存のZalando最適化（Liら2022、Streeckら2024）との違いは、商品間の結合制約を外して短時間で候補を提示することにある。

## Method

日別需要を合計し、在庫Mで販売数を切る。利益は次の順に計算する。

| 式 | 計算 | 意味 |
|---|---|---|
| (3) | s(d)=min(M, Σₜ Sᵗ(d)) | 在庫を超えて売らない |
| (4) | NMV(d)=(1−R)(1−d)Ps(d)/(1+VAT) | 返品率Rと税を除く |
| (5) | p(d)=NMV(d)−Cs(d) | 費用を引く |
| (7) | LTP(d)=p(d)+[M−s(d)(1−R)]γ | 残在庫の将来利益を足す |

γは既存の週次システムから得る、残る在庫1単位の将来利益である。

式(1)は各商品で argmax_d[LTP(d)+α NMV(d)]。候補を採点して並べればよく、商品間の交差価格効果は入らない。式(2)の −NMV′(d)/LTP′(d)=1/α は連続で微分可能な場合の限界条件。対話図は離散候補なので階段状に変わる。α=0で同点がある場合は、NMVで同点を解消しなければ強いPareto効率性までは保証されない。

## Why It Might Work

著者はLightGBMを精度、訓練時間、安定性から選んだ。Table 2の訓練時間はGBTが7時間、TSMixerが18時間、MLPが24時間。割引の単調性は不自然な需要曲線を抑え、商品別の独立採点は最適化を数時間から数分へ短縮する。

解釈：αを振って複数の候補を提示することで、担当者は収益と残在庫の価値を比較できる。ただし一定のγは将来の値付け方針を更新しない。予測誤差は残る。

本Labで残す注意点は交絡だ。過去の担当者が売れにくい商品ほど深く割り引いていたなら、割引と販売数だけを学ぶモデルでは、その商品が元から売れにくかった影響と値下げによる販売増を分けにくい。観測価格での誤差が小さくても、未実施の割引に対する需要予測が正しいとは限らない。

## Evidence

以下は一次資料である[原論文v1](https://arxiv.org/pdf/2606.13741v1)の著者報告。Table 4は11波、合計6,204,627 articlesを記載する。商品単位のクラスタ無作為化で事前利益・NMVを均衡させ、各試験を差の差で分析し、Bayesian階層モデルで統合した。同一商品が複数波に含まれる可能性があるため、620万をユニークSKU数とは置かない。

Table 5のPCIIは+6.00% [0.79, 11.03]、NMVは+2.23% [−0.83, 5.33]、SIARは+0.56% [−3.10, 4.26]。ドイツ単独ではSIAR +16.7%、NMV +17.9%、PCII +16.7%。全市場への外挿は避ける。代替商品間の干渉は無作為化だけでは消えず、SUTVAの懸念が残る。対照は人と既存アルゴリズムの混合運用である。

Table 2は212日分の評価。GBTは業務指標のDemand ErrorとGMV Errorで最良だが、均等に重みを置くRMSE・MAPEではMLPが最良。Table 3はシミュレーション限定で、MSEのPCIIはoracle比で予測115.02%→実現93.07%、Tweedieは94.21%→91.57%。Tweedieは予測との乖離が小さいが、実現PCIIはMSEより低い。


調整予算も揃っていない。著者は、LightGBMは速く安定して訓練できたためニューラルネットワークより広くハイパーパラメータを探索できたと説明しており、Table 2の差にはモデル構造だけでなく、実際に試せた設定の範囲も含まれる（§3）。


Demand Errorの重みは数量だけではない。式(9)では、市場・日ごとに対象商品をまとめ、値引き前の価格を重みにした数量の二乗誤差の合計を、同じ価格で重み付けした実績数量の二乗和で割って平方根を取るため、少量・低価格の商品を多く改善するモデルと、大きな売上を占める商品の誤差を減らすモデルで順位が変わりうる。

## Executable Understanding

対話図のαを上げると、3つの架空商品で選ぶ割引と在庫制約を見直せる。点はFig. 4の考え方を式(1)、(3)〜(7)で再計算した教材で、Zalandoの商品ではない。全離散解のPareto境界を列挙する図ではなく、加重和で選ばれた候補を示す。

最小実験では、400商品×56日の定弾力性需要から、需要水準・弾力性・曜日効果・割引を共通特徴とするLightGBMをMSEとTweedieでそれぞれ学習し、選んだ割引の利益をノイズなしの期待需要グリッドで評価する。seedは11、22、33。弾力性を特徴として渡す有利な教材条件なので、実データでの因果的価格効果推定は検証しない。

## Results

下図の最小実験では、予測した利益と、同じ割引を真の期待需要で評価した利益を分ける。基準は同じγで割引を選ぶoracleの短期利益。これはZalandoのPCII会計定義を完全に実装した値ではない。oracleは長期利益を最適化するため、比較する短期利益では100%を超える場合がある。

3 seedの数値はresults.jsonから表示する。論文Table 3の115.02%などを再現するように調整していない。損失の優劣と約束の正確さは別の問いであり、この小実験だけでTweedieの普遍的な優位は主張しない。

売上計画の承認に使うなら、実現利益の高さだけで採用は決めにくい。次の3点も確かめたい。

- 割引を選んだ時点の予測から、利益がどれだけ下振れしたか。
- 在庫に余裕がある商品と、上限に当たる商品で誤差が違うか。
- αを変えても同じ傾向が残るか。

## What We Verified

CONFIRMED：3 seedで割引に対する予測の単調性、販売数の在庫上限、αを上げたときの選択NMVの非減少をassertで確認した。式(3)〜(7)を通した利益計算と、予測・実現の分離を実行した。

PARTIAL：価格決定の機構を縮約している。市場別・予測日別モデル、γの週次モデルからの推定、過去の価格決定による交絡は含めない。

## What We Did NOT Verify

NOT TESTED：23件の実地試験、6%の利益改善、数百万商品の処理時間、本番の価格因果効果。非公開データや公式本番コードを実行していない。返品率や費用は定数、需要不確実性や交差価格効果、将来の在庫補充も省略した。

## Implementation

リポジトリ直下で実行する。

```bash
UV_CACHE_DIR=/tmp/uv-zalando uv run --no-project papers/zalando-sales-event-pricing-forecast-optimize/run.py
```

依存はLightGBM 4.6.0とNumPy 2.2.6。run.pyがresults.jsonを生成する。lab.yamlとREADME.mdが解説、mapping.mdが一次資料との対応を持ち、HTMLは生成物とする。次の検証では、価格を観測的に選ぶデータとランダムに割り付けるデータを比較し、最適化後の利益差が交絡にどれほど敏感かを調べたい。
