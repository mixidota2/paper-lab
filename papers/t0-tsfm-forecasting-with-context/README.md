# t0: A Time-Series Foundation Model for Forecasting with Context

同じ予測モデルに、予測時点で決まっている予定を渡すと精度は上がるか

Meyerらは、同じt0-alphaで、予測時点までに分かっている補助変数を渡す場合と、渡さない場合を比べました。将来分が既知の30課題ではskillが6.3ポイント高くなりましたが、11課題では悪化しました。

## 論文の概要

Meyerらは、販売数などの履歴に、予測時点で分かっている予定を加えて予測する時系列モデルt0を開発しました。モデルは、時系列を短い区間に区切ります。一つの変数が時間とともにどう動くかと、同じ区間で変数どうしがどう関係するかを交互に読み取り、予測分布の分位点を出します。

著者らは、学習済みのt0-alphaを変えずに、将来分が事前に分かる変数を渡す場合と渡さない場合を、公開の評価集fev-benchの30課題で比べました。季節ごとの過去の値を繰り返す基準予測と比べた指標skillは36.7%から43.0%に上がりました。差は6.3ポイントで、19課題で改善し、11課題で悪化しました。Rossmannの日次売上では、販促予定などを渡すと分位点損失が43%減りました。一方、M5の週次と月次では変化が2%未満でした。これは入力の有無を比べた結果で、発注や欠品への効果や、GBDTに対する優位性を示す比較ではありません。

## 発注時点に分かる情報を分ける

売上の履歴だけを受け取るモデルには、来週の販促日や休業日を直接伝えられません。一方で、対象と関係のない情報を入れると、予測がかえって外れることがあります。発注時点で分かる販促計画や天気予報と、実際に売れた数やその日の天気を分けます。実績を予定や予報の代わりに渡すと、当時は知り得ない情報を使ってしまいます。

## 事前学習で変数どうしの関係を読む

著者らは、補助変数が変わると、予測対象の値も変わる人工データを作りました。モデルは事前学習でこうした組み合わせを読み、売上の履歴と販促の予定のような、異なる変数どうしの関係を使います。ただし、追加情報を渡せることと、追加情報が役に立つことは別です。同じモデルでも、将来分が分かる変数を渡した30課題のうち11課題で成績が悪化しました。

著者らは、補助変数の変化が予測対象へ伝わる人工系列を事前学習に加えました。モデルは時系列を区間に分け、一つの変数の前後と、同じ区間にある別の変数を交互に読みます。

[ApolloPFN](apollopfn.html)やChronos-2と同じく、t0は売上履歴以外の情報も使えます。ただし、[Accuracy Is Not Service](accuracy-not-service-intermittent-demand.html)が扱うように、誤差が減っても欠品や在庫費用が減るとは限りません。小売で比べるなら、発注時点までに分かっていた情報をt0と勾配ブースティング決定木（GBDT）にそろえ、販促中と欠品中を分けます。

## t0が情報と分位点を扱う方法

### モデルは、時間方向と変数方向を交互に読む

t0-alphaは、入力を32時点ずつのまとまり（パッチ）に分け、各パッチを512次元のベクトルで表します。同じ変数の別の時点を読む層を2つ重ねた後、同じパッチ位置にある別の変数を読む層を1つ置きます。この組を繰り返し、計24層のうち16層が時間方向、8層が変数方向です。注意は8ヘッドで、各ブロックにはRMSNorm、SwiGLU、クエリとキーを正規化するQK normを使います。

### 著者らは、将来の予定と後から分かる実績を分けた

予測対象をy、過去の補助変数をx、将来分も予測時点で分かる補助変数をzとします。時間方向を読むとき、yとxは自分の時点までしか参照しません。zの例は、すでに決まった販促日や営業日です。zは予測期間分を含めて参照できます。

変数方向ではyとxがzを読みます。zはyとxを読みません。もしzが後の時点の売上実績を読めると、その実績がzの時間方向の処理で前の時点に伝わり、売上の予測に入るためです。論文は、この経路を防ぐ設計を示しています。実際の公開コードの確認範囲とは区別します。[一次資料：PDF v1の第4.1節・図3](https://arxiv.org/pdf/2609.24559v1)。

### 予測を出す時点で、標準化の基準を固定する

モデルはyとxを、それまでの平均と標準偏差で標準化し、逆双曲線正弦（arcsinh）で変換します。学習で将来の正解を変換するときも、平均と標準偏差には将来の実績を加えません。予測時点Tで基準を固定し、予測を元の尺度に戻すときにも同じ基準を使います。将来分が既知のzだけは、予測期間を含む全体の平均と標準偏差を使えます。

著者らは、観測していない値を統計量と学習の損失から外します。商品説明の文章や、時間が経っても変わらない商品の属性を、モデルに直接渡す仕組みは報告の対象外です。[一次資料：PDF v1の第4.1節・式2・第6節](https://arxiv.org/pdf/2609.24559v1)。

### 分位点は時点ごとに出す

t0-alphaは、次のパッチの各時点について、0.1、0.25、0.5、0.75、0.9の分位点を直接予測します。最小の分位点を出した後、softplusで正にした差を順に足すため、高い分位点が低い分位点を下回りません。学習では、各分位点の予測のずれを測るピンボール損失に、順に0.175、0.2、0.25、0.2、0.175の重みを付けます。別モデルのt0-betaは0.01〜0.99の21分位点を直接出します。

論文v1のt0-alphaは、直接出す分位点の範囲外を指定したとき、通常は端の値を使います。著者らは範囲外を予測する方法（IQFによる外挿）も別に評価しました。既存のコード確認時に公式READMEが案内していた外挿と、論文v1の通常の推論は同じ扱いにしません。[一次資料：PDF v1の第4.1・4.3・5.2節](https://arxiv.org/pdf/2609.24559v1)。

分位点は時点ごとの結果です。時間・商品をまたいで需要がどう同時に変動するかは示しません。各日の分位点を足しても、次に入荷するまでの需要合計の分位点にはなりません。発注で使うなら、予測時点で分かっていた予定をそろえ、欠品で売れなかった量をどう扱うかを決め、在庫の費用を別に確かめます。

## 著者らが測った予測の成績

#### 追加情報の有無を、同じモデルと同じ課題で比較した

著者らは、公開の評価集fev-benchの各課題で、同じ重みのt0-alphaを2回動かしました。一方は予測対象の履歴だけ、もう一方は予測対象とは別の補助変数も入力します。[一次資料：PDF v1の第5.1.2節・表5](https://arxiv.org/pdf/2609.24559v1)。

| 課題 | 補助変数なしのskill | 補助変数ありのskill | 差と95%信頼区間 | 改善した課題 |
| --- | --- | --- | --- | --- |
| 将来分まで分かる30課題 | 36.7 | 43.0 | +6.3ポイント（+2.2〜+10.9） | 19/30 |
| 過去分だけが分かる12課題 | 32.9 | 35.6 | +2.7ポイント（+1.0〜+4.2） | 9/12 |
| 補助変数がない58課題 | 入力は同じ | 入力は同じ | 著者らが出力の完全一致を確認 | — |

skillは、季節の過去値を繰り返す基準予測（季節ナイーブ）に対して、分位点の予測がどれだけ良いかを表します。著者らは、課題ごとにt0の分位点損失を基準予測の損失で割り、その比を0.01〜100に収めてから幾何平均します。1からその平均を引き、百分率で表します。0は基準と同じで、高いほど良い値です。6.3ポイントはこの指標の差で、平均絶対誤差（MAE）が6.3%減ったという意味ではありません。95%信頼区間は、課題を重複ありで抽出し直すブートストラップで求めています。店舗ごとの改善幅を予測する区間ではありません。

#### 日次のRossmannでは改善した一方、M5の週次・月次では差が小さかった

ドイツの翌日電力価格では、需要や再生可能エネルギーの発電量の予報を加えると、分位点損失は51%低くなりました。Rossmannの日次売上では、販促、祝日、営業日の情報を加えると43%低くなりました。M5では価格やカレンダーなど8変数を入力しても、週次・月次での分位点損失の変化は、良化も悪化も2%未満でした。販売数で評価した比較で、欠品や発注費用への影響は測っていません。[一次資料：PDF v1の第5.1.2節・図6](https://arxiv.org/pdf/2609.24559v1)。

#### 全100課題のt0-alphaとt0-betaは、別の比較

全100課題でt0-alpha自身の予測を集計したskillは42.9でした。ベンチマークの規則では、事前学習と重なった8課題をChronos-Boltの成績で置き換えるため、報告値は42.2です。一方、著者らはt0-betaの事前学習から、ベンチマークのデータを除いたと報告しています。t0-betaの全100課題でのskillは46.7でした。両モデルはパラメーター数だけでなく事前学習のデータも異なるため、規模だけを変えた比較ではありません。[一次資料：PDF v1の第5.1.2節・表4](https://arxiv.org/pdf/2609.24559v1)。

## Labの3つの計算

Labは、公式モデルを実行せずに3つの計算をします。表5の丸め済みの値からskillの差と損失比の変化を求めます。次に、2時点の人工例で、どの条件だと将来の実績が以前の時点へ伝わるかを調べます。最後に、正の差を足すと分位点の順序が逆転しないことを確かめます。実行するには `uv run papers/t0-tsfm-forecasting-with-context/run.py` を使います。

## 人工例の結果と、論文の値から計算した差

丸め済みの値から計算すると、将来分まで分かる30課題のskillは+6.3ポイント、過去分だけが分かる12課題では+2.7ポイントです。基準予測に対する損失比の幾何平均は、それぞれ約9.95%、約4.02%減ります。Labが個別の課題を集計し直した値ではありません。

2時点の人工例では、補助変数と予測対象がお互いの値を読めると、将来の実績が以前の時点に伝わりました。補助変数が予測対象を読むことを禁止すると、その実績は伝わりませんでした。分位点は、正の差を順に足したため、それぞれが直前の値より大きくなりました。

## Labが確認したこと

Labは、論文の丸め値から求めた差と、人工例での情報の伝わり方、分位点の順序を確かめました。原論文の仕組みの一部を確認した結果です（PARTIAL）。以前に固定コミットのコードを確認した際には、読んだ経路で論文どおりの参照制限を見つけられませんでした。そこで確認した範囲は対応表に記載しました。

## Labが確認していないこと

Labはt0-alphaやt0-betaを実行せず、性能、規模を変えた場合の動作、実店舗での効果は調べていません（NOT TESTED）。Chronos-2、ApolloPFN、GBDTとの同条件の比較も行っていません。欠品時の潜在需要や、発注と在庫の費用への影響は対象外です。時点ごとの分位点を足しても、入荷までの需要合計の分位点にはなりません。

## コードで計算する内容

`skill_audit()` は著者らの報告値から差を求めます。`propagate()` は、どの変数がどの時点の実績を受け取るかを集合で記録します。`ordered_quantiles()` はsoftplusで差を正にして順に足します。計算にはPythonの標準ライブラリだけを使います。モデルの重みを使っていないことは `results.json` にも記載しています。
