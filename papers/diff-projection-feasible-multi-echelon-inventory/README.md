# Hard Constraints, Smooth Gradients: Learning Feasible Inventory Policies via Differentiable Projection

## 概要

複数の製品で設備や資材を分け合うときは、製品ごとの生産量を別々に決めると、全体の上限を超えることがあります。著者は、学習モデルが出した目標を上限内の近い値に移し、整数の生産量に直す方法を提案しました。学習時は整数化を通る勾配を近似し、将来の在庫費用から生産目標の出し方を学びます。

論文の改訂版では、ASMLの研究課題をもとに14品目の生産と在庫をシミュレーションしました。予測に応じて在庫目標を変える最良の比較手法に対し、平均費用は基本設定で0.9%、設備容量が厳しい設定で1.8%低くなりました。これは実際の工場で生産計画を変えた結果ではありません。初版とは評価の条件が違うため、数値を区別して紹介します。

## 問題設定

多段階の生産では、製品ごとの上限を守っても、設備や資材を合計すると使いすぎることがあります。そのため、担当者は複数製品の生産量をまとめて決めます。論文は、満たせなかった最終製品の需要を次期以降に引き渡す注文（バックオーダー）として扱います。その場で売上を失う小売モデルとは異なります。段取り替えにかかる時間や費用は扱いません。実際の食品売場で棚割りを変える無作為試験でもありません。

## 制約と学習の役割

ニューラルネットワークが各製品の連続的な生産目標を出し、二次計画が制約を守る最も近い点を選びます。著者はそこから整数を選び、学習では連続値の厳密な局所勾配と、整数化の近似勾配を使ってモデルを更新します。

この論文は、毎期の整数の生産量で共有資材や設備の上限を守ります。DeepStockは在庫の関係式を強化学習に組み込み、Constrained FBSDEは在庫などの状態の推移を制約します。異なる判断を扱う研究で、同じ条件で性能を比べた結果ではありません。

## 生産目標を制約内の整数に直す手順

## 連続値の目標を制約内に移す

ニューラルネットワークが各製品の生産目標 `z` を連続値で出します。目標が共有設備や資材の上限を超えた場合、著者の方法は制約を守る連続値のうち、重み付きの距離で最も近い点 `x*` を選びます。この操作を射影と呼びます。式(2)は、`Mx≤r` の下で `½(x−z)ᵀW(x−z)` を最小にする強凸二次計画（QP）です。重み行列 `W` が正定値なら、実行可能な集合が空でないときに解は一つに決まります。

原論文の資材や設備の使用係数は非負なので、どの製品の生産量を減らしても、資材や設備を余計に消費しません。非負の生産量を減らしても制約を守れる性質を下方閉と呼びます。この性質があるため、各生産量の小数点以下を切り捨てても、上限は超えません。生産量に正の下限を課す場合や、製品間の量を等式で結ぶ場合には、切り捨てただけで制約を守れるとは限りません。

### 切り捨てた量から1個ずつ増やす

整数化は、連続解を切り捨てた `xᶠ=⌊x*⌋` から始めます。製品 `i` の優先度は `σᵢ=f(xᶠ;z)−f(xᶠ+eᵢ;z)−[Mᵀλ*]ᵢ` です。`eᵢ` は製品 `i` だけ1個増やすベクトルで、`λ*` は制約の厳しさを表す双対価格です。最適条件を使うと、優先度は重み `wᵢ` と連続解の端数から `wᵢ(xᵢ*−floor(xᵢ*)−0.5)` とも書けます。優先度の順に各製品を1回ずつ調べ、制約を守り、元の目的関数も悪化しない場合だけ1個を足します。

この手順は一般の整数最適解を保証しません。たとえば、非負の2製品で資材の上限が `2x₁+x₂≤3`、重みが同じ、目標が(0.9,1.8)なら、連続解は(0.66,1.68)です。切り捨てると(0,1)で、端数が大きい製品2に先に1個を足します。その後に製品1を足すと上限を超えるので、結果は(0,2)です。しかし、Labと同じ重み行列で比べた目的値は(0,2)で17/80、真の整数最適解(1,1)で13/80です。この追加の例は、用意した2製品の実験データとは別です。

原論文でいう完全性は、各実行可能な整数の生産量に写る目標の集合が、論文の条件の下で正の大きさを持つことです。学習したモデルが必ずすべての生産量を選ぶという意味ではありません。共有上限が `x₁+x₂≤2` のとき、切り捨てでも目標が(1,1)から特定の方向に伸びる半直線上にあれば、(1,1)を返します。ただし、その集合の面積は0です。Labの格子はこの半直線を避けるため、切り捨ての件数が0になりました。

### 学習で返す勾配

連続解については、等号になっている制約の組が局所的に変わらず、独立な制約を選べる場合に、最適条件からJacobianを求めます。製品1の個別上限だけに達していれば、目標だけを増やしても実際の生産量は増えません。両製品で共有上限に達している例では、目標を少し増やすと製品1に増分の半分が伝わり、製品2は同じ量だけ減ります。

目標 `z` を変えたときの勾配と、制約の右辺 `b` を変えたときの勾配は別です。過去の生産によって残りの資材が変わる場合、右辺を通して、その生産判断にも学習の信号が戻ります。容量が固定なら、その経路で過去の判断まで勾配は伝わりません。

整数化の出力は区間ごとに一定で、切り替わりでは通常の微分を使えません。そこで学習時は、整数化の部分だけで、連続解が動いた分をそのまま逆向きに伝えるSTEを使います。二次計画による射影の勾配までSTEで置き換えるわけではありません。著者は、生産が将来の在庫と未充足注文をどう変えるかをシミュレーターで計算し、その費用からモデルを更新します。Labは学習を実行していません。

## 制約に達したときの勾配

制約に達していない例では、目標を変えた分だけ、整数にする前の生産量も変わります。製品1の個別上限に達した例では、目標を増やしても製品1の量は変わりません。2製品で共有上限に達した例では、製品1を増やすと製品2が同じだけ減ります。

著者は、この連続値の変化を、等号になっている制約の組（活性集合）が近くで変わらない場合に計算します。制約が切り替わる点では、通常の微分が常にあるわけではありません。資材残量によって制約の右辺が変わる場合、右辺を通じて過去の生産判断にも勾配が戻ります。容量が固定なら、この経路では過去の判断まで勾配は伝わりません。整数化だけを恒等写像のように扱う近似とは別の計算です。

## 論文の版ごとの評価結果

一次資料は[改訂版（v2）§6.4、表5](https://arxiv.org/html/2608.02343v2#S6.SS4)と§6.5の表6です。著者は各設定で1,000通りの需要経路を使い、DBSで30期間を動かして得た初期状態と、その後の需要を各手法でそろえました。表5では、最良の比較手法DBSに対し、平均費用は基本設定で278.0から275.4へ0.9%、容量が厳しい設定k−で299.6から294.3へ1.8%下がりました。削減率の対応のある99%信頼区間の半幅はそれぞれ0.3、0.6ポイントです。

表5の4設定とは別に、本文には、さらに容量が厳しいk−−でDBSより3.1%低くなったという比較があります（対応のある99%信頼区間の半幅は0.6ポイント）。これは表5の主要4設定の数字ではありません。

改訂版の表6では、提案した整数化を切り捨てに替えると、全機能を使う方式に比べて基本設定で11.9±2.0%、k−で35.9±6.9%費用が増えました。±の幅は対応のある99%信頼区間の半幅です。整数化の近似勾配（STE）だけを学習から外し、評価時には同じ整数化を使った場合、平均費用の差は最大0.6%で、区間は0に届きました。連続値を選ぶ射影の勾配までSTEに置き換えた試行では学習が発散しましたが、他の設定でも学習できないと示したわけではありません。

## 図で確かめること

Labでは2製品の目標をz、生産量をxとします。生産量が非負、製品1は3以下、2製品の合計は6以下という制約の中で、目標に最も近い連続値を選びます。重みはW=diag(1/2,1/2)です。Labは辺ごとの最近点を調べて解を求め、外部の二次計画ソルバーは使いません。図で制約のかかり方を変えると、目標を少し動かした場合の勾配を比べられます。Labは、この勾配を目標を両側へ少し動かして求めた値と照合しました。

次に、小数点以下を切り捨て、優先度に沿って各製品を1個ずつ増やせるか調べます。制約を守り、目的値も悪化しない場合だけ増やします。Labは6,561個の目標で、提案された整数化を切り捨てや、整数解をすべて列挙した最適値と比べました。別の計算では、共有上限を2として、(1,1)を返す目標がどれだけあるかを調べます。

## Labの人工例

6,561個の目標では、整数化の後も制約違反はありませんでした。3,915件で切り捨てより目的値が低くなり、この格子では、整数解をすべて列挙したときの最適値との差も0でした。ただし、各製品が使う資材の量が異なる例では、優先度順の整数化が最適にならない場合があります。手法の説明に、同じ目的関数で二つの整数解を比較する例を載せました。

共有上限が2のとき、格子上の1,600個の目標のうち、提案された整数化は全件で(1,1)を返し、切り捨ては0件でした。切り捨てで(1,1)になる目標もありますが、それらは面積が0の半直線に限られ、この格子はそこを避けています。この例は、すべての実行可能な整数解に、正の面積を持つ目標の集合があるという論文の一般の証明ではありません。

## 確認したこと

CONFIRMED（確認済み）：3種類の制約のかかり方で、連続値の勾配が中心差分と一致しました。Labで試したすべての目標について、整数化した解が制約を守り、切り捨てに比べて目的値を悪化させないことも確認しました。

PARTIAL（一部確認）：Labで実装したのは、2製品の射影と整数化です。ニューラルネットワーク、経路微分による方策学習（HDPO）、整数化の近似勾配を使う学習は動かしていません。

## 確認していないこと

NOT TESTED（未検証）：Labは多段階在庫の長期費用、小規模問題の最適性ギャップ0.91%、ASMLの研究課題の費用削減、規模を広げたときの性能、現場導入を検証していません。整数化のSTEは真の勾配ではなく、学習にどれだけ役立つかも、この例では確かめていません。一般の制約や重みでの完全性や誤差の上限は、Labの結果ではありません。
