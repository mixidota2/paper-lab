# ReuseGR：検索語の計算をどこまで共有するか

検索や推薦の仕組みを調べるための教材です。同じ検索語なら商品コードの先頭部分（prefix）をどこまで使い回せるか、その先の計算に現在の履歴をどう使うかを分けて考えます。まず `method.md` で論文の仕組みと教材用の規則を読みます。次にLabで、人工的に作った商品コードの木を操作し、Table 5の投影とTable 1の指標を読み比べてください。原著のモデルを学習させたり、推論を再現したりする教材ではありません。

一次資料は[ReuseGR v1](https://arxiv.org/html/2611.04259v1)です。HTMLの§3〜5、Eq.3、Tables1/5、Appendix Aの履歴条件とC/Dを確認しました。PDF全体の画像、公式実装、生ログは確認していません。

## 再実行

このディレクトリで `uv run run.py` を実行すると、`results.json` を作り直せます。外部データや第三者のコードには頼りません。専用のテストはリポジトリのルートで `uv run pytest -q -ra --fail-on-skip tests/test_reusegr.py` を実行してください。サイト全体のビルドと静的preflight（ブラウザーを使わない事前検査）は、ルートのREADMEに従い、未使用の出力先を指定してください。

## 計算APIの契約

Pythonの`toy(prepared=True, depth=1, query='wide', history='left', budget=4)`とJavaScriptの`ReuseGR.toy(...)`は、同じ種類・範囲の値を引数に取ります。preparedは真偽値のみ、depthは0〜3の整数、budgetは0〜8の整数です。queryはwideまたはnarrow、historyはleftまたはrightです。整数を受け取る引数では、真偽値（bool）、文字列、配列、null、NaN/Infinity、範囲外の値を拒否します。`projection(p)`が受け取るのは0〜1の有限な数だけです。両言語の結果が一致するかは、この共通範囲で確かめます。任意の配列を受け取るAPIはありません。

計算に使う候補は、固定した16個の葉に限られます。候補がない集合を使わず、候補数に応じた分母で平均を計算する処理もありません。budget=0で順位表が空になるのは正常です。不正な入力は例外を返し、NaNをJSONのnullに置き換えて保存することはありません。出力のJSONに含まれる条件から結果を再計算できます。prepared d=0とcoldは、数値が同じでも別の経路として出力します。

## 根拠と限界

確認済み（CONFIRMED）は、教材用の入力範囲、処理経路、候補に到達できる条件、採点と採用の順序、および公表値の算術検算です。仕組みについて確認したのは一部（Mechanism: PARTIAL）です。学習済みモデルと商用ログは未確認（NOT OBSERVED）。原実験の再現、性能、規模を拡大したときの挙動、実務での適用は未検証（NOT TESTED）です。Nodeで画面の要素を模したテストは実ブラウザーでの確認ではありません。原版の検証では、実画面幅、実ブラウザーでの保存、日本語lintを確認していません。

原著の準備済み経路では、7Bモデルが最も高く評価した粗いコード（top1 coarse code）で履歴を絞ります。比較対象と未準備経路では、ログに基づき検索語の一致で絞る方式（logged query-match mask）を使います。ほかの処理も同時に変わっているため、結果の差をすべてprefix共有の効果とはみなしません。商用ログは非公開で、現代のLLMを使う二塔モデルとの比較もありません。検索語がある検索広告の結果を、検索語なしのフィードに一般化することはできません。

原著の節と教材のコードの対応は`mapping.md`で確認できます。Qは検索語の種類を数えたときの準備済みの割合、Pはログ行を数えたときの準備済みの割合です。HRは正解を1件以上取得できた検索語の割合、Recallは、正解全体のうち取得できた割合を検索語ごとに求めた指標です。

## JSON保存に失敗したとき

「合成条件と投影をJSON保存」を押すと、ファイルと同じJSONが読み取り専用の欄に表示されます。ダウンロードが始まらなければ、その欄からコピーして保存できます。表示される案内は、ダウンロード完了を確認したものではありません。条件の変更時、不正な入力時、初期条件に戻したときは、前の条件のJSONと取り違えないよう、欄と案内を消します。入力内容もJSONも外部へ送りません。

この保存機能の変更では、数値モデル、保存形式、原著の掲載値は変えていません。画面の要素を模したテストで、Blobやobject URLを作れない場合、ダウンロード操作に失敗した場合、連続で保存する場合、条件変更とリセットを確かめます。実ブラウザーやOSが実際にファイルを保存したかは、このテストでは分かりません。
