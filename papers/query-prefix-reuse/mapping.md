# 論文の処理とLabで確かめた範囲

Labは[著者論文第1版](https://arxiv.org/html/2611.04259v1)の一部を、小さな人工例に置き換えて説明します。著者の公式コード、モデル、ログを実行したわけではありません。

| 論文の箇所 | Labの対応 | 確かめた範囲 |
|---|---|---|
| §3の式3、§4の図2 | 方法の説明と処理図 | 同じ検索語に先頭の計算を使い回し、その先は現在の履歴で補うしくみを説明します。層ごとの処理時間は測っていません。 |
| §4.2〜4.4 | `run.py` と `model.js` の `toy` | 人が決めた候補の先頭と整数の得点を使います。ReuseCut、CellPlan、Path KDの学習は実装していません。 |
| §4.5、付録C | 計算結果の `l4_scored`、`branches`、`admitted` | 先に葉を採点し、その後で枝を選ぶ順序を確認します。学習したBudgetCutやOPD、GRPOは再現しません。論文では深さ3で枝を減らしません。 |
| 表1、式21 | 画面の指標を選ぶ欄 | 論文に載る3方式を比較します。検索語ごとに同じ重みで平均し、商品に展開する前のSIDで正解を数えます。 |
| 表5、付録D | `projection` と準備済みの割合を選ぶ欄 | 準備済みが占めるログ行の割合Pで平均の端点を補間します。Static Qの品質は検索語を分けて測った値です。混合したP95やP99は求めません。 |
| §5.7、付録D・E | 未準備の場合の処理図と本番比較 | 未準備の検索には別の0.5Bモデルがすぐ答えます。予測深度が正の場合だけ、その後の検索用に準備を依頼します。A/Bテストの効果は準備済みの割合から推計しません。 |
