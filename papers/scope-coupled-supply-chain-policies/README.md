# SCOPE: Supply-Chain Operations through Coupled Policies for End-to-End Coordination

SCOPEは品揃え・供給元・補充周期・配送経路を条件付きの方策としてつなぐ。JDの代理効用は最良の分業方式より約1.58%高い。ただし実店舗の売上A/Bや棚割りRCTではない。

## Core Idea — 主張と解釈

著者の主張：共有表現を使い、先に決めた品揃えや周期が後段の経路問題をどう変えるかを学習する。各段階の代理学習と、計画全体の検証用効用で方策の組合せを選ぶ。

Labの解釈：需要予測の精度だけでは、配送回数や積載制約を含む運用判断を評価できない。SCOPEは部門間の依存を計画全体の費用へ接続する資料として読めるが、代理効用の改善を売上増加へ置き換えられない。

## Overview — 概要

SCOPEは品揃え・供給元・補充周期・配送経路を条件付きの方策としてつなぐ。JDの代理効用は最良の分業方式より約1.58%高い。ただし実店舗の売上A/Bや棚割りRCTではない。

## Problem — 問題設定

品揃えを変えると運ぶ需要と重量が変わり、供給元を変えると距離が変わる。補充周期は一回の荷量と在庫の保有期間を変えるため、同じ配送最適化でも入力となる問題が異なる。

## Why It Might Work — 解釈

解釈：先行判断を固定してから強い配送ソルバだけを選んでも、先行判断が作った高費用の条件を解消できない。全体効用で品揃えの交換や周期候補を比較すれば、その条件自体を変えられる。ただし式(3)の理想的な完了価値を厳密に計算する方法ではない。

## モデル / 手法

## 三つの部門を四段階の決定でつなぐ

Figure 2と式(1)–(6)では、計画はy = (A, σ, T, R)。Aは各拠点の品揃え、σは供給元、Tは補充間隔、Rは配送経路を表す。Transformerの共有表現に需要・拠点・距離・費用を入れ、後の方策は前の決定を条件として受け取る。

式(1)はq̄ᵢ(A) = Σₚ∈Aᵢ dᵢₚwₚ、qᵢ(A,T) = T_z q̄ᵢ(A)。周期を延ばすと一回の荷量が増え、車両容量を超えうる。式(2)はU = V(A) − L_cov(A) − C_rt(R;c) − C_inv(A,T;c)。未採用品の需要に対する罰則L_covは、動的在庫シミュレーションで実現した欠品売上ではない。

式(3)のQ(A)は、品揃えを固定した後で残りの計画を最適化した値を表す。実装はこれを直接推定せず、品揃えの局所交換、実行可能な近接供給元による初期教師、全体で固定した周期の走査、経路の学習を使う。実行時には補充単位ごとに周期を選び、供給元と配送日で経路問題を分ける。

下の図では供給元を一つに固定し、2商品のうち1商品を選ぶ。Aは需要が大きく重い。Bは需要が少なく軽い。配車費用を変え、需要順で選んでから周期を最適化する分業方式と、品揃え・周期を同じ候補集合から同時に選ぶ全探索を比べる。


## Executable Understanding — 最小実験

`uv run papers/scope-coupled-supply-chain-policies/run.py`。標準ライブラリだけで実行でき、同じフォルダーのresults.jsonを更新する。

utility()で車両台数をceil(荷量/10)と計算する。周期1–4日と2商品を列挙し、同じ費用式で分業方式と全探索を比較する。学習されたSCOPEの方策や多拠点の経路探索は省略する。

## Results — 人工例の結果

配車費用が0なら需要の多いAが選ばれる。費用が高くなると荷量の小さいBへ切り替わる条件が生じる。全探索には分業方式と同じ選択肢も含めた。そのため、この例で全探索の効用が分業方式を下回ることはない。SCOPEの学習性能はここから判断できない。

## What We Verified — 確認範囲

CONFIRMED：車両容量による費用の段差と、費用条件による最適品揃えの変化。MechanismはPARTIAL。

## What We Did NOT Verify — 未検証

Performance / Scaling / Production applicabilityはNOT TESTED。学習、複数供給元、実際の道路距離、在庫動態、実店舗での品揃え変更は試していない。U_refの代理係数が現場の利益や欠品費用を正しく表すかも未検証。
