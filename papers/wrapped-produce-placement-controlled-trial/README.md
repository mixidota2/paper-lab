# WRAPPED：青果売場を入口側に移した店では、何が変わったか

Vogelらは、英国イングランドのディスカウントスーパー36店で、青果を入口近くに移して品ぞろえを広げた後の変化を調べました。研究チームは、会社が改装した18店を、売上や地域の特徴が似た18店と一組ずつ比べました。どの店を改装するかは無作為に決めていません。

研究の主な指標は、家庭が週に一度でも青果を買う確率です。6か月後は改装店側のほうが3.3ポイント高い推定でしたが、95%信頼区間は−2.5〜9.2ポイントでした。店舗全体の販売数量は、導入直後に「改装しなかった場合」の予測を0.32標準偏差上回りました。この二つは別の指標です。店舗で売れた量が増えても、買う家庭が増え続けたとは言えません。店舗は位置と品ぞろえを同時に変えたため、位置だけの効果も切り分けられません。

## 二つの図の読み方

「論文に書かれていること」の図では、店舗の販売数量と家庭の購入確率を選び、著者の推定値と95%信頼区間を時点ごとに読めます。店舗の導入直後の区間は、図では原論文の要旨にある0.11〜0.53を使います。本文§3.2は上限を0.5と記載しています。

「実験」の図は、論文の店舗を再現したものではありません。Labが作った架空の1組について、両店に共通する変化、改装直後だけの上振れ、改装した店だけの変化を設定します。対照店を使えば共通の変化を取り除けますが、改装した店だけの変化は残ります。JavaScriptが動かない場合も、ページにある初期値と数値表を読めます。

## 教材を手元で動かす

リポジトリの最上位で実行します。`run.py` はPythonの標準ライブラリだけで動きます。

```bash
uv sync --extra dev --frozen
uv run papers/wrapped-produce-placement-controlled-trial/run.py --test
uv run papers/wrapped-produce-placement-controlled-trial/run.py
uv run pytest
```

サイトを別の場所に生成する場合は、毎回新しい専用ディレクトリを指定してください。ビルドは出力先を作り直します。

```bash
uv run python -m paper_lab.build --root . --out /tmp/paper-lab-wrapped-review
uv run python -m http.server --directory /tmp/paper-lab-wrapped-review 8000
```

ビルドが終わったら `/papers/wrapped-produce-placement-controlled-trial.html` を開きます。ホームのキャッシュに書き込めない環境では `UV_CACHE_DIR=/tmp/uv-cache` を指定できます。サイト全体は `papers/` 全体をもとに生成します。

## ファイルと確認範囲

- `lab.yaml` と `method.md` は、著者が店舗を選んだ手順と、二つの指標を得た方法を説明します。
- `run.py` は、論文の値を示す `evidence.md` と、架空の店舗で試す `experiment.md` を生成します。図の文章を変更するときも `run.py` を編集します。
- `results.json` は、著者の報告値を `reported`、Labの計算値を `synthetic` に分けます。
- `mapping.md` は、各説明の出典とLabで再現していない手順を示します。

Labは実際の販売記録や会員カードの個票を入手していません。補足資料S2 Boxにはモデルの項が書かれていますが、残差の相関、推定時の設定、家庭の購入確率への変換手順は記載されていません。Labは原論文の推定を実行していません。
