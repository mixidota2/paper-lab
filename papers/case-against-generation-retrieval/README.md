# 商品IDを生成せずに推薦候補を探す

このLabは、言語モデルを使うことと、商品IDを生成して検索することを分けて考える。Metaの研究チームは、利用者と商品の表現を言語モデルで作り、実在する商品をベクトル索引で探した。このフォルダーのコードは、その推薦モデルを動かすものではない。

## 人工データで、探索を絞ると何を見落とすか調べる

Labは人工データの16候補を4つの枝に分け、各枝を中の候補の平均点で並べる。枝幅は、その順位の上からいくつの枝を残すかを指す。計算は全候補から選んだ最高点と、残した枝だけから選んだ最高点を比べる。平均点が低い枝にも最高点の候補があり得るので、残す枝を増やしながら、見落としの有無と調べた候補の数を確認する。

```bash
uv run papers/case-against-generation-retrieval/run.py
```

リポジトリの最上位で実行すると、`run.py` が `papers/_toy_common.py` の計算を呼び、全条件を `results.json` に保存する。

## 論文の結果と、コードで確かめること

Amazon Beautyの公開データでは、正解が上位10件に入る割合はOneRec-Thinkより二塔モデルの方が高かった。一方、正解が上位に来るほど高く評価するNDCG@10は0.0471から0.0380に下がった。著者はOneRec-Thinkの報告値と比較しており、同じモデル規模で両方を学習し直した結果ではない。

## 数値が示す範囲

このコードは言語モデル、学習、蒸留、索引、応答時間を検証しない。生成検索と比較するときは、商品集合、更新頻度、応答時間の上限をそろえる。公開データで教師が得た成績と、検索モデルを本番で動かした結果も分けて読む。論文の0.5%は使った学習データ量の比であり、事前学習費を含めた総費用の比ではない。
