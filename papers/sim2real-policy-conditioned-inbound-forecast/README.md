# Forecasting from Counterfactual Simulator Rollouts: A Sim2Real Evaluation


## 論文の概要

Amazon所属のWangらは、発注ルールを変えた直後の総入荷量を、変更後の実績がまだない段階で予測する方法を提案しました。著者らは過去の需要や納期を使って新ルールでの発注をシミュレーションし、そこから得た入荷量で予測器を学習させました。比較相手は、同じ構造で旧ルールの実績を学んだ予測器です。

著者らは、すでに導入を終えた2事例に戻り、新ルール導入後の入荷実績を使って評価しました。総入荷量について、予測誤差を実績で割った割合の絶対値を平均した指標（MAPE）で比較しました。模擬データで学んだ予測器はこの値が、点推定で第1事例では1.2〜3.1ポイント、第2事例では12.5〜18.7ポイント低くなりました。導入後に判明した実績で予測を補正すると、第2事例の3週先では誤差率がさらに9.4%から6.9%に下がりました。検証は一つのシミュレーターを使った2事例に限られ、受け入れ枠の超過や欠品が減るかはこの比較からは分かりません。

## 著者らの主張と比較の読み方

著者らは、新ルールをシミュレーターで動かしたデータを使えば、そのルールの実績がまだなくても総入荷量を予測できる場合があると報告しました。

比較では、発注ルールが新旧で異なり、学習データも模擬と実績で異なります。どちらの違いが誤差の差を生んだかは、この比較だけでは分かりません。

## 新ルールを使うと倉庫にはどれだけ届くか

商品の売れ方が同じでも、発注の決め方を変えると、注文数や倉庫に届く量は変わります。倉庫には全商品で共有する受け入れ枠があるため、どの発注条件なら倉庫の受け入れ枠に収まりそうかを判断するには、条件ごとに入荷の総量を見積もる必要があります。著者らが予測するのはこの合計です。予測器が発注ルールや受け入れ枠を決めるわけではありません。

## 入荷予測器をどのように学習させたか

### 過去の需要を使い、新ルールの注文から在庫を計算する

著者らは、各商品の情報を、発注によって変わるものと、発注しても変わらないと仮定するものに分けました。この考え方をExo-IDPと呼びます。需要、価格、発注原価、納期には過去の値を使います。ここでいう需要は、在庫が十分にあれば売れた数量です。一方、新ルールが出す注文数は、在庫や未着注文などの状態と、全商品に共通の費用 λ をもとに計算し直します。

1. 式1：`Jᵢₜ = Σ₀≤k<t aᵢₖ 1{vᵢₖ=t−k}`。商品 i について、過去の注文のうち週 t に納期を迎えた分を合計します。
2. 式2：`Iᵢₜ⁻ = Iᵢₜ₋₁ + Jᵢₜ`、`sᵢₜ = min(Dᵢₜ,Iᵢₜ⁻)`、`Iᵢₜ = max(Iᵢₜ⁻−Dᵢₜ,0)`。前週末の在庫に入荷を足し、需要と手元にある在庫の少ないほうを販売数とします。残った在庫は翌週に持ち越します。

### 共通の費用を入力し、総入荷量を予測する

倉庫が受け入れられる数量を G とします。著者らは、全商品の入荷量 J の期待値がこの枠を超えないように、全商品の発注ルールに、入荷1単位当たりの共通費用 λ を与えます。この費用は、注文を抑えるための調整信号です。仕入先に支払う価格とは別です。高い費用を与えると、新ルールは注文を抑え、それ以降に届く量も変わります。

著者らはHaar基底を使い、G が階段状に増減する計画を作りました。学習済みの調整モデルは、各計画を共通費用 λ の系列に変えます。著者らは新しい発注ルールを固定し、費用の系列を替えながらシミュレーションを行いました。その結果として得られた総入荷量を、予測器の学習に使います。更新するのは予測器だけです。

式3では、予測器は直前64週の履歴と費用の候補を受け取り、`Ĵₜ:ₜ₊L = ψθ(Xₜ,λₜ:ₜ₊L)` で総入荷量を予測します。祝日や需要予測など、予測を出す時点で分かる将来の特徴も使います。著者らは、商品を集約した特徴から総量を直接出す集約型（Global Aggregate）と、商品の予測を後から足す積み上げ型（Bottom-Up）を比べました。履歴側は参照間隔を1、2、4、8、16、32週に広げる因果CNN、将来側は逆向きの因果CNNで特徴を読みます。2層のELU MLPが26週先までを予測します。著者らは予測と模擬入荷量の二乗誤差を減らすように、Adam（学習率10⁻³）で2,000エポック学習させました。各模擬実行では3,000商品を抽出しました（付録B・表4）。

この研究の在庫シミュレーターはMadekaら、容量の調整はEisenachら、総入荷量を予測する仕組みはWangらの先行研究に基づきます（§3・付録A〜B）。

### 導入後に分かった実績で予測を補正する

著者らは導入から最初の4週が過ぎてから、式4の `Ĵcal = αₜ + βₜ Ĵsim` で予測を補正しました。新しく予測を出すたびに、そこまでに答え合わせが済んだ予測と実績を集め、切片 α と傾き β を求め直します。著者らはこの1組の係数をすべての予測期間に共通で使いました。結果がまだ分からない過去の予測は、実績が判明するまで係数の推定に使いません。

## 過去の需要と納期を再利用できる条件

旧ルールの実績には、新ルールが発注をどう変えるかは記録されていません。著者らは、新ルールをさまざまな条件で動かし、共通の費用を変えると総入荷量がどう動くかを学習データに加えました。シミュレーターの注文数や入荷量にずれがあっても、その反応を学ぶ材料にはなり得ます。

ただし、この方法は、発注ルールを変えても過去の需要や納期を使い回せると仮定します。第1事例の無作為割付を使った確認では、需要の差の95%信頼区間は1.37〜2.44、納期は0.35〜0.37で、どちらもゼロを含みません。著者らは、差が小さい一方で、仮定は完全には成り立たないと述べています（表5）。

## 著者が2つの導入事例で得た結果

[一次資料：原論文v1の本文・表](https://arxiv.org/html/2610.03662v1)。第1事例では、著者らは約2万商品を対象に、強化学習で作った発注ルールを無作為に割り付け、1年間運用しました。第2事例では、約10万商品を対象に別の発注ルールを3カ月運用しました。論文は導入先を大手小売業者とだけ記しています。以下は、どちらも導入を終えた後に行った予測の比較です。

| 事例と学習データ | 1週先 | 2週先 | 3週先 | 4〜10週先 |
| --- | ---: | ---: | ---: | ---: |
| 第1事例：新ルールの模擬 | 13.3±2.7 | 11.7±2.8 | 13.2±3.1 | 14.8±2.8 |
| 第1事例：旧ルールの実績 | 15.0±2.9 | 14.8±3.1 | 15.2±3.1 | 16.0±3.1 |
| 第2事例：新ルールの模擬 | 12.7±3.6 | 15.3±7.4 | 9.4±3.8 | 11.5±3.4 |
| 第2事例：旧ルールの実績 | 25.6±5.2 | 27.8±6.3 | 28.1±6.4 | 25.2±5.7 |

著者らは、すべての商品の入荷を合計したうえで、各週の予測の絶対誤差を実績で割り、予測を出した週にわたって平均しました。表は集約型の予測器を比べたもので、数値の単位は%です。±は各予測器の平均に対する95%信頼区間の半幅で、2つの予測器の差に対する区間ではありません（表2）。

著者らが新ルールの実績で補正した後、同じ順の誤差率は、第1事例で11.8%、11.2%、13.1%、14.8%、第2事例で12.6%、13.0%、6.9%、9.7%でした。第1事例の4〜10週先は点推定が変わりませんでした。第2事例について、旧ルールの実績で学んだ同じ集約型予測器を補正した結果は報告されていません（表3・付録D）。

別の診断では、著者らは事後に分かった需要や納期を入力し、実際の在庫から毎週シミュレーションを始め直しました。このときの総入荷量の誤差率は第1事例で13.2±2.4%、第2事例で11.8±2.6%でした。この診断には予測時点では分からない情報が含まれます。第1事例の商品・週ごとの比較では、実績を模擬値で回帰した傾きは発注が0.70〜0.71、入荷が0.67〜0.67、在庫が0.90〜0.91、販売が0.99〜1.00でした。これらは傾きの95%信頼区間です。たとえば入荷の傾き0.67は、模擬値が実績の67%だったという意味ではありません（表1）。

## Labでは架空の商品を使って流れを追う

Labは24個の架空の商品を使って、注文が届く週と在庫の増減を示します。費用と週を選ぶと、納期を迎えた注文が入荷し、販売分を引いた在庫が翌週に残る流れを追えます。費用を変えても、図に使う需要と納期は変わりません。

Labは、翌週の総入荷量を出す線形回帰を2つ作ります。どちらも、当週の在庫や未着注文など7つの値を入力します。一方は旧ルールで動く架空の過程、もう一方は新ルールで動くシミュレーターから学びます。シミュレーター側の学習データだけ、注文を0.7倍し、納期を1週延ばします。このずれは原論文の数値から求めたものではありません。評価では、両方の予測器を、ずれを入れていない同じ新ルールの過程で比べます。Labは入荷量がゼロでも計算できるよう、各週の絶対誤差を、実際の入荷量と1の大きいほうで割ります。

## 人工実験で新ルール側の誤差が下がったのは補正後

**NOT OBSERVED（補正前の改善は確認できず）。** Labが乱数の初期値を5通り変えて比べたところ、平均誤差率は旧ルールの人工履歴で学んだ予測器が28.054%、新ルールの模擬データで学んだ予測器が66.775%でした。

Labが結果の分かった予測と実績を4件集めてから、得られた分だけで毎回補正すると、平均誤差率は旧ルール側が28.477%、新ルール側が20.780%でした。この人工例では補正後に初めて新ルール側の誤差が小さくなりました。著者らが実際の導入事例で得た、補正前の改善は再現できませんでした。

## Labがコードで確かめたこと

**CONFIRMED（確認済み）。** Labのコードでは、前週の在庫に入荷を足し、販売を引いた数量が期末在庫と一致しました。図で費用を変えても需要は同じです。Labは両方の予測器を同じ期間で比べ、補正には評価対象より前に結果が分かった予測だけを使います。

**PARTIAL（確認は一部）。** Labは新ルールの模擬データを使って予測器を学習させました。ただし、著者らのCNNの代わりに線形回帰を使い、容量目標から費用を作る調整モデルも省いています。

## Labが確かめていないこと

**NOT TESTED（未検証）。** Labは大手小売業者の実データを使っていません。商品別の入荷精度や、費用、欠品、受け入れ枠の超過を減らせるかは確認していません。ほかの企業やシミュレーターに適用できるかも未検証です。

## 人工実験を実行する

リポジトリのルートで次を実行すると、人工実験の結果を作り直し、記事を生成できます。最初のコマンドでは `uv` が NumPy を用意します。

```bash
uv run --no-project papers/sim2real-policy-conditioned-inbound-forecast/run.py
uv run paper-lab build
```

`lab.yaml` は記事の原稿、`run.py` は人工実験のコードです。`results.json` では、論文の転記と人工実験の出力を別の項目に保存しています。
