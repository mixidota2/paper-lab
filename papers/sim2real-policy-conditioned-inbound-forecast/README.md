# Forecasting from Counterfactual Simulator Rollouts: A Sim2Real Evaluation

## Overview — 概要

**Worth Reading：方策を替えると、予測する入荷量そのものが変わる。** Amazonの2つの実配備を後から評価した研究。新方策を動かしたシミュレーターで予測器を学ぶと、旧方策の実履歴で学ぶ同じ予測器より、総入荷量のMAPEの点推定値が低かった。Study 1では旧履歴学習との差が1.2〜3.1ポイントにとどまり信頼区間も重なる一方、別の方策を配備したStudy 2では12.5〜18.7ポイントの差があるため、両研究を同じ強さの改善証拠とは読めない。

予測するのは入荷量だ。共通の容量コストλに各商品の発注方策が反応するため、自社の方策が予測対象を変える。発注・入荷の再現性が十分でないシミュレーターにも、学習データを作る用途はありうる。ただし容量超過、費用、欠品の改善は測っていない。

## Problem — 問題設定

倉庫の入荷処理量を抑えるため、各商品へ共通の入荷単価λを通知する。発注方策πはλを見て注文を変え、納期を経て入荷Jが変わる。次の容量計画には、その応答を先に知る必要がある。

過去の入荷は旧方策π₀の応答である。新方策π₁に替えた日に、π₁の実績はまだない。外から来る需要と、自社の発注で生じる入荷を同じ「時系列」として扱うと、この違いを見落とす。

## Core Idea — 著者の主張とLabの解釈

著者の主張：外生過程を再生し、新方策の行動と在庫状態を再計算した軌跡で応答予測器ψを学習する。2つの実配備への転移と逐次補正を測ると、不完全なシミュレーターでも旧方策の履歴より低い予測誤差を得る場合がある（§3–4）。

本Labの解釈：シミュレーターの精度と、学習データとしての有用性は別々に測りたい。MadekaらのExo-IDP、Eisenachらの容量調整、Wangらのdual coordinatorを引き継ぎ、ここでは「方策が変える予測対象」を実配備で評価した点が中心となる。データ源や方策整合が改善の原因だと単独に識別した実験ではない。

## モデルと式

### 固定して再生する量と、計算し直す量

Exo-IDPは状態をxᵢₜ=(yᵢₜ, ξᵢₜ)に分ける。外生ξは、欠品を補正した需要D、価格、原価、仕入先納期v。これらの過去系列を再生する。内生yは在庫、未着注文、入荷で、発注aᵢₜ∼π(·|xᵢₜ,λₜ)から再計算する。

Eq.1：`Jᵢₜ = Σ₀≤k<t aᵢₖ 1{vᵢₖ=t−k}`。過去の注文のうち今日が納期のものだけが届く。

Eq.2：`Iᵢₜ⁻ = Iᵢₜ₋₁ + Jᵢₜ`、`sᵢₜ = min(Dᵢₜ,Iᵢₜ⁻)`、`Iᵢₜ = max(Iᵢₜ⁻−Dᵢₜ,0)`。入荷後に販売し、残りを次期へ送る。下の週送り図で、この順序を追える。

### λを無作為に振る前に、容量計画から作る

Appendix B / Fig.1では、打ち切ったHaarウェーブレットの係数から容量目標Gの階段状の系列を作る。学習済みdual coordinatorがGをλへ変換し、固定した発注方策を動かす。得られる教師データは`(Xₜ,λₜ:ₜ₊L) → Jₜ:ₜ₊L`。予測器だけをMSEで更新し、発注方策へは逆伝播しない。

Eq.3：`Ĵₜ:ₜ₊L = ψθ(Xₜ,λₜ:ₜ₊L)`。商品別の履歴エンコーダーはdilated causal CNN、dilationは1,2,4,8,16,32、幅32、履歴H=64週。将来λと特徴量には逆向きのcausal CNNを使い、2層ELU MLPでL=26週を出力する。Global Aggregateは表現を集約して総量を出し、Bottom-Upは商品別出力を足す。Adam 10⁻³、3,000商品、2,000 epochという設定だが、Labの最小二乗回帰とは別物である。

Eq.4：`Ĵcal = αₜ + βₜ Ĵsim`。配備4週後から、その時点までに実現した予測・結果の組だけで線形回帰を拡張していく。αとβは全予測期間で共有する。未来の正解を補正へ混ぜない。

## Why It Might Work — 解釈

解釈：旧方策を忠実に記録したデータでも、新しいλ応答は学べない。模擬データの値にずれがあっても、新方策が何に反応するかを含んでいれば転移の足掛かりになる。α+βĴは配備後に分かった水準・尺度のずれを補う。

ただし、納期や需要が発注によって変わるほど外生再生の仮定は崩れる。Study 1の無作為化を使ったTable 5では、需要の処置係数の95% CIは[1.37,2.44]、納期は[0.35,0.37]。R²は0.02と0.01で小さいが、ゼロとの差は有意である。外生性が完全に確認されたとは扱わない。

## Executable Understanding — 実行可能な理解

24商品の在庫を、同じ需要・納期系列で再生する。λが異なると発注、入荷、在庫だけが変わる。週を送ってEq.1–2の保存則を確認した後、下のグラフで原論文の転移評価を読む。

最小実験は7特徴の線形回帰を共通に使う。旧方策の履歴と、新方策を動かす不完全な模擬データで別々に学び、新方策の真の過程で評価する。模擬側は注文を0.7倍し、納期を1週延ばした。これは意図的なずれであり、Table 1の回帰の向きを再現した設定ではない。補正は過去4観測以降の拡張窓のみ。5 seedを同じ評価期間で比較する。

方策は需要水準に基づく継続発注と、目標在庫との差を埋める発注を混ぜる。旧方策と新方策でλへの感度を変えた。初期案ではゼロ近傍の入荷にMAPEが過敏だったため、この方策へ改めて条件を固定した。MAPEの分母はmax(J,1)とし、ゼロ除算を避ける。

## Results — 最小実験の結果

**NOT OBSERVED：このtoyでは補正前の模擬学習の優位は出なかった。** 5 seed平均のMAPEは旧履歴28.054%、模擬66.775%。模擬の逐次補正後は20.780%、同じ補正を旧履歴へ適用すると28.477%だった。

新方策だけでは足りない。ここで確認できたのは、意図的な注文尺度・納期のずれが補正前の誤差を大きくし、配備後の観測を使う補正によってその誤差が下がるという、固定した人工過程での挙動までである。原論文のzero-shot改善を再現したとは扱わない。

## What We Verified — 確認できた範囲

CONFIRMED：在庫の保存則、λを替えても需要系列が同じこと、同じ評価期間を使うことをコードで確認した。校正には当該予測より前の結果だけを渡している。

PARTIAL：新方策の模擬データから学ぶ仕組みを人工過程で動かした。原論文のCNN、Haar sampler、dual coordinatorは実装していない。表と式の照合は独立した性能再現とは区別する。

NOT OBSERVED：補正前の模擬学習が履歴学習を上回る効果。結果に合わせて成功する設定へ調整せず、この条件での失敗も残す。

## What We Did NOT Verify — 未検証

NOT TESTED：Amazonデータでの再現、商品別の誤差、容量超過、実費用、欠品、λの最適化、他社・別シミュレーターへの一般化。本論文は1つのシミュレーターによる後ろ向き評価で、公式コードの案内はPDFにない。
