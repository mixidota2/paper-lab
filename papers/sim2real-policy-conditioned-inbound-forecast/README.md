# Forecasting from Counterfactual Simulator Rollouts: A Sim2Real Evaluation

## 発注ルールを変えた後の入荷を、切り替え前に予測する

発注ルールを変えると、同じ需要でも注文数が変わります。その注文が仕入先から届く週には、倉庫が処理する入荷量も変わります。旧ルールで集めた実績には、新ルールが同じ条件で何を発注するかは記録されていません。

Amazonの著者らは、過去の需要や納期をシミュレーターに与え、新ルールで発注した場合の入荷を計算しました。その入荷を使って学んだ予測器を、旧ルールの実績を使って学んだ同じ構造の予測器と比べます。著者の所属はAmazonです。論文は導入先を大手小売業者とだけ記しています。どちらも新ルールを導入した後の実績で評価しました。総入荷量では、予測誤差を実績で割った割合の絶対値を平均した指標（MAPE）を使います。誤差の点推定では、模擬データで学んだほうが低くなりました。差はStudy 1で1.2〜3.1ポイント、Study 2で12.5〜18.7ポイントです。改善幅は同程度ではありません。容量を超えた回数、費用、欠品の改善は、この比較から分かりません。

## 倉庫の受け入れ枠と発注をつなぐ

倉庫全体で受け入れられる入荷量を G とします。各商品の発注ルール（方策）π は、在庫などの手元の情報と、全商品に共通の入荷費用 λ を見て注文数を決めます。この費用は入荷を抑えるための信号で、仕入先に支払う価格ではありません。費用が高い条件では注文を抑えるように方策を動かします。予測器が返すのは、候補の費用を使ったときの総入荷量 J です。予測器そのものは費用や発注ルールを選びません。

## 著者の主張とLabの解釈

著者らは、実績と完全には一致しないシミュレーターでも、新ルールで動かして集めたデータなら、切り替え直後の予測に役立つ場合があると報告しています。モデルを作る時点で新ルールの実績を使わず、過去の導入事例に戻って予測します。導入後は、結果が判明した予測から順に補正に使います（§3–4）。

Labでは、シミュレーターが在庫や入荷をどれだけ正確に計算するかと、そこで作ったデータで学んだ予測器が実際の入荷をどれだけ当てるかを分けます。この研究はMadekaらのExo-IDP、Eisenachらの容量調整、Wangらの調整モデルを引き継ぎます。比較では、学習に使うデータが実測か模擬かだけでなく、どちらの発注ルールで作ったデータかも変わっています。誤差の差がどちらに由来するかは切り分けられません。

## モデルと式

### 発注を替えても過去の需要と納期を使う

著者らのExo-IDP（外生的な情報を使う意思決定過程）では、商品 i の週 t の状態を `xᵢₜ = (yᵢₜ, ξᵢₜ)` と分けます。需要 D、価格、発注原価、仕入先の納期 v は、新しい発注では変わらないと仮定して、過去の記録から再生します。需要は欠品で販売できなかった分を補正した量です。一方、在庫、未着注文、入荷は発注で変わるため、新しいルールの注文 `aᵢₜ ∼ π(· | xᵢₜ, λₜ)` を使って計算し直します。

- 式1：`Jᵢₜ = Σ₀≤k<t aᵢₖ 1{vᵢₖ=t−k}`。過去に出した注文のうち、週 t に納期を迎えた数量を足すと、その週の入荷になります。
- 式2：`Iᵢₜ⁻ = Iᵢₜ₋₁ + Jᵢₜ`、`sᵢₜ = min(Dᵢₜ,Iᵢₜ⁻)`、`Iᵢₜ = max(Iᵢₜ⁻−Dᵢₜ,0)`。前週末の在庫に入荷を足し、需要と手元にある在庫の少ないほうを売ります。残りを翌週に持ち越します。

### 費用の候補を与えたときの入荷を学ぶ

著者らはHaarウェーブレットの基底の一部を使い、段階的に増減する容量目標 G の系列を作りました（Appendix B / Fig.1）。学習済みの調整モデル（dual coordinator）が、容量目標を共通費用 λ の系列に変えます。固定済みの発注ルールにその費用を与え、シミュレーターを動かすと、候補の費用と、それに対応する総入荷量の組が得られます。平均二乗誤差（MSE）で更新するのは入荷予測器です。発注ルールはこの学習で更新しません。

式3は `Ĵₜ:ₜ₊L = ψθ(Xₜ,λₜ:ₜ₊L)` です。入力には直前64週の履歴に加え、候補の費用と、祝日や需要予測などその時点で使える将来の特徴を渡します。Global Aggregateは各商品の特徴をあらかじめ集約した履歴から総量を予測します。対してBottom-Upは商品別に予測してから足します。過去の履歴を読む因果CNNは参照間隔を1, 2, 4, 8, 16, 32と広げ、幅は32です。将来の費用と特徴は逆向きの因果CNNで読み、2層のELU MLPで26週先までの予測を出します。学習にはAdam（学習率10⁻³）を使い、1回の模擬実行で3,000商品を抽出し、2,000 epoch学習します（Table 4）。Labの線形回帰はこのCNNを再現していません。

### 導入後は、判明した実績から補正する

著者らは導入後の最初の4週を過ぎてから、式4の `Ĵcal = αₜ + βₜ Ĵsim` で予測を補正します。予測を出す時点までに結果が判明した過去の予測と実績だけで、切片 α と傾き β を求めます。新しい実績が判明するたびにこの組を足して係数を求め直し、一組の係数をすべての予測期間で使います。将来の実績を先に渡す手順ではありません。

## 過去の需要や納期を再利用できる条件

旧ルールを使ったときの実績だけでは、費用を変えたときに新ルールがどれだけ注文を変えるかは分かりません。シミュレーターの注文や入荷にずれがあっても、候補の費用に対する新ルールの反応を学ぶ材料にはなります。導入後の線形補正は、すでに分かった実績を使い、予測全体の水準と尺度を直します。

発注の仕方が需要や納期にも影響するなら、過去の値を別の発注ルールでも同じように使う仮定は弱くなります。Study 1の無作為割付を使ったTable 5では、処置係数の95%信頼区間は需要で[1.37, 2.44]、納期で[0.35, 0.37]でした。決定係数R²はそれぞれ0.02、0.01でしたが、処置係数の区間はどちらもゼロを含みません。R²の小ささを、発注の影響がない証拠にはできません。

## 著者が2つの導入事例で測ったこと

[一次資料：原論文のTable 1–3 / Appendix C–D](https://arxiv.org/pdf/2610.03662v1)。Study 1では約2万商品を対象に、強化学習（RL）で得た発注ルールを無作為に割り付け、1年間運用しました。Study 2では別の発注ルールを約10万商品に3カ月使いました。予測器の比較は事後に行っています。

| 学習データと導入事例 | 1週先 | 2週先 | 3週先 | 4〜10週先 |
| --- | --- | --- | --- | --- |
| Study 1：新ルールの模擬 | 13.3±2.7 | 11.7±2.8 | 13.2±3.1 | 14.8±2.8 |
| Study 1：旧ルールの実績 | 15.0±2.9 | 14.8±3.1 | 15.2±3.1 | 16.0±3.1 |
| Study 2：新ルールの模擬 | 12.7±3.6 | 15.3±7.4 | 9.4±3.8 | 11.5±3.4 |
| Study 2：旧ルールの実績 | 25.6±5.2 | 27.8±6.3 | 28.1±6.4 | 25.2±5.7 |

表はどちらも前節で説明したGlobal Aggregateの結果です。各予測の絶対誤差を総入荷量の実績で割り、その割合を週ごとの予測起点で平均します。値の単位は%です。±は正規近似による95%信頼区間の半幅で、同じ週に出した二つの予測の差に対する区間ではありません。Study 1では区間が重なりますが、重なりだけで差の有意性は判定できません。

新ルールの模擬データで学んだ予測器を導入後に補正した値は、表と同じ順でStudy 1が11.8 / 11.2 / 13.1 / 14.8、Study 2が12.6 / 13.0 / 6.9 / 9.7です。Study 1の4〜10週先は点推定で14.8のままです。Study 2について、旧ルールの実績で学んだGlobal Aggregateを補正した結果は報告されていません。

Table 1では、著者らは商品と週ごとに、模擬値を横軸、実績値を縦軸として、切片なしで回帰しました。傾きの95%信頼区間は、発注0.70〜0.71、入荷0.67〜0.67、在庫0.90〜0.91、販売0.99〜1.00です。発注の傾きは、模擬値が実績値の7割という意味ではありません。別の診断では、事後に判明した需要や納期も与えて1週ずつ進めたところ、総入荷量のMAPEはStudy 1が13.2±2.4%、Study 2が11.8±2.6%でした。この診断には予測時にまだ分からない情報を使います。運用時に出せる予測精度と同じ意味ではありません。

## Labの図と人工実験

在庫の図には人工の24商品を使います。どの費用を選んでも需要と納期は共通で、変わるのは発注と、それに続く入荷や在庫です。費用と週を選ぶと、過去の注文が期首在庫に加わり、販売分を引いた量が期末に残ることを式1–2で追えます。別のグラフに載せた著者の実測結果とは、入力も目的も異なります。

次の実験では、翌週の総入荷量を予測する7特徴の線形回帰を二つ作ります。 予測に渡す在庫や未着注文は当週に分かる集計値で、翌週に届いた量は答え合わせに使います。一方は旧ルールの人工履歴、もう一方は新ルールをシミュレーターで動かしたデータで学びます。後者の学習データだけ、注文量を0.7倍し、納期を1週延ばします。このずれは実験用に設定したもので、Table 1の傾きに合わせたものではありません。評価はどちらも、同じ期間に新ルールで動く人工過程と比べます。

Labの発注ルールは、需要水準に応じて毎週出す注文と、在庫やすでに発注した分を見て不足を補う注文を組み合わせます。旧ルールと新ルールで共通費用への反応は異なります。初期案では入荷がゼロに近いと誤差率が大きく振れたため、今のルールで条件を固定しました。Labの誤差率は入荷量そのものではなく、max(J,1)で割り、ゼロ除算を避けています。

## 人工実験では、補正前の模擬学習の誤差が大きかった

**NOT OBSERVED（効果は確認できず）。** 乱数初期値を5つ変えた平均で、旧ルールの人工履歴で学ぶと誤差率は28.054%、新ルールの模擬データで学ぶと66.775%でした。結果が分かった予測と実績が4件そろってから、得られた観測だけで毎回補正します。模擬データ側の補正後は20.780%、旧履歴側に同じ補正を適用すると28.477%でした。

この人工例では、ずれを入れた模擬データで新ルールを学ぶだけでは精度は上がらず、導入後の設定に相当する補正を加えて初めて、旧履歴で学んだ予測器より誤差が小さくなりました。著者の導入事例で報告された、補正なしの改善（zero-shot）を再現した結果ではありません。
