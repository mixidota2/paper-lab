# Bridging Forecast Accuracy and Inventory KPIs: A Simulation-Based Software Framework

## 予測誤差が小さいモデルでも、在庫費用は下がるとは限らない

予測の外れが小さいモデルでも、欠品まで含めると費用が高くなることがあります。著者はトラックの補修部品の需要を人工的に作り、7モデルを同じ在庫ルールで比較しました。平均絶対誤差が小さかったのはXGBoostとRandom Forest、総費用が最も低かったのはCrostonです。

## 著者は何を比べたか

補修部品は、需要がない日が多く、売れる日にまとめて必要になることがあります。著者は時間とともに需要傾向が変わる条件4種類、車両数の範囲4種類、部品寿命の範囲3種類を掛け合わせ、48の条件を作りました。各条件で、4販売店の3年分を人工的に生成します。店舗で観測した需要の比較ではありません。

## 著者の主張とLabの読み方

著者は、補修部品の需要を人工的に作り、予測結果から在庫費用と充足率までを計算できる公開ソフトウェアTruckPartsを提供しました。予測の外れと費用の関係は、需要の条件によって変わると報告しています。

Labの読み方：Accuracy Is Not Serviceが示した「誤差だけでは運用上の良し悪しは分からない」という問題を、費用と充足率で試せる環境です。現場でどのモデルが優れるかの証拠ではありません。需要の作り方や在庫ルールの仮定を変えて、結論がどこで変わるかを調べる出発点です。

## 予測の外れと在庫費用で順位が違う理由

平均絶対誤差（MAE）は実績と予測の差を絶対値にして平均します。同じ1個なら、多く予測しても少なく予測しても同じ誤差です。在庫費用では、持ちすぎれば保管費がかかり、足りなければ欠品や緊急便につながります。著者の試験環境では、保管・発注・緊急便・輸送・サービス不足の費用を通して、同じ予測でも費用がどう違うかを確認できます。

## 原論文の結果

一次資料の著者報告（v2 Table 1）では、XGBoostとRandom ForestのMAEは丸めるとともに0.43、Crostonは0.52です。一方、総費用はそれぞれ約8.2×10⁵、7.5×10⁵、7.4×10⁵でした。MAEはシナリオごとの値を平均し、ばらつきは標準偏差で示しています。費用は全シナリオの合計です。図では指標を切り替え、順位の違いを確認できます。

著者は、MAEと費用の順位相関を全体では0.95、シナリオごとに計算して平均すると−0.16と報告しています（Figure 6）。本文では、二乗平均平方根誤差（RMSE）と費用についても、シナリオ内の平均が−0.06です。需要の規模が違う条件をまとめた相関だけでは、個々の条件でどのモデルを選ぶべきか分かりません。Labはこれらの相関を再計算していません。

## Labの実験を試す

`UV_CACHE_DIR=/tmp/uv-cache uv run --no-project papers/bridging-forecast-accuracy-inventory-kpis/run.py`

Labの小実験では、毎日ゼロと予測するZeroと、需要が発生した日の数量と発生間隔から予測するCrostonを比較します。最初の730日でCrostonを学習し、次の365日はどちらの予測値も固定します。需要と補充ルールは共通です。欠品1個の費用を1、5、20、50に切り替えると、どちらの費用が低いかが変わります。ZeroはXGBoostなどの木モデルの代わりではありません。

## 欠品1個の費用を変えると順位が逆転する

Labの実験では、MAEはZeroが0.537、Crostonが0.855で、欠品単価を変えても同じです。欠品単価50では、総費用がZeroの9,800に対しCrostonは3,395でした。需要数量のうち即時に満たせた数量の割合（充足率）は、それぞれ0%と75%です。欠品単価1では総費用が196と994になり、今度はZeroの方が低くなります。Crostonがいつも有利なのではなく、欠品を減らす価値と在庫を持つ費用の兼ね合いで変わります。

## 原論文：部品が故障した日を需要に変える

著者は、販売店ごとに車両、車両ごとに部品を設定し、1日ずつ故障を発生させます。故障せず使われてきた部品が次の期間に故障する確率は、使用期間ごとの故障の起こりやすさ（ハザードh）を積分して、`P(故障 | 現在まで生存) = 1 − exp(−∫h(u)du)` で求めます（式1、Figure 1）。

故障までの期間には Exponential、Weibull、Log-logistic、Gompertz の4種類の分布を使い、季節や車両の使われ方も反映します。故障した部品の年齢をゼロに戻し、故障によって生じた需要を販売店・部品の種類ごとに集計します。

こうして得た日次需要を、予測モデルと在庫費用のシミュレーションに渡します（Figure 3）。最初の730日で学習し、次の365日で評価します。XGBoost、Random Forest、SVR、ARIMA、Croston、SBA、TSBの7モデルの設定は、平均絶対誤差（MAE）が小さくなるように選びます。

## Lab：予測を固定し、欠品1個の費用を変える

説明用の `run.py` は、各日が独立に、確率0.1で4個、それ以外は0個の需要を作ります。Crostonは、需要があった日の個数zと、前に需要があった日からの間隔aを別々に更新し、予測を `f = z / a` とします。更新の平滑化係数は0.1です。学習後は予測値を固定し、評価期間中の需要で更新しない設定です。Zeroは毎日0個と予測する比較対象です。

どちらの予測でも、目標在庫は `S = ceil(5f)`、つまり予測を5倍して切り上げた個数です。初期在庫は0、納期は1日。毎日、前日の発注分を受け取り、その日の需要に応え、残りの在庫に保管費を計上してから、目標に足りない分を発注します。足りなかった分はその場で失注し、未納分を翌日へ繰り越さない設定です。

予測誤差は `MAE = mean(|d − f|)`、費用は `C = Σ在庫 + p × Σ欠品数量` です。日末在庫1個・1日につき1の保管費、欠品1個につきpの費用を計上します。目標在庫の係数5や費用の係数は、違いを理解するための設定です。原論文の推定値ではありません。
