# Bridging Forecast Accuracy and Inventory KPIs: A Simulation-Based Software Framework

## 予測誤差が小さいモデルでも、在庫費用は下がるとは限らない

在庫を持ちすぎたときと欠品したときでは、かかる費用が違います。著者はトラックの補修部品の人工需要を作り、同じ在庫ルールで7モデルを比較しました。平均絶対誤差を小さく抑えたのはXGBoostとRandom Forestで、総費用が最も低かったのはCrostonです。

## 著者は何を比べたか

補修部品は、需要がない日が続いたあと、ある日にまとめて必要になることがあります。著者は需要の変化4種類、車両数の範囲4種類、部品寿命の範囲3種類を組み合わせ、48条件を設定しました。各条件で4販売店の3年分の需要を作りました。販売店で計測した需要は使っていません。

## 著者の主張とLabの読み方

著者が公開したTruckPartsでは、補修部品の需要を人工的に生成し、モデルの予測を使って在庫費用と充足率を計算できます。著者は、予測誤差と費用の関係が需要の条件によって変わると報告しました。

Labの読み方：Accuracy Is Not Serviceが示したのは、「誤差だけでは運用上の良し悪しは分からない」という点です。TruckPartsを使うと、費用と充足率を加えてモデルを比較できます。試験環境での順位を実際の店舗に当てはめるのではなく、需要の仮定や在庫ルールを変えても同じ順位になるかを調べるために使えます。

## 予測の外れと在庫費用で順位が違う理由

平均絶対誤差（MAE）は、実績と予測の差の絶対値を平均した値です。予測が1個多くても、1個少なくても、同じ誤差になります。保管費は売れ残りで増え、欠品が起きれば緊急便などの費用もかかります。著者の試験環境では、保管・発注・緊急便・輸送・サービス不足の費用を足し、予測が同じでも費用がどう変わるかを確認できます。

## 原論文の結果

一次資料（論文v2のTable 1）で著者が報告したMAEは、丸めるとXGBoostとRandom Forestがともに0.43で、Crostonは0.52です。同じ順で総費用は約8.2×10⁵、7.5×10⁵、7.4×10⁵でした。MAEはシナリオごとの値を平均し、標準偏差も示しています。費用は全シナリオの合計です。図で指標を切り替えると、どのモデルの値が小さいかを比べられます。

著者の報告では、全体で求めたMAEと費用の順位相関は0.95でした。シナリオごとに順位相関を求めて平均すると−0.16でした（Figure 6）。本文で報告した二乗平均平方根誤差（RMSE）と費用のシナリオ内相関の平均は−0.06です。需要規模の異なる条件をまとめた相関だけから、個々の条件でどのモデルを選ぶべきかは分かりません。Labはこれらの相関を再計算していません。

## Labの実験を試す

`UV_CACHE_DIR=/tmp/uv-cache uv run --no-project papers/bridging-forecast-accuracy-inventory-kpis/run.py`

Labでは、毎日ゼロと予測するZeroと、需要があった日の数量と発生間隔から予測するCrostonを比べます。最初の730日でCrostonを学習し、次の365日はどちらの予測値も固定します。両モデルに同じ需要と補充ルールを使い、欠品1個の費用を1、5、20、50に変えます。Zeroはこの小実験の比較対象で、XGBoostなどの木モデルの代わりではありません。

## 欠品1個の費用を変えると順位が逆転する

欠品単価を変えても予測は変わらず、MAEはZeroが0.537、Crostonが0.855でした。単価50では、総費用はZeroが9,800、Crostonが3,395です。充足率（需要数量のうち即時に満たせた数量の割合）は、Zeroが0%、Crostonが75%でした。欠品単価1では総費用がそれぞれ196と994になり、Zeroの方が低くなります。需要をすぐ満たせるように在庫を持つ費用と、欠品を減らして節約できる費用の差で、どちらが有利かが決まります。

## 確認したこと

CONFIRMED：毎日、前日の在庫に入荷を足し、販売分を引くと日末の在庫になります。販売数量と欠品数量の合計が当日の需要に一致することも確認しました。欠品単価50ではZeroの誤差が小さく、Crostonの総費用が低くなりました。確認できた仕組みはこの範囲に限ります（PARTIAL）。論文の需要生成と費用計算をすべて再現したわけではありません。

## 確認していないこと

Labは、性能、規模を拡大したときの挙動、実務で使えるかを検証していません（NOT TESTED）。著者の48条件、7モデル、費用シミュレータも再実行していません。著者は人工需要を使い、すべての販売店と部品に同じ在庫ルールの設定を使いました。価格、初期在庫、納期は共通で、供給者の容量に上限はありません。この結果は、販促と欠品がある状況での時系列基盤モデル（TSFM）と勾配ブースティング決定木（GBDT）の比較や、実店舗の棚割りを変える無作為化比較試験（RCT）の根拠には使えません。

## 原論文：部品が故障した日を需要に変える

著者は販売店ごとに車両を、車両ごとに部品を設定し、1日ずつ故障を発生させます。故障せず使われてきた部品が次の期間に故障する確率は、期間内の故障の起こりやすさ（ハザードh）を積分して、`P(故障 | 現在まで生存) = 1 − exp(−∫h(u)du)` で求めます（式1、Figure 1）。

部品が故障するまでの期間には、Exponential、Weibull、Log-logistic、Gompertzの4種類の分布を使います。季節や車両の使われ方も反映します。部品が故障したら部品の使用期間をゼロに戻し、その故障で生じた需要を販売店・部品の種類ごとに数えます。

著者はこの日次需要から予測を作り、予測に従って在庫費用を計算します（Figure 3）。最初の730日を学習、次の365日を評価に使います。XGBoost、Random Forest、SVR、ARIMA、Croston、SBA、TSBの7モデルは、平均絶対誤差（MAE）が小さくなるように設定を選びます。

## Lab：予測を固定し、欠品1個の費用を変える

Labの `run.py` では各日の需要を独立に生成します。確率0.1で4個、ほかの日は0個です。Crostonは、需要が出た日の個数zと前回からの日数aを別々に平滑化し、`f = z / a` を予測値にします。平滑化係数は0.1です。学習後は予測を固定し、評価期間中の需要で更新しないまま比較します。Zeroは毎日の予測を0個とする比較対象です。

両モデルに共通の目標在庫は `S = ceil(5f)` です。予測を5倍し、切り上げた個数を使います。初期在庫は0で、発注から到着まで1日かかります。毎日、前日の発注分を受け取ってから需要に応えます。日末の残りに保管費を計上し、目標までの不足分を発注します。需要に対して在庫が足りない分はその日で失注し、未納分を翌日へ繰り越さない設定です。

予測誤差は `MAE = mean(|d − f|)`、費用は `C = Σ在庫 + p × Σ欠品数量` です。日末在庫1個につき1日当たり1、欠品1個につきpを費用に加えます。目標在庫の係数5や費用の係数は、Labが違いを説明するために置きました。著者が推定した値ではありません。
