# RA-DFL：在庫配分の費用を見ながら需要予測を学習する

著者は、限られた在庫を複数の販売チャネルに配るとき、需要予測の誤差ではなく、その予測で在庫を配った場合の費用を使って予測モデルを学習しました。RA-DFLは平均費用と、費用が特に高くなる場合の損失の両方を考慮します。また、欠品で売れなかった分が売上に表れないため、観測売上をそのまま見て在庫を余らせたと判断しないよう、学習時の費用を補正します。

著者がM5のデータで計算した平均費用は、LightGBMで需要を予測してから配分する方式で4.903、RA-DFLで4.721でした（3.7%減）。一方、LightGBMの予測はそのままで、配分だけに高費用時のリスクを加えると5.380になりました（9.7%増）。RA-DFLが別の評価データでも勝ったわけではありません。評価では観測した売上を需要の代わりに使い、販促や欠品も代理指標で判定したため、実店舗での費用削減を測った結果ではありません。

## 図で確かめること

**どちらに在庫を置くか。** 販売先は2つ、全体の容量は10です。固定した需要パターン10通りに対し、整数の配分候補66通りを比較します。保有費用1、欠品費用6、移送費用1、移送可能率0.4は共通です。リスク重みを0〜1で変え、平均費用と高い方20%の平均費用（CVaR₀.₈）のどちらを重く見ると配分が変わるかを確かめます。

**欠品した日の売上から何を学べるか。** 在庫を移さない別の例で、真の需要10に対して売上は4です。売上を需要とみなすと、4を超える発注を過剰と扱います。欠品時にその罰則を外した損失と比べ、需要・売上・発注量を列挙して、補正後の損失が真の費用を超えないことも検算します。予測器の学習、需要の充足率に対する罰則、配分を微分して学習に戻す処理は含みません。

[手法の説明](method.md)では、論文の学習の仕組みとLabの計算を並べています。[原論文との対応](mapping.md)には、使った式と再現していない処理をまとめました。`results.json` では著者の報告値とLabの計算結果を分けています。

## 検算した範囲

- **確認済み（CONFIRMED）：** 有限個のシナリオからのCVaR計算、容量以内の整数配分の全探索、在庫移送がない場合に補正後の損失が真の費用を超えないこと。
- **一部のみ確認（PARTIAL）：** 平均費用と高費用側を重みづけする配分、欠品時に余剰の罰則を外す補正。移送がある場合の命題2や、損失を最小化すれば偏りなく真の需要を推定できるかは確認していません。
- **未検証（NOT TESTED）：** M5・Stallionでの再学習、原論文の最適値との隔たり0.32%、基準比3.7%減とCVaR追加時の9.7%増、実店舗の欠品と費用。Chronosなどの時系列基盤モデルと決定木系モデルを同じ条件で比較した実験でもありません。
