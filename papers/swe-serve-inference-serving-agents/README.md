# SWE-Serveを読む：推論サーバーを入口から確かめる

## 概要

著者らは、コードを書くエージェントが、推論サーバーSGLangに変更を加えた後も利用者の要求に答えられるかを調べました。53課題のうち19課題では、サーバーを起動し、実モデルを読み込んでから、利用者が使う入口を通して出力を確かめました。

この19課題に対してエージェントが作った627件の変更は、すべての検査を含めると288件が合格しました（45.9%）。実モデルを使う検査だけを採点から外すと、同じ変更のまま435件が合格しました（69.4%）。著者らはコードを書き換えたり、テストを実行し直したりしていません。採点の範囲を変えるだけで147件の判定が不合格から合格に変わりました。

## どこで問題が残るか

推論サーバーでは、リクエストを受ける処理、実モデルを呼び出す処理、キャッシュや状態を管理する処理がつながっています。関数を一つだけ呼び出すテストは、その関数自体を調べられます。一方、公開APIから渡した設定がその関数に届くか、前の要求の状態を次の要求が誤って使わないかは、入口を通して初めて分かることがあります。

## 論文の採点方法

著者らは推論サーバーの変更を、新しい機能と既存の動作に加え、一部の課題では実モデルを使うテストや性能条件で評価しました。実モデルを使うテストだけを採点から外すと、同じ変更でも合格率は23.4ポイント上がりました。

試験の作り方と採点手順は[方法の説明](method.md)にまとめています。

## 著者の結果

### 何を評価したか

53課題のうち12課題はCPU、41課題はH100 1台で実行しました。19課題で実モデルを使う検査を、3課題で性能条件を採点しています（表2）。

### 合格に変わったのは、627件中147件

著者らは、11モデルについてそれぞれ最良だった設定を選び、19課題に対する各3回の試行を集計しました。全検査に合格したのは288件です。実モデルを使う検査（E2E）だけを採点から外すと、147件が新たに合格し、435件になりました。178件は引き続き不合格で、採点結果がなかった14件も不合格のままです。

論文が示す差は23.4ポイントです。表10の件数から147÷627で計算できます。丸めた表示同士を引くと69.4−45.9＝23.5になりますが、同じ数字を別の精度で丸めた違いです。E2Eしかテストがなかった4課題を除いても、合格率は38.6%から61.4%に上がりました。

同じ件数のテストを減らす比較では、12課題の396件を固定し、課題と検査の役割をそろえて38件ずつ除きました。新たに合格した件数は平均16.1件と8.0件で、E2Eを外した場合が約2倍でした。別の比較では、サーバーの一つの部分だけを調べる26課題の平均合格率は69.0%、複数の部分をまたぐ27課題は47.7%でした。課題の内容が異なるため、またぐ範囲だけの効果とは言えません。

### モデルが同じでも、実行支援を変えると結果が変わる

全53課題を実行支援ごとに3回評価しました。GPT-5.6 Solの最大設定では、mini-SWE-agentが75.5%、Codexが73.6%でした。Claude Opus 5の最大設定では、mini-SWE-agentが75.5%、Claude Codeが69.8%でした。実行支援を変えると指示、使える操作、操作回数の上限なども変わります。この結果は、2モデルの特定設定に対する比較です。モデルだけの順位や、実行支援全般の優劣は示しません。

## 自分で確かめる

リポジトリのルートから `UV_CACHE_DIR=/tmp/uv-cache uv run papers/swe-serve-inference-serving-agents/run.py` を実行します。コードはPythonの標準ライブラリだけを使い、各実装の成否を同じフォルダの `results.json` に保存します。

Labの小さな配信プログラムには4つの実装があります。まず関数を直接呼び、次に利用者向けの入口を通し、最後に同じ配信プログラムへ2件続けて要求を送ります。毎回の期待値は、送った単語がそのまま返ることです。

`local-only` は直接呼ぶと `alpha` を返しますが、入口から呼ぶと何も返しません。`state-leak` は一度目に `alpha` を返し、二度目に `beta` を送ると `alpha beta` を返します。要求ごとに配信プログラムを作り直すと、前回の状態が残る問題は見つかりません。そこで、この検査では同じインスタンスに2回送ります。

## 実験の結果

四つの実装のうち、関数を直接呼ぶ検査では3件が合格しました。利用者向けの入口を加えると2件、連続した要求を確かめると1件だけが合格します。すべてを通るのは `complete` です。

四つの実装を変えず、検査の入口と順番だけを変えました。関数の動作だけでは、利用者向けの入口が応答しない問題と、前の要求が次の応答に残る問題を見分けられないことを、この例で確かめました。

LabはSGLang、HTTPサーバー、GPU、実モデルを使いません。実際の53課題やモデル11種類の合格率、性能条件、実行支援の比較は再現していません。3件から1件への差は、論文が報告した23.4ポイントとは別です。
