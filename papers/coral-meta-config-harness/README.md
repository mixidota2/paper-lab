# CORAL：推薦の設定を予算内で見直す

MetaのCORALが数日ごとに見直すのは、利用者に毎回出す推薦ではなく、既存の推薦システムの設定です。動画サービスでは、候補を集める経路ごとに予算の倍率を変え、別のサービスでは利用者グループごとに配信方法を選びます。言語モデルが運用統計と過去の変更結果を読んで案を出すと、数値最適化がその案に近い設定を予算内で選びます。

著者が報告したA/Bテストでは、動画サービスの最終構成で配信費用を増やさず、視聴時間が0.15%、動画を見た訪問の回数が全体で0.16%増えました。別のサービスでは利用者の反応に統計的な差が出ず、対象グループを広げると費用を減らせた額が初回より44%増えました。総費用が44%下がったという意味ではありません。

[原論文（2609.02730v1）](https://arxiv.org/pdf/2609.02730v1)の参照箇所とSHA-256は[出典との対応表](mapping.md)に記した。[手法の解説](method.md)と、[サイト本文の元ファイル](lab.yaml)も読める。

## 小実験の実行方法

リポジトリの最上位で次のコマンドを実行すると、同じフォルダーの[results.json](results.json)を作り直す。

```bash
uv run papers/coral-meta-config-harness/run.py
```

実験では、人が用意した3つの提案を使う。設定値を0以上、合計を10以下にし、各設定値と提案値の差を二乗して合計し、その値が最も小さい組み合わせを求める。もとの提案が条件を満たす場合は変更しない。この計算をユークリッド射影と呼ぶ。候補が離散的な場合は、予算内の候補をすべて比べて提案に最も近いものを選ぶ。別の人工例では、元費用100、初回の削減額10として「削減額が44%増える」と何が変わるかを示す。

## 確認できたこと

この小実験で確認したのは仕組みの一部（Mechanism: PARTIAL）である。個別の結果はresults.jsonの `checks` を参照する。CONFIRMEDは確認済み、NOT OBSERVEDは観測されなかったことを示す。LLMによる提案、前回の設定が結果に与えた影響を推定できるか、人の監督を減らせるか、設定を周期ごとに見直すと改善するかは検証していない。オンラインA/Bと実際の配信費用も検証していない。予算に収めた設定で目的の値が良くなるかも検証していない。性能、規模を広げた場合の挙動、本番への適用は未検証（NOT TESTED）である。
