# ISOMORPH — 物流状態まで予測する

## overview

ISOMORPHは物流網の需要と内部状態を再生成できる予測ベンチマークである。公開例は米国13拠点・16辺。補充は固定した(s,S)ルールで行い、補充方策の優越性は主張していない。販促と欠品を含む実小売データでの予測モデル比較とも区別する。 学習方策は使わない。

## problem

需要の予測誤差だけでは、倉庫の滞留や輸送の混雑は見えない。本論文は需要、未充足需要の累積であるbacklog、需要充足率、辺の容量使用率を同じ物流網から出力する。商品数は50と200、各系列は日次7,300期。 出発点は需要である。荷物は複数の倉庫を通る。途中には容量上限がある。未充足分は残る。

## method

## 需要を固定してもネットワーク状態は変わる

状態ξには手元在庫、未着注文、輸送中の荷物、平滑化需要を含む。ξₜ₊₁ = Ψ(ξₜ, yₜ, Lₜ)として状態を進める。需要yはネットワークが処理する前に生成される（§3.2）。

到着Aは先に既存の滞留Bへ割り当てる。B′ = max(B−A,0)、OH′ = OH + max(A−B,0)。その後に新しい需要yを処理し、OHₜ₊₁ = max(OH′−y,0)、Bₜ₊₁ = B′ + max(y−OH′,0)とする（式21–22）。

供給元ではOH<sかつ未着注文がないときS−OHを注文する。中間倉庫では上流から実際に荷物を運び、容量と経路に従って詰め込む。需要予測でこの物流状態を代用できるとは限らない。

## why_it_might_work

解釈：容量だけを変えて同じ需要を流せば、需要の難しさと物流網の難しさを切り分けられる。状態変数を揃える設計は、拡張したシミュレーターでも物量保存を検査する手掛かりになる。実網への適合度は別に評価する必要がある。 まず保存則を確かめる。次に予測を評価する。

## evidence

[一次資料v3](https://arxiv.org/pdf/2605.12768v3)のTable 5では、需要のMASEはPatchTSTが0.828、TimesFMが0.847。Moiraiはbacklog 2.228、充足率1.473、辺使用率0.721で、後者3指標の最良値だった。学習済みChronos-T5、Moirai-1.1-R、TimesFM-2.0は追加学習なし。ARIMA、ETS、PatchTSTは各rollout内で学習する。

過去512日から1・7・14・30日先を予測し、時系列分割は70/15/15。Table 5は週周期m=7で正規化したMASEを予測期間間で幾何平均した値。需要と辺使用率は29 rollout、backlogと充足率は定数系列5件を除く24 rolloutである。誤差棒はrollout間の95% Student-t区間。

Table 3のbullwhip比は各拠点のVar(inflow)/Var(outflow)。日次と月次で値が大きく変わる。Forward UQはシナリオ設定の集合に予測器を適用する実験であり、実網の全不確実性を覆う保証ではない。 比較の単位はrolloutである。実店舗ではない。

## executable_understanding

`uv run papers/isomorph-supply-chain-digital-twin/run.py`

下の容量選択で、84日間の需要を固定して輸送容量だけを変える。式(21–22)の到着・滞留・新規需要の処理順を実装し、毎期の在庫と需要の保存則を検査する。ここでの当日充足率は新規需要だけを分母・分子に使う。既存滞留の解消を含む指標とは区別する。

## results

results.jsonに容量8・12・20の全経路を保存した。容量不足で増える滞留を需要系列だけからは見分けられない。小実験は予測モデルを走らせていないため、著者のMASEを再現した結果ではない。

## what_we_verified

CONFIRMED：全252ステップで物量と未充足需要の保存則が成立し、3条件の需要は一致した。PARTIAL：到着先でのサービス処理を確認した。13拠点の経路探索や荷詰めは実装していない。

## what_we_did_not_verify

Performance / Scaling / Production applicabilityはNOT TESTED。Chronos、Moirai、TimesFM、ARIMA、ETS、PatchTSTの再学習・推論、bullwhip比、Forward UQの被覆率は追試していない。「最初の公開digital twin」は著者の位置づけとして扱い、網羅的な先行研究調査では確定していない。

## implementation

run.pyは標準ライブラリだけで動く。simulate()で需要と容量の比較条件を固定し、assertで保存則を検査する。1辺・1期遅延へ簡略化した。補充の教材ルールは到着先にも(s,S)を使うため、公式の非到着先補充と同一ではない。ネットワーク図と論文値はlab.yaml、実験曲線はresults.jsonを正本とする。

## Core Idea

著者の主張：公開可能な多段階物流網から需要とネットワーク状態を再生成し、予測とシナリオに由来する不確実性を評価する。

解釈：固定方策のもとで予測対象と物流条件を動かせる点が研究地図の追加セルとなる。在庫最適化手法の勝敗とは別の評価軸である。
