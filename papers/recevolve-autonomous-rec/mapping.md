# Googleの論文とLabの人工例の対応

[著者論文 v1](https://arxiv.org/html/2609.01622v1)のどの処理を、Labのどこで説明または計算したかを示します。公開HTMLには独立した付録がなく、著者の公式コードへのリンクは本文と書誌では確認できませんでした。参考文献のautoresearchは別の実装です。提出日は[arXivの書誌](https://arxiv.org/abs/2609.01622)にある2026年7月20日を使いました。

| 論文の箇所 | Labのどこで扱うか | 確認した範囲 |
|---|---|---|
| §3、図1〜2 | 中央の担当と実験の流れを示す図 | どの担当が情報を保存し、各実験に何を渡すかを示します。実際のエージェントは起動しません。 |
| 式1〜2 | 方法の説明 | 現在の知識と実験結果を使って次の案を選ぶ仕組みを説明します。探索方策は学習しません。 |
| Algorithm 1 | `decide()` と `lifecycle()` | 辞書で状態を表し、条件を満たした案だけを残します。コードの版管理は操作しません。 |
| §5.2 | `candidate_probe()` | 同じスコアから候補数だけを変えます。論文で人間が見つけた問題を、RecEvolveが自動で検出したという意味ではありません。 |
| 表1と図3 | 構成ごとの比較 | 表1で示された累積4構成を扱います。41件すべての成績は分かりません。 |
| 表2と§5.7 | 本番の指標 | 満足度などの著者報告を読みます。Cold-Startの負の値は、新しいコンテンツが見つかるまでの時間が短くなったという意味です。 |

候補数を照合するルールはLabが追加しました。実務で比較条件を合わせるには、候補ID、選び方、評価データの版も別に確認します。
