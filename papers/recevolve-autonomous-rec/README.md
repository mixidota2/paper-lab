# RecEvolve：コンテンツ推薦モデルの改良案を出し、検証して積み重ねる

GoogleはRecEvolveで、コンテンツ推薦の候補検索モデルを改良する作業を自動化しました。エージェントが案を出して検討し、実装・学習・評価まで進めます。主指標の改善幅と補助指標の条件を満たした構成だけを残し、次の実験の基準にします。

著者は5系列を並行して約2日で41件の実験を完了しました。複数の変更を積み重ねた最終構成では、オフラインの上位50件の順位の指標（NDCG@50）が0.4796から0.5751に上がりました。本番では満足度の指標が3.77%増えたと報告しました。別の探索では、学習を改善せずに評価条件を変えただけで指標が上がりました。人間が原因に気づき、この変更を元に戻しました。

一次資料：[著者論文 v1](https://arxiv.org/html/2609.01622v1)。

## 仕組みと結果を読む

[method.md](method.md)は、どの担当が情報を持ち、何を基準に変更を残すかを説明します。[mapping.md](mapping.md)では論文の記述とLabが確認した処理を対応させています。記事と図は `lab.yaml` などから生成します。

## 人工例を実行する

リポジトリのルートで次のコマンドを実行します。コードはPython標準ライブラリだけを使い、実行ファイルと同じ場所に `results.json` を作ります。

```bash
uv run papers/recevolve-autonomous-rec/run.py
uv run paper-lab build
```

Labは同じ正例スコアを残し、比較に使う負例だけを減らしました。利用者の表現を学習し直さなくても、順位の指標が上がることを確かめる例です。別の例では、候補数が変わった実験を採択しない条件を足し、変更前の状態が残るかを確認します。この条件はLabの提案です。Googleのエージェントが比較条件の変化を自動で検知したという意味ではありません。

Labが実行したのは指標の計算と採択の判定です。著者のエージェント、TPU学習、版管理の操作、本番の満足度は再現していません。確認済みと記した項目は、人工例の結果に限ります。
