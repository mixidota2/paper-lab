# 原論文とLabで確かめた計算の対応

2026-09-23に、保存していた[原論文v1のPDF](https://arxiv.org/pdf/2609.22747v1)を確認しました。照合時のSHA-256は `3b3dc018790b6c0919e44b348ade304a935bead51794083432daf77dc2b9445d` です。

| 原論文 | Labで対応する説明や計算 | Labが行っていないこと |
| --- | --- | --- |
| §3.1・SNIPS | `snips()` は、調べたい方式と選択が一致した記録を、選択確率の逆数で重み付けします。 | 複数の表示位置を補正したり、極端な確率を切り詰めたりはしません。 |
| §3.2・式1 | `simulate()` で、対象の作品を外す場合と外さない場合を、同じ探索ログから推定します。`exact()` で設定から期待値を直接計算します。 | 候補3件、表示枠1つの人工データです。Netflixのシミュレーションではありません。 |
| §3.3・式2・付録§6.2 | 記事の図では、候補内の差と候補に入る確率を掛けます。式は `method.md` で説明します。 | 推薦の各段階を再実行したり、Netflixの実ログでHájek推定量を計算したりはしません。 |
| §4.2・図2 | 記事の根拠欄で、ホーム画面から行を外した11件のA/Bテストと、オフラインの行単位の貢献の比較を説明します。 | 11件の元の座標は入手しておらず、散布図やR²は再計算していません。 |
| §4.3・図3 | 著者が作品Aのラベルの誤りを見つけた手順を図にしました。 | 障害のログや、修正後の回復量は検証していません。 |

論文とarXivの書誌を確認した範囲で、公式コードを入手できるリンクは見当たりませんでした。Labは著者コードを実行していませんが、コードが非公開であると確認したわけではありません。
