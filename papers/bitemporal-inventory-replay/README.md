# 報告が後から届くときの在庫の再計算

同じ3日目の在庫でも、何日目までに受け取った報告を使うかで答えが変わります。Labは、一つの商品に対する5件の報告と3件の将来予定を使い、報告を選び直したときに在庫と売り逃しがどう変わるかを計算します。

`run.py` を別のフォルダへコピーし、`python run.py` を実行すると、同じフォルダに `results.json` が出力されます。標準ライブラリだけで動きます。`results.json` の `cases` に、採用した報告、過去と将来の在庫の推移、最終的な5項目があります。

- `method.md`：報告を選ぶ順番と、コードを置く位置による違い
- `experiment.md`：合成例の報告と将来予定、ブラウザーで切り替えられる結果
- `mapping.md`：論文とLabで確かめたことの対応

在庫の推移は決められた数量から計算します。需要を予測したり、LLMの正答率を再測定したりしたわけではありません。[原論文v1](https://arxiv.org/html/2611.14671v1)は、同じ種類の計算をどこまでモデルに任せるかを比較しました。
