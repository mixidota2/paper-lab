### 同じ利用者の履歴から、動画と投稿者の関心を別々に取り出す

HGenPushは、フィードでの長期・短期の行動、クリックした通知、送った通知の履歴を読みます。年齢などの利用者の特徴も加えます。入力の末尾に投稿者用と動画用の目印（`[cls]`）を置き、一つのデコーダーで処理した後、その二つの位置から関心の表現を読み出します（§3.1）。主な実験設定ではデコーダーは16層、表現の幅は512です。各層は、手前の情報だけを読む自己注意、RMSNorm、SwiGLUを使います（§3.1.2・§4.1.4）。

動画経路は、動画の内容を細かさの異なる3段のコード（SID）で表します。投稿者経路では、まず投稿者IDやマルチモーダルな特徴をベクトルにします。著者はクリックを使い、利用者の関心と、その利用者が反応した動画の投稿者の表現を近づけます。同じ学習用バッチの別の投稿者と取り違えにくくなるように、対照損失のInfoNCEを使います（式16）。

著者はこの投稿者のベクトルをRQ-Kmeansで2段のコードに変えます。第1段で最も近いコードを選び、第2段でそれだけでは表せなかった差を埋めます。コードの使用が一部に偏るのを抑えるため、学習にSimVQを使います。動画側は3段、投稿者側は2段で、どちらも各段に8,192個のコードがあります（§3.2.2・§4.1.4）。

投稿者経路の出力は、投稿者の2コードだけではありません。その後ろに動画の第1段のコードを足した `(author₁, author₂, video₁)` です。利用者が好む投稿者を表すコードの範囲で、どの種類の動画を候補にするかも絞れます。最終的に候補になるのは投稿者ではなく動画です。

### 前のコードに応じて次を選び、大きなデコーダーは回し直さない

各経路は、先に計算した利用者の関心を、コードの生成中は固定します。k番目のコードを選ぶときには、すでに出したコードの埋め込みを関心の表現に足します。k番目専用の小さなニューラルネット（FFN）が、その和を使って次のコードの確率を求めます（式14）。後のコードの確率は、どのコードを前に選んだかで変わります。

学習時は正解のコード列が分かっているため、各段のFFNへ正解の先行コードを渡し、並行に計算できます。本番で候補を作るときは正解がないので、途中まで作った有力なコード列をビーム探索で残し、それぞれを伸ばします。各段を独立に予測するのではなく、コード列への依存を残したまま、大きなデコーダーによる履歴の読み直しを省きます。

### クリック後の行動を報酬にし、動画ごとのコード列を学習する

UCPAは、通知をクリックした後のセッションで、利用者が各動画にどう反応したかを報酬にします。著者は、当てはまった行動ごとに点を足します（式20）。

| クリック後の行動 | 点 |
| --- | ---: |
| 有効な再生、プロフィールを開く、コメント欄に滞在する | 各+2 |
| いいね、フォロー、共有、コメント | 各+1 |
| 短時間で再生をやめる | −2 |
| 低評価 | −5 |
| 通報 | −10 |

同じセッションで利用者が見た動画を1組にし、実験では1組を最大50件に制限しました。各動画の報酬から組内の平均を引き、標準偏差で割ります。これで、同じ組のほかの動画に比べて反応が良かったかを表します（式21）。標準偏差が0の場合の処理は、本文からは分かりません。

GSISPOでは、各段のコードを選ぶ確率を、学習前後のモデルで比べます。各段の確率比の幾何平均を動画のコード列全体の重みとし、設定した下限と上限に収めます。その重みに学習の勾配を流さず、標準化した報酬と、その動画のコード列を出す対数確率に掛けます（式22〜24）。著者は、クリックで選ばれた動画のコードを学ぶ損失も残しており、強化学習の目的に別のKL項を加えていません。
