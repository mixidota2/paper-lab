# 原典と実装の対応

| 原典 | 自作コード | Labで確認できる範囲 |
| --- | --- | --- |
| §2 MNL・最終品揃え後悔 | probabilities / revenue / oracle | 非購入の重みを1とし、既知の収益と独立した顧客の観測を前提にします。oracleはkを変えながら上位k商品の期待収益を計算し、最も高い値を求めます。 |
| §3 Theorem 3.1 / Corollary 3.2 | component_a | コードはすべての区切り（cut）と、値が最小になる区切りをすべて返します。テストは有限個の部分集合を照合するもので、上限（supremum、上界のうち最小のもの）の証明ではありません。 |
| §5 Theorem 5.1 式(2)(3) | b_choice / component_b | `(3a,2a,a)` では最大直径を最小にする分割は `(k,l)=(1,2)` です。コードは二項分布を使って、購入回数ごとの確率を厳密に足し合わせます。 |
| §6 Theorem 6.1 式(5)–(7) | c_choice / component_c | d=2では4群に1点ずつ入るので、丸めても収益は変わりません。コードは2種類の品揃えを同じ回数だけ観測した結果で判断します。余った観測は使いません。 |
| Lab独自比較 | integrated_case / generate | Labは4通りの選好を含む96条件を比較します。未知の選好全体から最悪の条件を探して方策を決める、一般のminimax問題は解きません。 |
| 画面 | interactive.js / paper_lab.assortment_observation | 画面は保存済みの期待収益と期待後悔を表示します。観測例を選んだときは、方策がその結果をどう使って品揃えを決めるかを表示します。方策には選好を渡しません。 |
