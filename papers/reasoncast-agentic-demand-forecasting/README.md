# ReasonCast: Agentic Demand Forecasting with Selective Semantic Reasoning

祝日やセールの情報を、いつ使えば需要予測の誤差を減らせるか

Yangらは、Chronos-2 smallの需要予測をそのまま使うか、イベントの情報で補正するかを選ぶ方法を提案しました。公開データM5のイベント期間では比較手法より誤差が小さく、非公開データの平常期では補正を見送って元の予測を保ちました。

## 論文の概要

Yangらは、祝日や大型セールなどの情報を、次の7日間の需要予測に使うかどうかを選ぶ方法を提案しました。ReasonCastは、販売の履歴を読むChronos-2 smallを土台に、イベント情報を使わずに予測を返すか、手元の情報で補正するか、ツールで情報を調べて補正するかを選びます。祝日と大型セールでは補正を見送らない決まりです。

著者らは、過去の販売データを使い、公開データM5のイベント期間と、非公開のECデータを評価しました。M5のイベント期間で、実績の合計に対する絶対誤差の割合（WMAPE）はReasonCastが32.63%、比較手法で最も低かった追加学習済みChronos-2 smallが33.10%でした。非公開データの平常期では、毎回補正する方式の誤差が9.59%だったのに対し、補正を見送ったReasonCastは元の予測と同じ7.91%でした。発注や在庫が改善されたか、運用にかかる時間と費用は、これらの比較では分かりません。

## イベントをいつ予測に使うか

販売数の履歴だけでは、今年の祝日や大型セールで需要がいつ変わるかは分かりにくい場合があります。一方、需要が安定しているときに関係のない情報を加えると、予測がかえって外れることがあります。著者らは、イベントの情報を使うかと、使う場合に予測をどれだけ変えるかを別々に決めました。

非公開のECデータは、最も細かい商品カテゴリごとに毎日の販売数を集計した15,696系列です。一つの商品を一店舗で売った数ではありません。著者らは、予測時点までに分かる情報だけを使い、次の7日間を予測しました。

## 補正しないときに元の予測が変わらない理由

ReasonCastは補正しない場合、補正の強さを小さく調整するのではなく、補正を止めて元の予測を返します。補正する場合は、予測器の内部表現のうちイベントに対応づけた成分がテキストを参照します。ただし、テキストから得た変化をそこへ投影し直しません。イベントだけに影響がとどまるとは言えず、イベントによって販売数がどれだけ変わったかという因果効果も分かりません。

著者らは、まずChronos-2 smallで数量を予測し、Qwen3-32Bでイベントの情報をどこまで使うかを決めました。補正する場合は、日ごとの動きと予測の水準を別の処理で調整します。

補正を見送れば元の予測を変えない設計により、平常期に不要な補正を持ち込まずに済みます。導入を検討するときは、欠品で売上に表れなかった需要を区別し、予測誤差が減るかと、発注や在庫の費用が減るかを別々に比べる必要があります。

## ReasonCastの処理とLabで扱う式

### どの情報で予測を補正するかを決める

Chronos-2 smallは、過去の販売数から次の7日間の予測を出します。Qwen3-32Bは、その予測と不確かさ、その時点までに分かっていた祝日やセールの記録を読み、次のうち一つを選びます。

- Skip：イベント情報による補正を行わず、Chronos-2 smallの値を返します。
- Basic：手元にある情報から、どのイベントが関係するか、需要がいつ、どの方向に、どの程度動くかを整理し、補正に使います。
- Tool：検索や時系列の統計も使ってイベントの情報を整理し、補正に使います。

著者らは祝日と大型セールではSkipを選べないようにしました。イベントの情報を与えても、すべての予測で改善するという保証はありません。

### イベント情報を整える訓練と、予測誤差を使う訓練を分ける

著者らは最初に、Claude Opus 4.6が作った例を使い、Qwen3-32Bが指定された形式で答えるように学習させました。その後、需要の変化の方向、日ごとの形、変化の大きさ、ピークを採点し、強化学習で回答を調整しました。

著者らはこのモデルで訓練例を作り直し、イベントの説明と販売履歴の表現を対応づけ、予測器の補正部分を学習させました。最後は予測器を固定し、補正による予測誤差の変化、補正で悪化した場合の罰点、ツールの利用費用を使って、Qwen3-32Bに経路の選び方とイベントの説明を学習させました。実績は学習や検証に使い、予測を出すときの情報には含めません。

### 予測器の中で日ごとの形を変え、出力後に水準を変える

著者らはQR分解で得た直交基底 `Q` から、射影 `P = QQᵀ` を作りました。予測器の内部表現 `H` を、イベント情報を参照する成分 `Hᴱ = HP` と、それ以外の成分 `Hᴺ = H(I−P)` に分けます。両方を足すと元の `H` に戻ります。後者はテキストを参照しません。

式8では、テキストを参照して得た変化 `ΔH` を、`H̃ = Hᴺ + Hᴱ + mαgΔH` で内部表現に足します。その変化を同じ部分空間に投影し直さないため、補正自体がイベントの部分空間だけに収まるとは言えません。式11では、内部表現から求めた予測値に `exp(mβgρ)` を掛け、予測の水準を調整します。

`m` はテキストを使うかを表し、`g` は予測ごとの補正の強さです。Skipを選ぶか、テキストがなければ `m=0` になります。その場合は内部表現への加算が0、出力に掛ける値が1となり、Chronos-2 smallの予測を変えません（式12）。

一次資料：[ReasonCast v1の第4節・図1・付録B](https://arxiv.org/html/2608.15291v1)。

### Labは補正の式を、7日分の数字で確かめる

Labは、元の予測 `b`、足す値 `a`、倍率の対数 `l`、補正の強さ `g` を受け取り、各日について `(b + g*a) * exp(g*l)` を計算します。論文はモデルの内部表現へ加算しますが、Labでは予測値に直接足します。モデルの学習や検索を再現する実験ではありません。

Labは実績 `y` を、補正でなく誤差の測定にだけ使います。Skipでは、補正せずに元の予測をコピーします。論文と異なり、祝日の例でもSkipを選べます。以前の固定例でのBasicとToolも名称に対応する固定の計算で、モデルや検索は動きません。

### 誤差を比べ、実績がゼロの場合も区別する

WMAPEは、日ごとの絶対誤差の総和を、実績の合計で割って100を掛けます。過大予測と過小予測は相殺しません。画面は、補正した予測と元の予測のWMAPEの差をポイントで示します。差が負なら補正したほうの誤差が小さいという意味です。実績が7日ともゼロならWMAPEは計算できないので、保存値は `null` です。絶対誤差の平均であるMAEは実績合計で割らないため表示します。

元の予測が毎日10で、実績が毎日20の例では、補正なしのWMAPEは50%、2倍の補正を強さ1で使うと0%、強さ0.5では約29.289322%です。実績が毎日10なら、同じ2倍の補正で0%から100%に悪化します。実績が3日目に増える例では、補正を4日目にずらすと、誤差が12.5%から25%に増えます。以前の固定例では、実績が動かない日にBasicで補正すると0%から20%に増える条件もあります。

### 入力を確かめ、保存結果を読み込んだときは再計算する

画面は7日分でない配列、数値でない値や無限大、負の実績、0から1を外れた補正の強さを受け付けません。カンマ、読点、空白で区切れますが、連続した区切りや末尾のカンマでできた空欄を0として扱いません。

Labは結果を行ごとに計算します。指数が大きすぎて計算できない行は「計算不能」とし、その曲線を表示しません。最大の強さの補正を計算できなくても、Skipの元の予測は変わりません。負の予測が一つでもあれば、元の予測も含めて警告します。負の値を0に直すことはありません。

保存ファイルにはschema 2、教材の識別子、仕様版2.0.0、原論文の版、誤差の計算規約を記録します。読み込むときは形式と版を確かめ、`inputs` を検査して、現在の教材で再計算します。保存された `output` や説明文は、そのまま正解として使いません。旧schema 1や未知の仕様版は受け付けません。

## 著者らが測った予測誤差

### 著者らは、ECの詳細カテゴリと、M5の商品で別々に評価した

著者らは、非公開のECデータで、詳細カテゴリごとの日次販売数を15,696系列使いました。2024年8月10日から2025年8月31日を学習、2025年9月1日から10月31日をモデル選択、2025年11月1日から2026年5月30日を評価に使いました。評価対象は7日分の予測を出す15期間で、祝日が10、大型セールが3、平常期が2です。公開データM5では、10店舗の販売数を商品ごとに合計した3,049系列について、イベント前後の7日間を14期間評価しました。予測を出す時点で分かっていたカレンダー、イベント、価格の情報を使っています。

### M5では最良の比較手法より0.47ポイント低く、平常期では元の予測を保った

WMAPEは、評価対象の絶対誤差をすべて足し、実績の絶対値をすべて足した値で割る指標です。M5のイベント期間では、ReasonCastが32.63%、追加学習していないChronos-2 smallが34.40%、最も誤差の小さかった比較手法のChronos-2 small（Multi-FT）が33.10%でした（表2）。ReasonCastと最良の比較手法との差は0.47ポイントです。

非公開のECデータで祝日の影響を受けやすい詳細カテゴリでは、ReasonCastが39.10%、Chronos-2 smallが55.42%、最良の比較手法のChronos-2 small（Uni-FT）が42.39%でした。この値を、M5の商品単位の結果と同じ分母で比べることはできません。大型セールの影響を受けにくいカテゴリでは、ReasonCastのWMAPEは最小でしたが、MAEはPatchTSTの方が小さくなりました。

非公開データの平常期2期間では、常にイベント情報で補正するReasonCastのWMAPEが9.59%でした。一方、補正を見送る経路を通したReasonCastは、元のChronos-2 smallと同じ値を返し、WMAPEは両方とも7.91%でした（表3）。これは、イベントがあって補正を選んだ場合にも、すべての予測で誤差が小さくなるという結果ではありません。

著者らが比較したのは予測誤差です。イベントの因果効果や、発注、在庫、欠品への影響は測っていません。ツール呼び出し頻度、予測を出すまでの時間、実際の推論費用も、論文は全体を報告していません。

一次資料：[ReasonCast v1の第5〜6節・表2・表3](https://arxiv.org/html/2608.15291v1)。

大型セールの影響が大きいカテゴリでは、ReasonCastが20.89%、最良の比較手法のChronos-2 small（Multi-FT）が22.14%でした。差は1.25ポイントです。祝日で影響が大きいカテゴリでは42.39%に対する39.10%で、差は3.29ポイントです。平常期で補正を常に使う場合と使わない場合の差は1.68ポイントです。

別の検査で、著者らは同じ販売履歴とモデルを使い、イベント情報の項目と傾向の説明を逆にしました。予測誤差が大きくなったのは15期間中13期間でした。訓練後の補正が、誤った説明の影響をすべて防ぐとは言えません（第5.8節）。

## Labで人工の7日間を試す

Labの画面は実績、元の予測、補正に使う値を分けて受け取ります。同じ7日分の実績に対して、元の予測、最大の強さで補正した予測、指定した強さで補正した予測を並べます。値を変えると表とグラフが更新されます。補正の計算には実績を渡さず、出来上がった予測の誤差を計算するときにだけ使います。

## 正しい補正と不要な補正の差

元の予測が毎日10、実績が毎日20の例では、補正しない場合のWMAPEは50%です。毎日の予測を2倍にする補正を強さ1で使うと0%、強さ0.5なら約29.289322%になりました。逆に実績が毎日10なら、同じ2倍の補正によって0%から100%に悪化します。以前の固定例にも、不要なBasicで0%から20%に悪化する条件があります。いずれも、補正のもとになる情報が正しいかをLabが設定した人工例です。

## Labが確認したこと

Labは、実績が0だけの場合、負の予測、入力が不正な場合を区別しました。人工例では、誤差、補正の強さを半分にした場合、間違った補正、イベント日のずれを手計算と比べました。Skipでは補正せず元の予測を使います。検証は教材の計算に限り、原論文の仕組みの一部です（PARTIAL）。この計算の検査では、画面の表示、キー操作、ファイルの書き出しは調べていません。

## Labが確認していないこと

LabはChronos-2やQwen3-32Bを実行していません。検索、直交射影、経路の学習、強化学習は再現していません。売上から欠品時の需要を推定できるか、販促や品切れの費用を減らせるか、件数を増やしても使えるかは未検証です（NOT TESTED）。

## Labの計算

ブラウザーの `model.js` と、Pythonの `evaluate()` は、予測値に加算してから倍率を掛ける式 `(b + g*a) * exp(g*l)` を計算します。論文の式8はモデルの内部表現に加算しますが、この教材は出力に直接足します。以前の固定例にあるBasicとToolは名称に対応する固定計算で、言語モデルや検索は動きません。同じ入力には同じ結果を返します。
