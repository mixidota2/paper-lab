# Harness-Zero：外から点検していた手順をモデルに教える

Yeらは、エージェントの外側で点検していた手順を、モデル自身に学ばせられるかを調べました。Harness-Zeroでは、別のエージェントが元の提案を実行前に読み、そのまま使うか、実行できる別の手順に直すかを決めます。著者らは採用した応答を含む成功記録でQwen3.5-9Bを追加学習しました。評価時は点検役と強化版の支援を外し、固定の指示文とBashを使う最小環境を残しました。

三つの領域で別々に学習したモデルを同じ最小構成で比べると、評価値の平均は23.3%から44.3%に上がりました。元のモデルに強化版の支援を付けた場合の41.7%も上回りました。一方、USPTOでは学習後の最小構成が30.0%で、元のモデルに強化版の支援を付けた38.0%に届きませんでした。44.3%は各領域を同じ重みで平均した値で、全課題を合算した成功率ではありません。

## 研究が扱う問題

モデルの外側の仕組みは、使うツールや残す記録、どこで結果を点検するかを決めます。ただ、その仕組みをどの実行環境にも持ち込めるとは限りません。点検役だけが使えるツールの呼び出しを覚えさせても、学習したモデルが最小環境に戻ると、その操作は実行できません。

## 著者らの方法をどう読むか

著者らは、モデルを外から支援する仕組み（ハーネス）が教える手順を、採用した応答の履歴に変えました。モデルをその履歴で学習させ、評価時は強化版の支援、点検役とその参照資料を外し、最小の実行環境だけを使いました。

この研究が変えるのは、モデルの重みと、評価時に外から与える支援です。SWE-Serveの実行環境の比較、FlashVectorの配信の改善、AURAの推薦品質の診断とは、変える対象が異なります。ベンチマークの差を、本番のA/Bテストや費用削減の結果にはできません。

## 教えられる可能性がある手順

点検役が、モデルの使える手段に合わせて手順を直せば、学習時と評価時の操作がそろいます。たとえば変更の前に状態を見たり、変更した後に結果を確かめたりする手順を、記録から学べる可能性があります。一方、分野固有の知識や、専用ツールが担う検査まで、同じデータ量で覚えられるとは限りません。

## 著者らが比較した結果

[一次資料：原論文の表2と4](https://arxiv.org/pdf/2609.24974)。表計算とUSPTOは一回の試行の成功率、AppWorldは課題が定めた目標の達成率です。

| 著者らが比べた構成 | 表計算（SpreadsheetBench） | AppWorld | USPTO | 3領域の等重み平均 |
| --- | ---: | ---: | ---: | ---: |
| 元のモデルと最小環境h | 31.0% | 26.8% | 12.0% | 23.3% |
| 元のモデルと強化版h★ | 39.0% | 48.2% | 38.0% | 41.7% |
| 追加学習したモデルと最小環境h | 44.0% | 58.9% | 30.0% | 44.3% |

同じ最小環境では、学習後の平均は元のモデルより21.0ポイント高くなりました。元のモデルに強化版を付けた場合と比べても、平均では2.6ポイント上回りました。ただし、USPTOの比較では38.0%に対して30.0%と低くなりました。

表4では、著者らは強化版を使ったときだけ元のモデルが行った28種類の行動を調べました。行動ごとに対象課題を選び、追加学習したモデルがその行動を取った割合を平均すると82.3%でした。28件のうち何件を実行できたかという値ではありません。

## 点検と学習の手順

### 点検役が実行前に提案を採用するか決める

著者らはKimi K3を使い、元のモデルを外から支援する手順を備えたハーネスを作りました。この強化版を論文ではh★と呼びます。著者らは、その手順や制約を点検役が読む参照資料Kにまとめました。点検役はGPT-5.6 Solです。教わる側のQwen3.5-9Bは、固定の指示文とBashを使う最小環境hで応答を提案します。

点検役は、提案がまだ実行されていないときに読みます。提案をそのまま使う場合はPASS、実行できる別の手順に直す場合はREPLACEを返します。式(3)では、元の提案をyₜ、置き換えた応答をzₜとし、PASSなら採用応答ỹₜはyₜ、REPLACEならzₜです。実行するのは採用した応答だけです。次にモデルが読む履歴には、採用した応答とその実行結果を入れます。見送った提案や点検役の内部のやりとりは入れません。

### 成功した履歴を使ってモデルに手順を教える

著者らは成功した履歴を残し、表計算487件、アプリ操作282件、USPTO500件を使いました。領域ごとにQwen3.5-9Bを分けて学習させ、各データを2周使ってLoRAで重みを調整しました。式(4)の損失はL = −Σ log πθʰ(ỹₜ|cₜ)です。採用した応答を次に出す確率が低いほど、損失は大きくなります。ただし置き換えた応答に点検役の視点で書いた推論が入り込む場合は、その部分を損失に入れません。点検役自身の説明をモデルに模倣させるためではありません。

評価時には、学習したモデルと最小環境hだけを使います。支援を強化したh★、参照資料K、点検役は使いません。最小環境まで取り外したわけではありません。

### 教材は採用した応答だけを残す

Labは、点検役が示した結果を与え、採用した手順の文字列が実行対象と学習用履歴に残るかを確かめます。実際のコマンドは実行せず、学習や点検役の判断も行いません。確率を0.2と0.8にした場合の損失は、二つの値を式に入れて計算します。

## 教材で手順を確かめる

`uv run papers/harness-zero-distillation/run.py` で、同じフォルダの `results.json` を作れます。コードは、点検役がPASSまたはREPLACEを返したと仮定し、どの手順を実行対象と履歴に残すかを表示します。手順は文字列なので、実ファイルの読み書きやコマンド実行はしません。別に、採用応答の確率が0.2と0.8のときの損失を計算します。

## 教材の結果

上書き案を置き換える例では、元の上書き案が学習用の履歴に入らず、先にバックアップしてセルA1を編集する案だけが残りました。負の対数尤度は、応答の確率を0.2から0.8に変えると約1.609から0.223に下がります。仮定した確率の計算であり、モデルが学習で手順を覚えた結果ではありません。

## Labが確かめたこと

**仕組み：一部確認（PARTIAL）。** Labは、採用された手順だけを実行対象、モデルが読める履歴、学習の対象に残します。見送った案が入らないことを架空の例で確かめました。

## Labが確かめていないこと

Labは、外側の支援の作成、言語モデルによる点検、点検役の推論を損失から除く処理、LoRA学習、28種類の行動の評価を試していません。点検役を外しても能力が保たれるか、配信性能や規模を広げたときの挙動、本番での効果も未検証です。

## コードを読むときに見る箇所

`collect()` は式(3)に対応するPASSとREPLACEを処理し、学習するモデルに見せる応答を返します。`nll()` は式(4)の応答一つ分の損失を計算します。どちらもPythonの標準ライブラリだけで動きます。モデルの重みを変えたり、点検役が内部で書いた推論を伏せたりはしません。
