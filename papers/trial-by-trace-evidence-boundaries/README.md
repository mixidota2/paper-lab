# Trial by Trace：成果物と実行基盤を別々に確かめる

エージェントが別の手順で仕事を終えれば、途中で処理の失敗が誤って伝わっても、成果物だけは正しい場合があります。この教材は、成果物を調べた結果と、エージェントを動かす仕組み（実行基盤）を調べた結果を別々に入力できるようにしています。[論文v1](https://arxiv.org/html/2610.32285v1)の規則の一部を使い、著者の実装は動かしません。

## 画面で比べる

成果と実行基盤にそれぞれ2項目あり、どちらも2項目目は合格に固定しています。基盤の1項目目を「状態2：仕組みを使わなかった」にし、成果の1項目目を合格と不合格で切り替えてください。成果の全項目を満たした場合だけ、基盤の状態2も合格になります。

成果の2状態、基盤の4状態、3個のチェック欄のオン・オフで64条件を試せます。チェック欄は、記録がそろっているか、元の結果が隠れたか、事前に決めた候補の条件に合うかを仮定する欄です。実際の記録は読みません。候補として扱う組は一つです。

## 全64条件を計算し直す

リポジトリでは `uv run --locked python papers/trial-by-trace-evidence-boundaries/run.py`、配布ディレクトリでは `uv run --no-project python run.py` を実行します。PythonからNode.jsのテストを呼び、計算に通ると `results.json` が更新されます。外部APIも乱数も使わず、依存関係やブラウザーを自動でインストールしません。

自動テストは、64条件の計算、誤った入力の扱い、選択に応じた表示と初期化を確認します。表示の検査には画面の代用品を使います。著者の実験の再現、原因の裏付け、実ブラウザーや読み上げでの動作は、この教材のローカルテストでは確認していません。
