# Trial by Trace：完成物と実行基盤を別々に採点する

正しい完成物ができても、途中で処理の失敗が正しく伝わったとは限りません。この教材では、エージェントが出した成果と、エージェントに情報を渡す実行基盤を別々に採点します。[原論文](https://arxiv.org/html/2610.32285v1)の規則を小さな例に当てはめたもので、著者の実装や実験を再現したものではありません。

## 画面で試すこと

成果と実行基盤にそれぞれ2項目あります。各層の2項目目は合格に固定し、画面では1項目目だけを変えます。まず実行基盤を「2：仕組みを使わなかった」にし、成果を合格と不合格で切り替えてください。同じ基盤の状態でも、成果を全項目満たした場合だけ基盤の項目が合格になります。

成果2状態、実行基盤4状態、チェック欄3つのオン・オフを組み合わせると、2 × 4 × 2³ = 64条件になります。チェック欄は実際の記録を調べた結果ではなく、教材に与える仮定です。扱う候補関係は1組に限ります。

## 手元で結果を再計算する

リポジトリでは `uv run --locked python papers/trial-by-trace-evidence-boundaries/run.py`、配布ディレクトリでは `uv run --no-project python run.py` を実行します。Node.jsが必要です。モデルの呼び出しや乱数は使わず、依存関係やブラウザーを自動でインストールすることもありません。
