成果物が正しくても、途中の結果は正しく伝わったか

処理が失敗したのに成功と伝わっても、エージェントが別の手順で仕事を終えれば、成果物は正しくなる場合があります。この教材では、成果物の合否と、エージェントを動かす実行基盤（Harness）の合否を分けて扱います。

得点の決まり方

1. 記録を照合する → 2. 成果と基盤を採点する → 3. 候補の条件を確かめる → 4. 証拠から原因を確認する

得点は S=50 pA/nA + 50 pH/nH。成果と基盤それぞれで、合格した割合に50を掛けます。両方の全項目が合格したときだけ100点です。記録の不備だけで基盤に欠陥があるとは判断しません。

状態2の扱い

Trial by Trace v1の§3.4の表4・式3と§3.5の式4・6を使った教材です。基盤に仕組みがないか、その仕組みを使う処理まで進まなかった場合を、著者は状態2としました。成果が全項目に合格すれば、基盤のその項目も合格（1）になります。成果に一つでも不合格があれば、基盤のその項目は0です。採点表が別でも、この判定には成果が影響します。

条件を切り替える

成果と基盤にそれぞれ2項目あり、どちらも2項目目は合格に固定します。1項目目の判定と、チェック欄の仮定を選ぶと、下に点数が出ます。割合は教材の各2項目のうち合格した割合です。実際のモデルや採点器を動かした結果ではありません。

成果 100%／基盤 50%／総合 75点
成果は全項目に合格したか：はい
成果と基盤はともに全項目に合格したか：いいえ
基盤に不合格の項目があるか：はい
元の結果が見えなかった項目を除いても、基盤に不合格が残るか：はい
基盤の失敗が成果に影響したかを調べる候補：該当なし
実際に失敗が伝わったか：未検証

元の処理の結果が別の処理に隠れても、採点ではその項目の不合格を残します。基盤が原因だったかを調べるときは除きます。一方、調べる候補を選ぶときは除く前の不合格を使います。候補になっただけでは、基盤の失敗が成果に伝わったとは判断しません。

限界

この教材は原記録を読まず、途中の情報の変化や出来事の順番を確かめません。基盤の項目が0でも、欠陥があると確かめたわけではありません。著者の実験、モデルの性能比較や実務での効果は検証していません。

実装

得点を計算するコード・全64条件。自動テストでは条件の変更と初期化も確認します。記録と実行が対応しない設定では採点を保留します。64条件は成果の2状態、基盤の4状態、3個のチェック欄のオン・オフを組み合わせた教材の件数です。
