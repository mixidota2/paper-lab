# DeepStock：目標在庫と需要の係数を使う発注モデル

## Overview

DeepStockは、発注量を決める強化学習モデルに、在庫管理で使われてきた考え方を組み込む方法です。モデルが需要の履歴や予測を使って目標在庫を求め、その目標から手元の在庫と入荷予定の合計を引きます。不足分があれば発注します。著者は発注量を直接出すモデルと比べ、学習の設定を試せる回数が少ないときに、この仕組みの効果が特に大きいと報告しました。

AlibabaのTmallでは2025年4月、実際に導入した方法と、同じ月の発注の見直し間隔と入荷にかかった日数を使って従来法を動かしたシミュレーションを比べました。在庫回転日数は海外商品で1日、国内商品で2日短く、欠品率にははっきりした差がありませんでした。従来法の数値は試算で、実店舗や倉庫で両方式を無作為に割り付けて測ったものではありません。

## 問題設定

商品が欠品すると、売れなかった分は販売記録に残りません。著者は商品が売り切れた時刻からその日の需要を推定し、この推定をモデルの学習に使いました。推定が外れたときに発注量がどれだけ変わるかは、Labでは調べていません。

商品によって販売規模、発注から入荷までの日数、発注を見直す間隔は異なります。Tmallの実験では、著者はこうした違いを含む190次元の特徴を使いました。著者は、この条件でモデルが発注量を直接出すと、学習や学習設定の選択が不安定になりやすいと説明しています。

## 発注モデルの出力

Baseでは目標在庫から、手元の在庫と入荷予定の合計を引きます。在庫が目標に足りなければ、不足分だけを発注します。Coeffでは需要の履歴や予測にそれぞれ係数を掛けて足し、発注量を求めます。Bothは二つを組み合わせ、係数を掛けて足した結果を目標在庫にします。モデルはどの方式でも現在の在庫などを入力に取ります。著者は、モデルの出力によって変換の影響を打ち消せるため、表せる発注ルールの範囲は狭まらないと説明しています。

DeepStockは、在庫などの入力から発注量を決めるニューラルネットワークを強化学習で訓練します。大規模言語モデル（LLM）は使いません。SabreAgentは、設計時にLLMを使い、運用時は設計済みの数理最適化で発注します。InvEvolveは、LLMで人が読める発注コードを書き換え、候補を検証します。

## 発注量を計算する式

手元と入荷予定の在庫が合わせて18個あり、ネットワークが24を出したとします。Noneは24を発注量として扱うので24個を発注します。Baseは24を目標在庫として扱うので、足りない6個だけを発注します。総在庫が30個なら、同じ目標では追加発注はありません。

式では、在庫の状態を `I`、それ以外の特徴を `x` と書きます。`tot(I)` は手元の在庫と入荷予定の合計です。ネットワーク `μ` は `I` と `x` を入力に取り、方式に応じて数を1つ、または係数を複数返します。計算後の発注量が `q` です。

```text
None:  q = μNone(I, x)
Base:  q = max(μBase(I, x) − tot(I), 0)
Coeff: q = μCoeff(I, x)ᵀ f
Both:  q = max(μBoth(I, x)ᵀ f − tot(I), 0)
```

CoeffとBothは、過去の短期・長期需要、予測した短期・長期需要、定数1を並べた `f=feat(x)` を使います。モデルが返した係数を順に掛けて足し、Coeffはその合計を発注量に、Bothは目標在庫にします。原論文の導入部pp.3–4に沿い、LabはCoeffに切り上げや下限を追加していません。図と逆算の実験では、発注量が負にならない出力を使っています。

著者は入力を正規化して、販売規模の異なる商品で同じ発注モデルを使います。Coeffを使う計算では、正規化した入力から求めた係数を需要特徴に掛け、発注量を商品の需要規模に合わせます。Labは発注量を計算する式だけを実装しており、正規化やネットワークの学習は含みません。

## この方法で学習しやすくなる理由

BaseとBothでは、手元の在庫と入荷予定の合計が目標在庫に達すると、発注量は0になります。Coeffでは同じ係数でも、需要を表す入力が変わると発注量が変わります。著者は、こうした仕組みがあると、在庫管理に沿った発注を学習中に試しやすくなると説明しています。Fig. 3では、著者が作った人工環境で、Baseを使うDDPGは、価値関数が満たすべき式からのずれ（Bellman誤差）が小さくなりました。

ネットワークの出力は在庫状態によっても変わります。図では出力を固定しているため、実際に学習した方策が、在庫が増えるたびに発注を減らしたり、需要が増えるたびに発注を増やしたりするとは限りません。

## 論文の評価と導入結果

著者の評価と導入結果の一次資料は、[原論文のTable 1・2と§4](https://arxiv.org/pdf/2603.19621v1)です。Labは著者と同じデータで検証していません。欠品率は欠品と判定した日の割合で、売り逃した個数の割合ではありません。在庫回転日数は、各日の終わりに残った在庫の平均を、1日あたりの平均販売数で割った値です。

オフライン評価のTable 1では、著者がDDPG Bothを基準に各方式を比較しました。DDPG Noneは欠品率が10.10ポイント高く、在庫回転日数が6.13日長い結果でした。DS Noneは欠品率が2.10ポイント高く、在庫回転日数は1.25日短くなりました。DS Baseも欠品率が2.18ポイント高く、在庫回転日数は2.81日短くなりました。著者は、欠品率が1ポイント下がる改善を、在庫回転日数が2日短くなる改善と同じ重さで評価して、DDPG Bothを選びました。両指標で最良だったという意味ではありません。

2024年7月、Alibabaは改善の余地が大きい海外商品を選び、対象の10%に新しい発注方法を導入しました。著者は、導入群の前後差から残り90%の前後差を引く差の差分析で、在庫回転日数が9.53日短くなったと報告しました。欠品率の差は論文で「−0.83%」と表記されています。対象を無作為に選んでいないため、全商品に同じ結果を当てはめることはできません。

2025年4月、Alibabaは同社が在庫を持つ海外商品の100%と国内商品の87%に導入しました。著者は旧方式を続けた場合の在庫を、その月に実際にかかった入荷日数と発注の見直し間隔を使ってシミュレーションしました。実際の新方式は、この試算より在庫回転日数が海外商品で約1日、国内商品で約2日短く、国内A+では4.04日短くなりました。欠品率には判別可能な差がなく、差がちょうど0だったと確認したわけではありません。在庫価値を50億人民元とした推計では、在庫の価値が3.5億人民元、年間資本費用が1,330万人民元減ると著者は試算しました。

2025年10月、AlibabaはTmallで自社が在庫を持ち、補充を管理する商品と倉庫の組み合わせ100万件超のすべてに導入しました。この導入範囲に、ほかの出品者が管理する在庫は含みません。

## 図で発注量を確かめる

図の選択欄で12、24、36のいずれかを選ぶと、図はNoneの発注量とBaseの目標在庫をその値に固定し、CoeffとBothの重み付き和も同じ値になるよう係数を選びます。横軸の総在庫を右にたどると、BaseとBothは目標から総在庫を引くため、発注量が減って0になります。NoneとCoeffは総在庫を引かないので、この条件では発注量が変わりません。線が重なっていても、発注量を求める式は異なります。

発注したい量を0以上の q 個とすると、Baseでは総在庫に q 個を足した値を目標にすれば、式が q 個を返します。Bothでは、値が1の定数特徴の係数だけをその目標にし、ほかの係数を0にすると同じ発注量になります。Labはこのやり方で総在庫と発注量の55通りの組み合わせを確かめました。モデルを学習させてこの出力を見つけたわけではありません。

## Labの計算結果

Labが55通りを計算すると、4方式とも指定した発注量を誤差0で再現しました。図では目標在庫を12・24・36個、総在庫を0〜48個とし、BaseとBothに同じ目標を与えると全点で発注量が一致しました。需要特徴は [4, 8, 12, 16, 1] で、最初の4係数は [0.1, 0.2, 0.3, 0.4] です。

この計算は、発注量の式を確かめるためのものです。図表の欠品率と在庫回転日数は、論文に記載された評価結果であり、55通りの計算から出した値ではありません。

## Labで確かめたこと

CONFIRMED（確認済み）：Labは55通りの在庫と発注量を使い、4方式すべてで指定の発注量が出る入力を計算しました。BaseとBothに同じ目標在庫を与えると、図の発注量は一致しました。

PARTIAL（一部確認）：Labが確認したのは、モデルの出力を固定した場合の式の動きです。DDPG、PPO、DSによるモデルの学習は実装していません。

## Labで確かめていないこと

NOT TESTED（未検証）：Labは学習がどれだけ速く収束するか、ハイパーパラメータを変えると結果がどれだけ変わるか、Table 1の順位を確かめていません。100万超の商品と倉庫の組み合わせで動くか、本番導入が欠品率と在庫回転日数をどれだけ変えたかも検証していません。Tmallの非公開データ、欠品日の需要推定、報酬の重み、運用中の再学習は再現対象外です。

## 結果の再生成

リポジトリの直下で次のコマンドを実行すると、Pythonの標準ライブラリだけで `results.json` を作り直せます。

```bash
UV_CACHE_DIR=/tmp/uv-deepstock uv run --no-project papers/deepstock-policy-regularized-inventory-drl/run.py
```

`run.py` に発注量の式と確認条件、`lab.yaml` と `README.md` に本文と図の説明、`mapping.md` に原論文と実装の対応を載せています。サイトはこれらのファイルからHTMLを生成します。学習速度を検証するなら、公開の人工環境で設定を試す回数をそろえ、NoneとBaseの学習曲線を比較します。
