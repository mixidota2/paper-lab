# DeepStock：発注量を直接学ぶ代わりに、目標在庫や需要の係数を学ぶ

## Overview

DeepStockは、発注量を決める強化学習モデルに、在庫管理で使われてきた考え方を組み込む方法です。モデルが需要の履歴や予測を使って目標在庫を求め、その目標から手元の在庫と入荷予定の合計を引きます。不足分があれば発注します。著者は発注量を直接出すモデルと比べ、学習の設定を試せる回数が少ないときに、この仕組みの効果が特に大きいと報告しました。

AlibabaのTmallでは2025年4月、実際に導入した方法と、同じ月の発注の見直し間隔と入荷にかかった日数を使って従来法を動かしたシミュレーションを比べました。在庫回転日数は海外商品で1日、国内商品で2日短く、欠品率にははっきりした差がありませんでした。従来法の数値は試算で、実店舗や倉庫で両方式を無作為に割り付けて測ったものではありません。

## Problem

欠品で買えなかった分は販売記録に残りません。著者は、欠品が起きた時刻を使ってその日の需要を外挿し、販売数ではなく推定した需要で方策を訓練しました。この推定が外れたときに発注がどの程度変わるかは、Labでは確かめていません。

商品によって販売規模、発注から入荷までの日数、補充の間隔も違います。Tmallの実験では190次元の特徴を使用しました。発注量をネットワークから直接出す通常の方法では、この条件のもとで学習やハイパーパラメータの選択が不安定になりやすいと著者は説明しています。

## Core Idea

**著者の主張。** Baseでは出力を目標在庫と読み、現時点の総在庫を引きます。Coeffでは出力を係数と読み、需要に関する特徴の重み付き和から発注量を計算します。ネットワーク自体が在庫状態を受け取るため、Baseを使っても全状態で同じ目標在庫を使う必要はありません。著者は、この変換を打ち消す値も出せるので、表せる発注ルールの範囲は狭まらないと説明しています。

**Labでの読み方。** 変わるのは、学習中に試しやすい発注です。最終的なルールを固定する工夫ではありません。DeepStockが訓練するのは、在庫状態から発注量を決めるニューラルネットワークです。SabreAgentが大規模言語モデル（LLM）を設計時に使い、その後は固定した数理最適化で発注することや、InvEvolveがLLMで人の読める発注コードを更新し、候補を検証することとは異なります。DeepStockはLLMを使いません。

## Method

`I`は手元と輸送中の在庫の状態、`x`は在庫以外の特徴、`tot(I)`は総在庫です。`f=feat(x)`は過去や予測の需要を表す4つの特徴と定数1をまとめたものです。`μ`はその時点の状態を受け取る学習済みネットワーク、`q`は発注量です。

```text
None:  q = μNone(I, x)
Base:  q = max(μBase(I, x) − tot(I), 0)
Coeff: q = μCoeff(I, x)ᵀ f
Both:  q = max(μBoth(I, x)ᵀ f − tot(I), 0)
```

4式は原論文の導入部pp.3–4に対応します。Coeffには論文にない切り上げや下限処理を足していません。実験では非負の出力を使います。商品ごとに在庫と時々刻々と変わる入力の尺度をそろえ、Coeffで需要に見合う個数に戻します。著者は、販売規模が異なる商品で一つの方策を共有するためにこの処理を使いました。

## Why It Might Work

出力が目標在庫なら、同じ目標を出したとき、手元と輸送中に十分な在庫があれば追加発注は0です。需要特徴に係数を掛ける方式では、同じ係数でも需要の規模に応じて発注量を変えられます。著者は、このような行動を学習中に試しやすくなると説明しています。Fig. 3では、Baseを用いたDDPGで、価値関数が満たす式からのずれ（Bellman誤差）が小さくなりました。

ただし、ネットワークの出力μ自体も在庫状態によって変わるため、在庫が増えるといつも発注が減る、需要が増えるといつも発注が増える、という単調性保証にはならない。図では、出力を固定したときだけの関係を示しています。

## Evidence

一次資料の[原論文Table 1・2、§4](https://arxiv.org/pdf/2603.19621v1)にある著者報告です。Labが同じデータで確かめた結果ではありません。

**オフライン比較（Table 1）。** 数値はDDPG Bothからの差です。DDPG Noneは欠品率+10.10ポイント、回転日数+6.13日。DS Noneは+2.10ポイント、−1.25日、DS Baseは+2.18ポイント、−2.81日でした。DDPG Bothと比べ、DS Baseは欠品が多い代わりに在庫が早く回ります。著者は欠品率を回転日数の2倍重く扱う評価でDDPG Bothを最良としましたが、両指標で最良という意味ではありません。

**2024年7月、導入前後を比較。** 改善余地が大きい国際SKUから対象の10%を選び、導入群の前後差から対照群の前後差を引く「差の差分析（DiD）」を行いました。欠品率は−0.83ポイント、回転日数は−9.53日です。無作為に割り付けた比較ではないため、全商品に同じ効果が出るとは限りません。

**2025年4月、運用実績と旧方策のシミュレーションを比較。** 実際の補充間隔と入荷までの日数を使い、旧方策を続けた場合を計算しました。国際SKUは約−1日、国内は約−2日、国内A+は−4.04日でした。欠品率に判別可能な差はありません。在庫価値50億人民元を前提にした推計は、在庫削減3.5億人民元、年間資本費用削減1,330万人民元です。通貨は日本円ではありません。

## Executable Understanding

図の選択欄で出力を固定してから、横軸の総在庫を見ます。目標在庫から総在庫を引くBaseとBothの線は、在庫が増えると発注量が減り、0で止まります。Noneは発注量を直接出し、Coeffは需要特徴の重み付き和を使うため、この条件ではどちらも水平です。線が重なっていても、同じ計算をしているわけではありません。

逆に、ある状態で非負の発注量qを出したいとします。Baseでは目標をμ=q+tot(I)にします。Bothでは他の係数を0とし、定数特徴の係数をq+tot(I)にすれば同じqが出ます。55組の在庫と発注量でこの関係を確かめます。ネットワークが学習でこの出力を見つけられるかは別の問いです。

## Results

55組すべてで、指定した発注量を誤差0で復元しました。目標を12・24・36、総在庫を0〜48とした図では、同じ目標を与えたBaseとBothの線が重なりました。需要特徴は[4, 8, 12, 16, 1]、最初の4係数は[0.1, 0.2, 0.3, 0.4]です。

この計算では発注の性能を測っていません。図の欠品率・回転日数は論文の値を転記したもので、55組の計算結果ではありません。

## What We Verified

**CONFIRMED（確認済み）。** 原論文の式を使った55例では、指定した非負の発注量をすべて誤差0で再現しました。BaseとBothに同じ目標を与えた場合も、発注量は一致しました。

**PARTIAL（確認は一部）。** 計算したのはネットワーク出力を固定した場合です。DDPG、PPO、DSでネットワークを訓練する部分は実装していません。

## What We Did Not Verify

**NOT TESTED（未検証）。** 強化学習がどのくらい速く収束するか、ハイパーパラメータ次第で結果がどれだけ変わるか、Table 1の順位が再現されるかは未確認です。100万超のSKUと倉庫の組への拡張や、本番導入が欠品・回転日数に与えた因果効果も検証していません。Tmallの非公開データ、欠品時の需要推定、報酬の重み、運用中の再学習は再現対象外です。
