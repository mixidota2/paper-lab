# LinkedInは、配信で増える成果を見積もって届け先を決める

## LinkedInが8週間の実験で比較したもの

LinkedInは施策を届けた場合と届けなかった場合の成果をそれぞれ予測し、その差を使って、どの会員に何を届けるかを決める仕組みを作った。著者はLinkedIn Feedのマーケティング枠で従来の配信方法と8週間比較し、会員の長期価値を表す指標（LTV）が対照群より7.20%高かったと報告している（p=0.041、95%信頼区間は[0.31%, 14.09%]）。比較したのは配信方法全体で、Transformerだけの効果は分からない。

## 届けなくても行動する会員に予算を使うと、何が起きるか

施策を届けた場合の反応確率が高い会員でも、何も届けなければ同じ行動を取るかもしれない。その会員に予算を使うと、施策があれば行動を変える別の会員へ届ける余地が減る。また、担当者がキャンペーンごとに配信先を決めると、合計で予算を超えたり、一人に施策を届ける回数が多くなったりする。

## モデルが成果の差を予測し、配分器が届け先を決める

著者はまず、Transformerで会員と施策の接触履歴を読み取る。DragonNetはその表現を使って、施策あり・なしの成果を別々に予測する。次に、ベイズの考え方を使ったバンディットが、モデルの不確実性をもとに、普段は選ばない配信先も試す。最後に配分器がすべての施策をまとめて見ながら、予算と頻度の上限を守る組み合わせを選ぶ。届けると成果が下がると予測した場合や、制約内で成果を増やせる選択肢がない場合、配分器は配信を見送れる。

Labでは[Netflixが欠けた比較対象を観測する試み](netflix-counterfactual-observability.html)、[Spotifyが二つのしきい値で推薦を絞る方法](spotify-incremental-recommendation-causal.html)、[Pinterestが買い物の推薦候補を絞る方法](pinterest-causal-retrieval-shopping.html)と読み比べる。LinkedInの論文ではその先で複数の施策に共通の予算をどう配るかが主題になる。これはLabで四つの論文を読み比べた整理であり、四社を同じ実験で比較した結果ではない。

## なぜ反応確率でなく、成果の差を見るのか

配信ありと配信なしの差を正しく推定できれば、施策を届けなくても起きる分を、配信の成果から除ける。ただし、過去のログから差を推定するには、記録した特徴を考慮した後に、配信と成果の両方に影響する未観測の要因がないと仮定する。また、似た会員について、配信あり・なしの両方を観測できることが必要になる。この条件を満たすかどうかは、DragonNetを使うだけでは決まらない。

## 本番では配信先の決め方をまとめて変えた

[一次資料：論文の§5.4–5.5](https://arxiv.org/html/2608.10182v1#S5.SS4)では、LinkedInが会員を両群に50/50で無作為に割り付けている。従来群では二段階の反応予測を使って候補を選び、順位を付けた。新方式の群では、マーケティング担当者が指定する対象条件は残したまま、成果の差を予測して、全体の制約のもとで配信先を決めた。最初の実験では新方式の配信量が足りなかったため、配分時に配信量と費用をそれぞれ制約し、実際に使った金額から次回の費用目標を調整する仕組みを加えた。最終比較は従来群の配信量と費用の範囲を目安にした。会員ごとに両群で同じ回数だけ届いた、という意味ではない。

著者は公開バンディットデータを使った模擬実験でも選択方法を比較した。また、固定した学習・検証データで入力や構成の一部を変え、8構成を各5回試した。これらの結果は本番A/Bとは別で、時系列入力とTransformer自体の寄与も切り分けていない。

## Labでは4人への配分を全列挙する

`UV_CACHE_DIR=/tmp/uv-cache uv run papers/linkedin-prediction-to-incrementality/run.py` を実行すると、同じ予算で二つの配信方法を比較できる。架空の4人に対して施策は1種類で、配信あり・なしそれぞれの期待成果と配信費用をあらかじめ設定した。プログラムは送るか送らないかの16通りを調べ、予算内で評価値が最大になる組み合わせを選ぶ。学習も外部の最適化ソフトも使わない。

## 予算3なら、配信で増える期待成果は0.20と0.50

配信したときの期待成果を合計する方法では、A・B・Dに届ける。配信で増える分を合計すると0.20になる。配信で増える分を最初から最大にする方法はC・Dを選ぶ。増える分は0.50、配信しない人も含めた4人の期待成果は1.90から2.20になる。さらに予算を5に増やしても、後者は成果が下がるAに送らず、費用4で配信を止める。設定した期待値から得た結果で、論文の7.20%を再現したものではない。

## Labで調べた範囲

Labは配分の仕組みを一部検証した（Mechanism PARTIAL）。全列挙で予算を変えると配信先が変わること、増分最大化では増分が負のAを選ばないことを確認した（CONFIRMED）。原論文の図1、関連する式と本番実験の条件を本文と突き合わせた。

一方、LabはTransformerを組み込んだDragonNetを学習していない。最終層に対するラプラス近似、トンプソンサンプリング、双対法による配分、配信量と費用の調整も実行していない。大規模時の最適値や新商品への適用を含め、予測性能、規模を広げたときの挙動、本番への適用はいずれも未検証（NOT TESTED）。LinkedInの会員ログは使っておらず、著者のA/Bも再実施していない。

## プログラムと原論文の対応

Python標準ライブラリだけで動く。`ROWS`は4人分の入力、`allocate()`は配分の全列挙、`compute()`は予算ごとの比較と検査を担当する。乱数を使わず、実行するたびに`results.json`を書き直す。HTMLは`lab.yaml`、文書、保存結果から作る。

[原論文](https://arxiv.org/abs/2608.10182)の式や図のどこを参照したかは[mapping.md](mapping.md)、元の仕組みの詳細は[method.md](method.md)に記す。Labが確認した論文には公式実装へのリンクが見当たらなかった。
