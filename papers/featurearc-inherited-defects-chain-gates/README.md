# FeatureArc：最後の追加が動いても、機能全体が動くとは限らない

FeatureArcは、エージェントが前の段階で書いたコードを引き継いで、一つの機能を少しずつ広げるときの評価です。このLabでは、以前の段階に残った不具合と、後の変更で壊れた動作を小さな整数列の例で比べます。著者の方法を読む価値があるのは、エージェントが自分で書いたテストと、機能全体の受入検査を分けて考えられるためです。結果をもとにモデルの順位を勧めるものではありません。

## 配布ファイルで教材を動かす

記事の配布リンクから `run.py`、`render.py`、`interactive.js` を同じフォルダーに保存してください。`run.py` は計算を行い、`render.py` は `interactive.js` を読んで表示用の文書を作ります。Pythonの標準ライブラリだけで動きますが、3ファイルはすべて必要です。

保存先のフォルダーで次を実行します。

```bash
python run.py
```

コードと同じフォルダーに `results.json` と `experiment.md` ができます。同名のファイルは上書きするので、残したい結果がある場合は先に別名で保存してください。別の場所から実行するなら、`python "/保存先/run.py"` のようにコードの場所を指定します。

## リポジトリ全体で検証する

次のコマンドは、リポジトリのルートで実行します。依存ライブラリは固定された版を使います。

```bash
uv sync --locked --extra dev --python 3.12
uv run --locked python papers/featurearc-inherited-defects-chain-gates/run.py
uv run --locked pytest -q -ra --fail-on-skip tests/test_featurearc.py
uv run --locked pytest -q -ra --fail-on-skip
uv run --locked paper-lab build
uv run --locked python tests/review_103.py --preflight --site site --out /tmp/featurearc-preflight
```

`run.py` は、実際の関数の戻り値をあらかじめ決めた期待値と比べます。10条件でそれぞれ3段階を試し、最終コードの検査結果と、集計に使う分子・分母も保存します。`render.py` は初期状態をHTMLに残し、`interactive.js` は保存済みのJSONを読みます。ブラウザーで別の計算をするわけではありません。「前の記録」ボタンで戻るのは、記録を表示する位置だけです。

入力は用意した有限の整数列と、0以上の件数上限に限ります。ネットワークや実際の言語モデル、著者のコードは使いません。PythonとJavaScriptの検査で確かめるのは、計算して保存した記録と画面の表示が合うことです。

## 何を確認したか

- **確認済み（CONFIRMED）:** 境界値、空の入力、符号付き合計、状態の引き継ぎ、途中で失敗したあとの回復、割合の分母、同じ入力から同じファイルができることをローカルテストで確認します。
- **論文との対応は一部（PARTIAL）:** 段階の検査と全体の検査の違いを、小さい例で表しました。実際のリポジトリ編集、エージェントの会話の維持、テストを抽出する過程は再現しません。
- **公開先は未確認（NOT OBSERVED）:** 参照した資料では、著者が使ったコードや実行データの配布先を確認できませんでした。存在しないと判断したわけではありません。
- **未検証（NOT TESTED）:** 実モデルの成績、乱数を変えたときの安定性、規模を広げた場合、実務の効果、修正による因果効果は確かめていません。画面の動作は、対象版の保護されたCIと独立レビューで確認します。単体テストだけでブラウザーの動作を確認したとは扱いません。
