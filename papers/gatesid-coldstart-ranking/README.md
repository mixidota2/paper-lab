# GateSIDは、購入履歴の少ない商品をどう順位付けするか

Alibaba Internationalの研究チームは、クリックや購入の記録が少ない新商品を推薦候補の中でどう順位付けするかを調べました。GateSIDは、商品の画像や説明をもとにした識別子（SID）と、実際の行動から学んだ商品表現を使います。二つの表現で過去の行動を別々に参照し、掲載日数や表示回数などに応じて結果を混ぜます。GateSIDが変えたのは候補の順位付けで、候補を探す方法ではありません。

総トラフィックの20%を使った2週間のA/Bテストで、著者は従来方式より取引総額（GMV）が全体で2.6%、掲載20日未満の商品に限ると5.6%増えたと報告しています。追加の遅延は5ミリ秒未満でした。ただし、実験したのは一つのECサービスです。商品内容を表す特徴だけを加えた効果ではなく、GateSID全体を導入した結果です。

一次資料は[原論文第2版のPDF](https://arxiv.org/pdf/2603.22916v2)です。照合した箇所とPDFのSHA-256は[mapping.md](mapping.md)、モデルの式は[method.md](method.md)、サイトの原稿は[lab.yaml](lab.yaml)にあります。

## 人工データの計算を手元で実行する

配布された `run.py` はPython標準ライブラリだけで動きます。保存したフォルダーで `python run.py` を実行すると、同じ場所の `results.json` に結果を書き出します。リポジトリを取得した場合は、ルートから次を実行できます。

```bash
uv run papers/gatesid-coldstart-ranking/run.py
```

Labは、3件の行動からなる履歴を用意し、商品内容で照合したときと、行動から学んだ表現で照合したときのスコアを固定します。スライダーで混合比wを0、0.25、0.5、0.75、1から選ぶと、同じ履歴のどこを重く見るかがどう変わるかを確認できます。混ぜた重みは二つの履歴に同じように掛けます。

Labは固定した正例と負例から対照損失（InfoNCE）を求め、同じwを掛けます。掲載日数やクリックからwを学ぶ工程はありません。

## 計算で確かめたことと、確かめていないこと

人工データでは、w=0で行動側の重みだけが残り、w=1で商品内容側の重みだけが残ります。途中の値では、混ぜた重みの合計が1になり、対照損失に掛けた分はwに比例して増えました。Labで確かめたのは、これらの式と境界での動作です。入力はrun.py、計算結果と確認範囲はresults.jsonにあります。

[results.json](results.json)の`checks`には、人工例で確認した項目（CONFIRMED）と、検証しなかった項目（NOT TESTED）があります。仕組みの検証は一部（PARTIAL）です。

Labは、商品内容をSIDに変えるRQ-VAE、混合比を決めるモデル、クリックと支払いを予測する順位付けモデルを学習していません。本番でのAUCや取引総額、処理規模、追加遅延が5ミリ秒未満だったことも、独立には検証していません。確認したのは人工データで混合比を固定した場合の計算であり、実際の新商品の順位が良くなるとは、この計算だけでは言えません。
