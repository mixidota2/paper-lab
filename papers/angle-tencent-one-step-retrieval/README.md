# ANGLE：検索意図と商品語を生成する広告検索

## 概要

Tencentの著者は検索広告を「広い検索意図」と「広告の短い要約」の組で表しました。ANGLEはこの組を検索語に合わせて生成し、関連性を判定してから、広告の価値に応じて候補を並べます。表示できる広告がない組は生成の途中で除きます。広告を表す専用の番号と広告との対応をモデルに覚えさせる代わりに、短いテキストで索引を引く仕組みです。

著者が報告した本番の比較では、流通総額（GMV）がWTSで2.16%、QBSで5.01%増えました。これらは論文が匿名で示した二つの検索システムです。著者はANGLEを既存のランキングに候補を足す仕組みとして運用しており、精密ランキングまで廃止した比較ではありません。

## 候補を取得する手順

広告側は、大まかな検索意図と広告の内容に即した短い要約を作ります。検索側は、検索語から意図を生成し、配信できる広告がある要約に探索を絞ります。組を生成した後は関連性を調べて索引を引き、候補を既存の精密ランキングに渡します。配信可否、検索語との関連性、商用価値は別の判断です。詳しい手順と数式は `method.md` と `lab.yaml` にあります。

## 著者が報告した結果の読み方

検索ログの表2で、著者のHR@100はANGLEで0.5273、最も高かった比較先のSimBert-v2-Gで0.3095でした。動的な制約付き探索を外した条件は0.2975ですが、自由に生成した後に近似近傍検索を使う構成へ変わっており、制約だけを外した比較ではありません。

WTSの広告費について、著者は要旨と表3に+1.81%、§4.2に+1.18%と記しています。流通総額の+2.16%は一致します。クリック数やコンバージョン数の増加を、クリック率やコンバージョン率の改善と読み替えることはできません。QBSに同じ実験条件を使ったかや、信頼区間は分かりません。両システムの指標は `lab.yaml` に載せています。

## Labの合成例を実行する

配布した `run.py` を保存し、そのフォルダで `python run.py` を実行すると、同じ場所の `results.json` が更新されます。Pythonの標準ライブラリだけで動きます。リポジトリからは `uv run papers/angle-tencent-one-step-retrieval/run.py` でも実行できます。

この例は5広告と4組の点数を固定し、組を選ぶ前に配信可否を調べるか、選んでから調べるかを比べます。最大1組なら、後から調べる場合は0件、先に調べる場合はBとCの2件です。最大3組なら、どちらもB・C・Dの3件です。同じ組にFを手で追加すると、組の点数を変えずに取得できます。

確認したのは、配信可否を見てから組を選ぶ処理と、索引から複数の広告を取得する処理です。Hunyuan、DPO、トークン単位の探索、本番の効果は試していません。論文と合成例の対応は `mapping.md` を参照してください。
