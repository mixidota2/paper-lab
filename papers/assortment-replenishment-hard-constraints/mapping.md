## 論文の式とLabの計算の対応

一次資料：[論文本文](https://link.springer.com/article/10.1007/s10696-023-09492-z)。著者はHübnerとKuhnです。論文は2023年4月2日にオンラインで公開され、2024年の巻号に収録されました。ライセンスは[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)です。記事内の図、入力例、計算プログラムはLabが作成しました。

| 論文の箇所 | Labで計算すること | 確かめる例 |
|---|---|---|
| 式(1)〜(4) | `evaluate` の `direct`、`transfer`、`demand` で商品自身の需要、流入、総需要を求める | T1〜T4。代替割合 `mu` を固定し、最初の代替先から再転送しない |
| 式(6)〜(9) | `stock`、`required`、`profit`、`width` に棚在庫、必要在庫、利益、使用幅を記録する | 商品ごとに棚在庫を判定し、必要量と一致する案を認める |
| 式(10)〜(14) | 0面から上限 `K` までの整数面数を組み合わせ、全候補を調べる | 候補数と、最大利益が同じ案の数 |
| 図6の需要切り詰め | 主な計算には使わない | T3の別計算で、同じ利益比較には使えないことを示す |
| 式(15)〜(16)の比例初期案 | Labはこの初期案を実装していない | 代替なしの案と、採用品を固定する案を比較に使う |

Pythonの `run.py` の `oracle` と、ブラウザー用の `model.js` の `solve` は別々に実装しました。どちらも整数面数をすべて調べます。基準案に代替需要を足すと在庫条件を満たさない場合、利益差の割合を出しません。また、どちらの計算にも補充作業費を含めていません。

最低棚在庫比率の範囲と等号の扱い、採用しないときの0面については、`implementation.md` にまとめました。書誌は出版社のページで確認しました。詳細な式と図6は提供された照合仕様を使ったため、図の分岐をすべて独立に確認したとは扱いません。

[全店の棚幅配分](storewide-shelf-decomposition.html)とは、外した商品の需要の配り方が異なります。この教材では、買い替え先ごとの割合を固定します。その先の商品も外した場合、残った商品の基礎需要に比例して配り直すことはしません。
