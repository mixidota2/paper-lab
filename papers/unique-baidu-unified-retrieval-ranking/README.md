# UNIQUE: A Unified Retrieval and Ranking System for Large-Scale Feed Recommendation

Baiduの研究チームは、アプリのフィードに載せる記事や動画を探す処理と、見つけた候補を採点する処理に、同じモデルを使う方法を提案しました。UNIQUEは利用者の履歴をもとに、まず見てもらえそうなコンテンツのグループを選びます。次に、グループから取り出した候補をベクトルの内積で絞り、残った候補ごとに履歴の異なる部分を参照して採点します。モデルは共有しますが、配信時には候補を段階的に絞ります。

Baiduはアプリの候補取得部分で、以前の方式とUNIQUEを1週間比べました。著者の報告では、視聴時間の合計が0.96%、コンテンツの配信量が1.08%増えました。候補取得サービスの応答時間は99パーセンタイルで89ミリ秒でした。この値は推薦画面全体の応答時間ではありません。

## 候補を探す処理と採点する処理

UNIQUEはコンテンツの内容や利用者の反応をもとに、各コンテンツにグループを表すコードを割り当てます。推薦時には利用者の履歴と、調べたいコードや候補の情報を同じモデルに渡します。モデルは、どのコードから候補を集めるかと、絞り込んだ候補をどのように採点するかを一緒に学習します。実運用では、採点した候補を推薦システムの後続処理に渡します。

## 読む順番と再実行

`lab.yaml` には論文の問いと結果を、`method.md` にはコードの割り当てから推薦候補を渡すまでの手順を記載しています。`mapping.md` では論文の式とLabの計算を対応づけ、どこまで確かめたかを説明します。

```bash
uv run papers/unique-baidu-unified-retrieval-ranking/run.py
```

`run.py` はPython標準ライブラリだけで動き、同じフォルダに `results.json` を書き出します。ファイルを単体で取得した場合は `uv run run.py`、LabのHTMLを生成する場合はリポジトリで `uv run paper-lab build` を実行します。

Labが確認したのは、架空の値を使ったコードの割り当てと、候補ごとに履歴を参照する計算の一部です（PARTIAL）。実運用の成果、件数を増やしたときの性能、導入の可否は検証していません（NOT TESTED）。
