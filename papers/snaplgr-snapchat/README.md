# LLM-Based Generative Retrieval for Snapchat Content Recommendation

SnapLGRはQwen3-0.6Bで動画候補のIDを事前に生成し、配信時は索引を読む。著者は従来のT5方式との7日間の比較で視聴時間が0.37%増えたと報告した。動画IDだけのログ評価とは別の結果だ。

Labの判定はWatch。論文の確認日は2026年9月21日。

## 実行

```sh
uv run papers/snaplgr-snapchat/run.py
uv run paper-lab build
```

## 概要

Snapchatの研究チームは、動画の推薦候補を探す処理で、既存の1,300万パラメータのT5モデルに代えて、6億パラメータのQwen3を使いました。SnapLGRは動画を表す識別子（SID）を追加し、まずIDと動画の内容の関係を学び、次に利用者の行動履歴から候補のIDを予測するように学習します。著者は本番での計算を間に合わせるため、GPUで候補IDを絞る処理や、処理の振り分け方も変えました。

著者は7日間のA/Bテストで、従来方式より視聴時間（View Time）が0.37%増えたと報告しています。これとは別に、両方式で同じSIDを使ったログ評価では、上位32件でのID一致を測るRecall@32が4.624%から11.11%に上がりました。視聴時間が2.40倍になったわけではありません。本番ではIDの作り方、モデル、配信処理を一緒に変えており、Qwen3の事前学習だけの効果は切り分けていません。

## 問題

事前学習済みの言語モデルは、Snapchatが動画に付けたSIDを知らない。似た動画に同じIDが付いたときの扱いと、短いIDを広いビームで生成する計算量も考える必要がある。候補生成が改善しても、その後の順位付けを経て視聴時間がどのくらい伸びるかは、ログのID一致だけでは分からない。

## 著者の提案

著者は動画の内容と一緒に視聴された記録を使ってSIDを作り、Qwenに追加したIDの意味を学ばせた。候補を生成する計算にはCUDAを使い、ワーカーへの割り振り方式も変えた。配信時は生成を繰り返さず、事前に作った動画候補を索引から読む。

[SIDScope](sidscope-diagnostics.html)が扱うように、IDが有効であることと、候補の動画を一つに決められることは異なる。SnapLGRは候補を集める処理を入れ替えた方式で、[Sona](sona-yandex-music.html)のように最終順位を付けるところまで統合した比較ではない。

## 改善が見込める理由

動画候補を選ぶモデルの容量を増やすと、同じ行動履歴から予測できる関係を増やせる可能性がある。PPRで同じ利用者が見た動画を近づけると、内容が似ているかだけでは表せない関係もIDに反映できる。CPTは追加したIDを内容と結び付けるが、その後のSFTでは行動ログを使う。著者のRSAでは、CPTで得られた類似構造との一致がSFTの後に弱まった。

## 論文の比較

### 視聴時間を測った本番比較

著者は本番で7日間、CLIP型のSID（256³）と1,300万パラメーターのT5を使う従来方式とSnapLGRを比較した。表8は視聴時間（View Time）+0.37%（p=0.007）、利用時間（Time Spent）+0.09%（p=0.048）、Deep Sessions +0.18%（p=0.027）、Deep Sessionsに達した利用者数+0.11%（p=0.017）と報告する。割り当てたトラフィックの割合は本文にない。IDの作り方、モデル、配信処理を同時に変えたので、Qwenの事前学習だけの効果には分けられない。

### 同じSIDで、ログ上の一致を測った比較

表3では両方式でQwen3-VLのSIDを使い、上位32件のSIDの再現率を比べた。T5は4.624%、SnapLGRは11.11%で、差は6.486ポイント。ここで当てるのはSIDで、一つのSIDから複数の動画を選ぶ。視聴時間や動画の取得率が同じだけ伸びたわけではない。

表5は同じLLMでIDの作り方を変えた別の比較だ。Qwen3-VLのSIDを使うと、SIDのRecall@32は10.98%で、動画単位のRecall@32は2.765%だった。二つの値は評価するものが違うので、SIDの再現率を動画の再現率として読まない。

### 学習の各段階と、処理件数の比較

表4は全モデルを6億パラメーターにそろえている。SIDのRecall@32は、ランダム初期化からSFTした場合が10.77%、事前学習済みモデルにSFTした場合が10.98%、SFTの前にCPTも行った場合が11.11%だった。CPTの追加分は0.13ポイントで、著者の表は相対で1.19%と報告する。テキストの類似関係とSIDの類似関係がどれだけ一致するか（RSA）は、初期の0.016からCPTで0.322になり、SFTの後は0.167だった。SFTだけの値は0.162。RSAの低下は、動画を識別できなくなった割合ではない。

表7の処理量はA100上で、旧方式を1とすると順に9.3、30.7、45.7倍だった。最後に先読みと非同期の書き込みを加えた分だけなら、直前の構成に対して約1.49倍だ。学習の処理量は別の表6で、A100上のソフトウェアの変更までで1.78倍、H100への移行を含めると3.63倍だった。45.7倍は日次生成の処理量で、利用者ごとのオンライン応答時間ではない。

## Labの小実験

Labは30個の人工のSIDそれぞれに2本の動画を割り当てた。生成したSIDは全条件で固定する。各SIDから名前順で先頭の動画を選ぶ方法と、手で決めた点が高い動画を選ぶ方法を比べる。正解動画が高い点を持つ条件と、低い点を持つ条件を作った。

この例ではSIDが一致する割合はすべて1.0。違うのは、そのSIDに対応する2本の動画からどちらを選ぶかだ。

正解を各SIDで点の高い方に置くと、名前順では30本中14本が正解で、点の高い方を選ぶ方法では30本すべてが正解だった。正解を点の低い方に置くと、名前順では30本中16本が正解で、点の高い方を選ぶ方法では0本だった。SIDはどちらの条件でもすべて一致している。

点の付け方に合うよう正解を作った例なので、点の高い動画を選べば本番でも必ず良くなるという結果ではない。

Labは人工の動画で、SIDの一致率が同じでも選んだ動画の正答率が変わることを確かめた。動画を選ぶ順序だけを変えることで、SIDの評価と動画そのものの評価が異なることを示した。

LabはQwenのCPT・SFT、PPRやRQ-VAEの学習、TensorRT-LLM、分散ワーカー、GPUの高速化、本番A/Bを再現していない。人工例は一つのSIDから1本を選ぶ単純な処理で、本番の反応指標の重みや、SIDごとに保存する候補数を再現しない。

## 実行するコード

`materialize()` は生成したSIDに対応する動画を調べ、名前順か値の高い順で1本を選ぶ。`compute()` は同じSIDを与え、正解を高い点の動画と低い点の動画に切り替える。動画の点は乱数の初期値を固定して作り、LLMを学習しない。

リポジトリのルートで `uv run papers/snaplgr-snapchat/run.py` を実行する。Python標準ライブラリだけを使い、コードと同じ場所に `results.json` を保存する。
