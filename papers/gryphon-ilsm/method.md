### 同じIDを持つ曲を、曲ごとに採点する

Gryphonは、双方向Transformerで利用者の履歴を一度読み、状態列Eᵤを作る。IDを生成するデコーダーと、曲ごとに点を付ける部品（Item-Level Scoring Module、ILSM）が同じ状態列を使う。SIDは曲を表す短いトークン列で、生成確率は各トークンの条件付き確率を掛けて求める。生成確率の対数は各トークンの対数確率の和になる。

```text
pθ(σ|u) = ∏ᵦ pθ(sᵦ | u, s<ᵦ)
ℓθ(σ|u) = Σᵦ log pθ(sᵦ | u, s<ᵦ)
Cσ = {i : Φ(i)=σ}       Iᵤ = ∪σ∈beam Cσ
```

Cσは同じSIDを持つ曲の集合だ。ビーム探索で残したSIDから、それぞれに対応する曲を取り出し、合わせて候補集合Iᵤを作る。生成確率をそのまま曲の得点にすると、同じSIDを持つ曲は全部同点になる。ILSMは曲ごとの表現eᵢをQueryにしてクロスアテンションで履歴を読み、MLPでその曲の点を付ける。

```text
eᵢ = Titem(Φ(i), hᵢ)
rφ(u,i) = fφ(Eᵤ, eᵢ)
TopN(u) = TopNᵢ∈Iᵤ rφ(u,i)
```

式のhᵢには一般に曲ID、曲の属性、内容の情報を入れられる。ただし論文のモデル比較で、ILSMに渡した追加の曲特徴は曲IDだけだ。著者は、追加特徴の種類で差が付かないようこの条件を選んだ。Gryphonは、比較するVanilla GRの7層のエンコーダーと3層のデコーダーのうち、デコーダーの1層をILSMに替える。著者によると、この構成のパラメーター数と推論時間の差は1%未満だった。比較実験ではモデル共通で履歴長512、隠れ幅1024、ビーム幅2048を使った。[一次資料：元のGryphon論文第2版・§3.2と§4.1.3](https://arxiv.org/html/2606.08604v2)

### 次に聴く曲を予測する二つの損失

デコーダーは、正解の曲に付いたSIDの負の対数尤度Lgenを下げる。ILSMは、同じバッチから集めた負例と正解の曲を比べ、次に聴く曲を予測する。論文は複数のデバイスから負例を集め、負例としてサンプリングされる確率Qᵢの対数をスコアから引く（sampled softmax）。

```text
zᵢ = rφ(u,i)/τ − log Qᵢ
LNIP = −log [ exp(zᵢ₊) / Σⱼ∈{i₊}∪B⁻ exp(zⱼ) ]
L = Lgen + λ LNIP                 （報告実験は λ=1）
```

τは温度、B⁻は負例の集合。共有エンコーダーは両方の損失から勾配を受ける。この比較では、曲を出した後の複数の行動を調整して最終順位を学んだわけではない。本番ではILSMが選んだ1,000曲を、従来と同じ最終順位付けモデルに渡した。別論文の[Gryphon-v2](gryphon-v2-cascade.html)は、教師の点数を学び、実験群で最終順位付けモデルまで置き換えた。[一次資料：§3.3・§4.2](https://arxiv.org/html/2606.08604v2)
