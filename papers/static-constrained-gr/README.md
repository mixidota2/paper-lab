# STATIC：推薦候補を出す途中で、許可された作品だけに絞る

著者は、生成型の推薦モデルが記号を一つずつ足して作品のIDを組み立てる途中で、許可されていないIDを除く方法を提案しました。たとえば公開から7日以内の動画だけを対象にすると、モデルは古い動画のIDをそもそも完成させません。STATICは許可されたIDを先頭の記号ごとにまとめ、その木をTPUやGPUが読みやすい配列に変えます。

著者の測定では、TPU v6e上の30億パラメータのモデルで、候補を制限する追加処理は1ステップ当たり0.033ミリ秒でした。推論時間の約0.25%に当たります。YouTube短尺動画のホーム画面では、公開から7日以内の動画だけを出す候補源を追加したところ、その範囲の動画の視聴が5.1%増えました。前者は処理時間の比較で、後者は候補源を追加したA/Bテストです。

詳しい処理は[手法](method.md)、原論文と小実験の違いは[出典との対応](mapping.md)、サイト本文の元データは[lab.yaml](lab.yaml)にあります。一次資料は[論文の固定版PDF](https://arxiv.org/pdf/2602.22647v2)です。

## 小実験を実行する

```bash
uv run papers/static-constrained-gr/run.py
```

Labは、0か1の記号を3つ並べた架空の作品IDを5個用意し、そのうち001と111を許可しました。同じ点数で比較すると、全作品から上位1件を出してから許可集合で絞る方法では、残る作品は0件です。先に候補を許可集合に限ると、上位1件として001が残ります。また、空の先頭部分を含む15通りについて、配列の探索結果が許可集合の定義と一致することを確認しました。

実行すると同じフォルダーの[results.json](results.json)が更新されます。Pythonの標準ライブラリだけを使います。この小実験はCPUで動き、著者が測ったTPUの処理時間、YouTubeの視聴の変化、Amazon Reviewsでの推薦成績は再現しません。
