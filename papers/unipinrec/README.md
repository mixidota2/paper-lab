# 候補を探したあと、順位付けは履歴を読み直さずに済むか

このLabは、候補生成と順位付けが履歴を別々に処理する場合と、同じ結果を使う場合を計算で比べる。80リクエストについて、候補を各10件に固定し、履歴の長さだけを変える。履歴1要素と候補1件を同じ1単位として数えるため、結果はTransformerの実際の演算数や応答時間ではない。

```bash
uv run papers/unipinrec/run.py
```

このコマンドは `papers/_toy_common.py` の計算を呼び出し、比べた全条件を `results.json` に書く。

配信時の速度を判断するには、キャッシュの転送、容量不足時の再計算、履歴やモデルの更新も含めて測る必要がある。キャッシュの共有を止める比較と、二つの目的での共同学習を止める比較は分ける。前者は配信の速度、後者は学習が検索や順位付けの質に与える影響を調べるためだ。

一次資料のリンクと論文の説明は `lab.yaml` にある。
