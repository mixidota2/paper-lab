### 著者は何を、いつ消したか

エージェントは作業を進めるたびに、過去の推論、ツールの呼び出し、ツールが返した結果を次の入力に含める。著者は、Mini-SWE-agent と Trae agent の両方で同じ DeepSeek-V4-Flash を使い、SWE-bench Verified の同じ100課題を解かせた（§III）。

著者は各ターンのツールを実行した後、次にモデルへ何を渡すかだけを変えた。まず、推論、ツールの出力、または両方を削除の対象にした。両方を選ぶとツールの呼び出しも対象になる。次に、ターンごとに確率で選んでその部分を丸ごと取り除く方法と、各ターンから決まった割合のトークンを無作為に取り除く方法を比較した。前者は削除したことを示す短い文を残し、後者はその文と残った断片を残す。

直近2ターンを残す条件では、モデルは新しい出力をいったん読める。すぐに削る条件では、その出力に削除がかかると、モデルは元の内容を読む機会がない。各ターンを削るかは、対象になったときに一度だけ決める。

比較は削除の42構成に、削除しない基準5回を加えた。100課題、2種類のエージェントで計9,400実行。著者は変更したコードが関連するテストを通ったときに、その課題を解決したと数えた。上限は200ターンだった。

### なぜ、短くした位置から後ろの料金が変わるのか

著者が費用を推計する際は、前回と今回の入力を先頭から1トークンずつ比べる。最初に違う位置より前だけが、安い単価で再利用できる。たとえば前回が「指示、A、B、C」で、今回が「指示、A、C、D」なら、「指示、A」だけを再利用として数える。C は両方にあるが、その前で並びが変わったので、今回の C には通常の単価がかかる。

1回の呼び出しの費用は次の式で計算する。これは論文 §III-C の規則を Lab で式にしたものだ。

**C = p_new (n − c) + p_cache c + p_output o**

n は今回の入力トークン数、c は先頭から一致した数、o は出力トークン数。論文の単価の比は通常の入力1、再利用入力0.1、出力5だった。割引を使わない比較では、再利用分にも1を使う。作業全体の費用には、情報を読み直すために増えた呼び出しも足す。

### 読み直しと費用は、それぞれ別の分母で比べる

著者は、同じ実行の過去の読み取り結果と、異なる行の80%以上が一致する読み取りを「再取得」とした。5行未満の結果は対象外。通常の再取得率は再取得の回数を読み取りの回数で割る。一方、表IIIでは、残した結果のうち後で読み直した割合と、消した結果のうち後で読み直した割合を別々に求める。

費用とターン数は、削除した条件の100課題での中央値を、削除しない各回の中央値で割る。得られた5つの比を平均する。課題ごとの費用比を先に平均した値ではない。著者は対応する課題を10,000回取り直して95%区間を求めた。この区間は課題を選び直したときの揺れを表し、介入の再実行や削除の抽選の変動を含まない。
