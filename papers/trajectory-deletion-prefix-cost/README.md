# 履歴を短くすると、モデルに払う費用も減るのか

著者は、同じモデルを使う2種類のコーディングエージェントで、どの履歴をいつ消すかを比較した。直近2ターンを残した42評価では、すべての入力を同じ単価で数えると26評価で費用の推計値が下がった。一方、前回と同じ入力の先頭を安く再利用できる料金を使うと、安くなる評価はなかった。[論文の本文と表](https://arxiv.org/html/2610.35496v1)

Lab の作例では、同じ記号列を順に送る。途中から2記号を取り除くと、残った記号でも前回と同じ順序で始まらない部分には通常料金がかかる。初期設定では、延べ入力が72から66へ減る一方、合計費用は87.00から87.30へ増える。単位は作例の相対費用で、通貨ではない。

## 手元で再生成する

リポジトリの直下で実行する。`run.py` が144条件の費用を計算し、`render.py` がその結果と操作画面を生成する。計算には外部APIや実モデルを使わない。

```bash
uv run --locked python papers/trajectory-deletion-prefix-cost/run.py
uv run --locked pytest -q tests/test_deletion_cost.py
uv run --locked paper-lab build
```

- `method.md`：著者の比較と、入力を再利用するときの料金を説明する。
- `evidence.md`：解決課題、読み直し、料金の結果を区別する。
- `experiment.md`：Lab の作例で、入力の順序、再利用の割引、追加の読み取りを切り替える。
- `mapping.md`：原論文を参照した箇所と、Lab で確かめなかったことを確認する。

Lab が確認したのは、順序付きの記号での計算と画面への反映だ。実モデルの性能、処理時間、キャッシュの動作、実際の請求額は確認していない。著者が公開した実行ログや分析コードも実行していない。
