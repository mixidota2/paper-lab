# EXAONE Demand：需要の振る舞いで小さな補正を分ける

## 何を変えたモデルで、著者の評価はどうだったか
需要がめったに来ない商品と、需要はよく来るが数量の振れが大きい商品では、予測で捉えるべき違いがある。EXAONE Demand 1.0は、需要向けのデータで、需要の間隔や数量のばらつきに応じて補正を使い分ける時系列基盤モデル（TSFM）だ。22データセットのMASE幾何平均は1.0667。TiRex-1.1の1.0818との差は約1.4%にとどまる。Worth Readingとした理由は、この差の大きさより、古典的な需要分類を学習の手掛かりにした設計にある。

## 需要の間隔と量のばらつきは別の性質
売れる間隔と、一度に売れる量のばらつきは別の性質だ。欠品で販売数がゼロになる場合もある。一般的な時系列データだけで学習すると、こうした短く疎な需要系列の割合が小さくなる。ただし需要専用と呼ぶ本論文のコーパスも、系列数の39.87%、観測点数の67.51%がエネルギーで、小売はそれぞれ17.18%、1.33%である（Table 11）。

## 需要を分類して、予測モデルの補正配分を学ぶ
**著者の方法。** 学習用データは、合成した47,500系列を含め、全体で約1,130万系列・484億観測点になる。基盤モデル（backbone）の重みは変えず、全系列に共通する補正（LoRA）を1本、需要クラス別の補正を4本追加する。どの補正をどれだけ使うかは系列ごとに決める。LoRAは大きな重み行列を、小さな行列の積で補正する方法である。

**本Labの解釈。** 業種名で専門家を分けるより、需要が途切れる頻度と数量変動で分けるという設計が読みどころになる。境界に近い系列を1種類に決めつけず、複数の種類に近いものとして学ぶ。予測時には分類式を使わない。配分を決める小さなモデル（router）が、予測時点までの系列から得た8統計量を受け取り、比率を出す。

ADI = 観測期間数 / 非ゼロ期間数、CV² = 非ゼロ数量の分散 / 平均²とする。式5–6は対数軸上で境界を柔らかくする。

`a = sigmoid(log(ADI / 1.32) / 0.35)`

`c = sigmoid(log(CV² / 0.49) / 0.60)`

`π = [(1−a)(1−c), a(1−c), (1−a)c, ac]`

πの成分は、順にSmooth、Intermittent、Erratic、Lumpy。式10の教師分布は`π̃ = π² / Σπ²`で、温度T=0.5により優勢な成分を強める。routerはゼロ比率、ADI、CV²、時間との相関、1次自己相関、増加割合、全期間のCV、系列長を読む。式4では、ADI、非ゼロCV²、全期間CV、系列長の4つを対数で圧縮する。増加割合には2u−1を使う。π̃は分類統計から作る学習用の教師比率、qは学習済みのrouterが出す配分比率だ。画面で計算するのはπ̃までで、学習済みのqは出さない。各投影に配分器がある。どの配分器も同じ8統計量を読むが、配分は投影ごとに計算する。同じ投影では、系列内のすべてのトークンに同じ配分を使う。

式11は`y = W₀x + Σₑ gₑ (α/rₑ) BₑAₑx`。元の重みW₀は固定する。共通する補正に0.5を割り当て、残り0.5を4つの補正にqの比率で分ける。共有rank=16、各専門枝rank=4、α=8。24層×6投影=144か所へ付ける。式12はrank方向に枝を積み、行列積をまとめる実装である。

## 共通する癖と需要パターンごとの差を分ける
推測：共有枝が需要全般の補正を受け持てば、専門枝はクラス間の差へ容量を使える。生の系列から計算した統計量は、正規化後の表現で見失う需要の特徴をrouterへ渡す。ただしbackbone比の改善には学習コーパスとadapterの両方が含まれる。MASEの1.1050から1.0667への差には両方の変更が含まれるため、配分器だけの効果は分からない。

古典的なSyntetos–Boylan–Croston分類（2005）を教師信号へ転用した点が、容量拡張を狙うMoirai-MoEとの違いになる。Chronos-2、TiRex-1.1は直接の比較対象であり、Table 8にLightGBMなどの木モデルはない。

## 著者の予測誤差：22データセットで比較
一次資料の[原論文v1](https://arxiv.org/pdf/2609.30880v1)のTables 8–9で著者は、22データセットで需要の点予測の誤差（MASE）と、分位点予測の誤差（WQL）を比較した。下表はその著者報告で、Labは数値を再現していない。

| モデル | MASE幾何平均 | WQL |
| --- | ---: | ---: |
| EXAONE Demand | 1.0667 | 0.1138 |
| 合成データのみ | 1.0742 | 0.1147 |
| TiRex-1.1 | 1.0818 | 0.1161 |
| Chronos-2 | 1.0885 | 0.1406 |
| 凍結backbone | 1.1050 | 0.1169 |

MASEは履歴の季節naive誤差で正規化した絶対誤差で、小さいほどよい。MASEが1を超えても、同じ未来期間で季節naiveに負けたと直接断定はできない。分母は過去期間の誤差だからだ。データセット間は幾何平均で同じ重みを持つため、系列数の多いデータセットをその数に比例して重く扱う集計ではない。

Car partsのMASEは0.828、TiRexは0.916。対照的にElectricity (H)では1.010対0.912で負ける。22行中、掲載7モデルの最良は10行。実データ併用は合成のみより16行で改善する。全比較モデルへの勝率91.9%は836組の比較に対する割合で、系列の91.9%で勝ったという意味ではない。

著者自身が36の比較TSFMを同一手順で実行している。値の重複検査で学習候補358,008系列を除外したが、既存モデルの事前学習データには同じ除外を適用できず、比較は非対称である。評価には電力・M4・計算資源が多く、販促共変量、在庫費用、サービス率の比較はない。

## Labでは何を比較するか
`run.py`は5つの乱数seedで、4種類の人工需要を作る。各seedで別の160系列を使い、SES、Croston、SBA、TSBから全系列共通の手法を選ぶ。未使用320系列では150期間の履歴から30期間を予測し、同じ履歴とMASE分母で比べる。

比較する混合方式はSmooth→SES、Intermittent→SBA、Erratic→Croston、Lumpy→TSBという説明用の割当で、式5–6のπで平均する。この対応はLabの仮定で、論文の学習結果ではない。数量はGamma分布から生成して丸め、Bernoulliの抽選で需要が発生するかを決める。論文の負の二項分布による生成器とは異なる。

ページの平面ではADIとCV²を動かし、πとπ̃を比較する。在庫図では潜在需要を固定し、販売数だけが在庫量で制限される様子を見る。両者を分けて記録できることが、合成需要の利点である。

## Labでは混合が5回中4回で悪化
乱数の初期値を変えた5回のうち4回で、混合方式のMASEは検証用データで選んだ共通手法より悪かった。seed=19のみ0.8848→0.8702へ改善した。**安定した精度向上はNOT OBSERVED**。分類の重みが滑らかに変わっても、混合で予測が良くなるとは限らない。数値はresults.jsonに保存する。

## 式と人工例で確認したこと
MechanismはPARTIAL。式5–6の確率和、両境界での均等比率、数量を10倍してもADIとCV²が変わらない性質はCONFIRMED。古典予測器の混合を実行したが、学習routerやLoRAは実装していない。

## 手元で人工例を実行する
Python標準ライブラリだけを使う。リポジトリのルートで実行する。

```sh
UV_CACHE_DIR=/tmp/uv-exaone uv run --no-project papers/exaone-demand-routed-tsfm/run.py
```

`stats()`が式1–2の統計量、`membership()`が式5–6と10、`forecasts()`が4つの古典法を担う。乱数seed、検証方法、全22行の転記値はrun.pyに固定している。HTMLはlab.yaml、README、results.json、mapping.mdとwidget生成コードから作る。
