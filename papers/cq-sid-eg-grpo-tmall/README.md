# CQ-SID：検索語から商品群を選び、既存の順位付けに渡す

Efficient Generative Retrieval for E-commerce Search with Semantic Cluster IDs and Expert-Guided RL

Tmallの研究チームは検索語から商品ごとに異なるIDを出す代わりに、似た商品をまとめた群の識別子（SID）を出す方法を提案しました。モデルはカテゴリや検索ログを使って作った群の中から候補を選びます。Tmallは選んだ群を商品に展開し、既存の順位付けに渡します。

検索の候補を最大1,000商品にそろえたオフライン比較では、比較方式のRQ-VAEが65個のSIDを出した条件でクリック商品のヒット率は42.75%でした。CQ-SIDは30個で44.22%でした。著者はTmallアプリの検索で2週間のA/Bテストも行い、取引総額（GMV）が1.15%、UCTCVRが0.40%増えたと報告しました。本文にUCTCVRの詳しい集計方法はありません。全面導入後の72.63%は他の候補生成経路との重複を認めた上で、生成経路にも帰属する購入の割合です。購入件数の増加率ではありません。

一次資料：[論文第2版](https://arxiv.org/html/2605.14434v2)。Labの判定：Worth Reading。

## 仕組みを読む

[method.md](method.md)は、Tmallが商品群をどう作り、どの群を検索の候補にするかをモデルがどう学ぶかを説明します。[mapping.md](mapping.md)では、論文の各節とLabが確認した処理を照合できます。記事と図を定義する `lab.yaml` などから、公開用のページを生成します。

## 人工例を実行する

リポジトリのルートで次のコマンドを実行します。最初のコマンドは `run.py` と同じフォルダに `results.json` を出力します。二つ目は記事を含むサイトを生成します。

```sh
uv run papers/cq-sid-eg-grpo-tmall/run.py
uv run paper-lab build
```

Labの人工例では生成した群の数を3個から6個に増やすと、目当ての商品が上位20件から外れます。群を増やしたことで、後段の点がより高い商品も増えるためです。もう一つの例では、すべての候補が同じ報酬だと平均との差がゼロになり、クリックされた商品のSIDを足すと最初の更新に使う差が生まれます。群を分ける例では5,001商品を100群までしか分けないため、均等に近く分けても最大の群に51商品が残ります。

## Labが確認していない範囲

Labはカテゴリ表現の学習や、指数移動平均（EMA）によるコードブックの更新を再現していません。Qwen2.5-0.5Bの教師あり学習（SFT）やEG-GRPOの繰り返しも実装していません。通常のGRPOで候補の多様性が下がるか、本番のCTR・CVR・GMVがどう変わるか、平均約40msで応答できるかは検証していません。第2版は購入などを複数の経路に帰属できると明記していますが、詳しい帰属のルールや本番の順位付けの実装、ログの選択バイアスの大きさは確認できません。
