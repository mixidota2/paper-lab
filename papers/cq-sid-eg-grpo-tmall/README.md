# CQ-SID：商品群を生成し、Tmallの既存ランキングにつなぐ

Efficient Generative Retrieval for E-commerce Search with Semantic Cluster IDs and Expert-Guided RL

TmallAPPのCQ-SIDが生成するのは、意味の近い商品をまとめた群の識別子（SID）である。個々の商品IDは生成しない。生成したSIDに対応する商品を候補として取り出し、既存の順位付け処理に渡す。商品群を作る段階では、カテゴリの制約と、検索語と商品の組み合わせを学ぶ対照学習を使う。候補を生成するモデルは、EG-GRPOで既存の露出とクリックの記録に合わせて調整する。

著者は2週間のA/BテストでGMV +1.15%、UCTCVR +0.40%と報告した。一方、72.63%はすべての購入のうち生成による候補取得経路に帰属した割合であり、購入の改善率ではない。

一次資料：[arXiv 2605.14434v1](https://arxiv.org/pdf/2605.14434v1)。判定：Worth Reading。

## 読み方

lab.yamlに本文と図の定義があり、method.mdでモデルと数式を補足する。mapping.mdでは論文の各節とLabの実装を照合できる。run.pyで最小実験を実行し、results.jsonでその結果を確認できる。siteはこれらの原本から生成する。

## 実行

```sh
uv run papers/cq-sid-eg-grpo-tmall/run.py
uv run paper-lab build
```

## 検証の境界

Labでは、SIDから商品候補を取り出す処理を確認した。後段で残す件数に上限を設けると、生成時に探す範囲を広げても、目当ての商品が残りやすくなるとは限らない。同じ群の候補すべてが同じ報酬を得ると、群内の相対的な優位度（advantage）はゼロになる。正解の例を群に加えたときの報酬差と、最初の更新で使う勾配も確認した。また、分割先を最大100群に制限している。5,001商品を分けたときの最大群は51商品だった。

カテゴリ表現の学習、EMAによるコードブックの更新、Qwen2.5-0.5Bの教師あり微調整（SFT）、複数ステップにわたるEG-GRPOは再現していない。通常のGRPOで実際に学習が崩れるか、CTR・CVR・GMVがどう変わるか、配信時に40msで処理できるかも確認していない。ログにどのような選択バイアスがあるか、複数の経路で候補になった商品の成果をどこに帰属させるか、本番の順位付けをどう実装したかは、論文からは分からない。
