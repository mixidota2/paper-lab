# SGC：ゲーム中の助言を、いまの状態に合わせる

TencentのLiuらは、ゲーム中の助言が、プレイヤーの手持ちや直前の会話に合わなくなる問題を調べました。提案したSGCは、どのツールで調べるか、回答に必要な事実や制約は何か、次に何を提案するかを、文章を書く前に決めます。言語モデルは、自分で毎回これらを決め直す代わりに、ゲームと会話の状態をもとに決まった内容を受け取ります。

著者らは実際のゲームのログをもとにした200セッション、約1,000回答を比較し、人が各回答を採点しました。3つの仕組みをすべて使うと、状況に合う回答の割合はセッションごとの平均で96.7%でした。すべての回答が基準を満たしたセッションは83.5%で、先に計画を作る比較方式の26.5%を上回りました。回答が始まるまでの平均は、最初のトークンで測って1.5秒、比較方式では6.1秒でした。この比較は回答の採点と待ち時間を扱い、勝率や継続率がどれだけ変わったかは示していません。

## どんな問題を扱うか

攻略情報では正しい技でも、プレイヤーがまだ解放していなければ、その場では使えません。質問に沿った回答でも、今の所持品を取り違えたり、直前に見送った助言を繰り返したりすると、プレイヤーにとって使いづらくなります。著者らは、状況に合わない方向へ回答が進む失敗をdirection driftと呼びます。

## どこで役に立つと考えられるか

必要条件を先に照らし合わせれば、文章が自然かどうかとは別に、その助言を実行できるかを検査できます。同じ候補、状態、設定、乱数の初期値を使えば、履歴に基づく提案を再現できます。ただし、質問から取り出した条件が間違っていたり、参照した状態が古かったりすると、規則で選んだ助言も間違います。規則だけで最終回答の意味まで保証する方法ではありません。

## 著者らが比較した結果

[一次資料：原論文§7、表3〜4、付録G](https://arxiv.org/pdf/2609.27606v1)。著者らは約4週間分のゲームのログから抽出した200セッションで、同じ言語モデル、ツールの定義、参照証拠を使って5条件を比べました。プロンプトだけの条件は実際にはツールを使いません。2人が独立に採点し、食い違いは3人目が裁定しました。表の採点結果は人の判定に基づきます。応答時間は、同じ機器とネットワークで、準備運転の最初の要求を除いて測りました。

| 比較した構成 | 最初のトークンまでの平均（秒） | 状況に合う回答（TGA、%） | 全回答が基準を満たしたセッション（SGA、%） | 助言の質／進展／一貫性 |
| --- | ---: | ---: | ---: | --- |
| プロンプトのみ | 2.3 | 61.1 | 20.0 | 6.2 / 4.7 / 8.3 |
| 先に計画してから実行（PE-Agent） | 6.1 | 69.8 | 26.5 | 6.5 / 5.5 / 8.1 |
| W1 | 1.5 | 89.1 | 46.5 | 8.4 / 7.7 / 9.0 |
| W1とW2 | 1.5 | 89.9 | 56.5 | 8.4 / 7.7 / 8.9 |
| W1、W2、W3 | 1.5 | 96.7 | 83.5 | 8.6 / 8.5 / 9.2 |

TGAは、セッションの中で状況に合う回答が何割かを求め、セッションに同じ重みを付けて平均します。SGAは全回答が基準を満たしたセッションの割合です。右端は、助言の質（TGQ）、対話を通じた進展（DGP）、回答どうしの一貫性（CCC）を1〜10で採点した結果です。比較方式で73.5%だった基準未達のセッションは、完全版で16.5%でした。相対的に約78%減ったのはこの採点上の比率で、製品の障害件数ではありません。

著者らは、比較方式をSGCと同じ量だけ製品向けに調整していません。差には構成の違いと調整の影響が含まれます。機能を順に足した結果から、各機能を単独で使った効果や、追加する順を変えた結果は分かりません。公開版では、言語モデルの具体名、評定者の一致度の全件集計、一部の統計表は確認できません。

## 教材で試すこと

Labは、プレイヤーがA、B、Cを持ち、Aに必要な技skill-Xだけはまだ使えないと仮定します。毎回同じ優先順で選ぶ規則、所持条件を照らし合わせる規則、条件に加えて履歴も見る規則を、同じ12ターンで比べます。言語モデルは使いません。

## 教材の結果

優先順だけで決める規則は、使えないAを12回提案しました。所持条件を確かめる規則では、使えない提案は0回でしたが、Bを続けて出した組が11ありました。履歴も見る規則では、使えない提案と連続した同じ提案がともに0回で、提案を見送ったのは2回でした。連続した提案は、隣り合うターンで同じ候補を出した組を数え、見送りを挟む再提案は数えません。これはLabの架空の結果で、論文の採点結果を再現したものではありません。

## Labで確かめたこと

**仕組み：一部確認（PARTIAL）。** Labは、条件を満たせない候補を除き、直前に提案した候補を見送ることを確かめました。乱数の初期値をそろえれば同じ提案になること、選べる候補がなければ提案しないことも確認しました。W1の教材では、必要な試合状態がない場合と、登録していない意図の場合に、ツールを先に確定しません。

## Labで確かめていないこと

Labは、言葉から意図や条件を読み取る処理、生成中のタグ解析、実ツールの並列実行、最終回答の矛盾のなさを検証していません。著者らの200セッションの採点や最初のトークンまでの1.5秒を再現していません。処理の規模を広げた結果、実製品のA/B結果、ECやコード補完での効果、IGPOとの統合も未検証です。

## 実装の読み方

`run.py` はPythonの標準ライブラリだけで動きます。`freeze_tools()` は登録した意図と試合状態を見て、先にツールを確定するかを返します。`ground()` は必要なもののうち、所持していないものを返します。`schedule()` は、見送る候補を除き、抽選して残った候補から選びます。`replay()` は選んだ候補を履歴に記録します。教材は待機を1ターンに固定します。軽い不足や注意の判定、段落の組み合わせの全規則、文章の生成は実装していません。

## 実行と配布資料

Pythonの標準ライブラリだけで動きます。

```bash
uv run papers/sgc-state-grounded-conditioning/run.py
```

スクリプトは実行結果を同じフォルダの `results.json` に保存します。仕組みは[手法](method.md)、出典と教材の対応は[対応表](mapping.md)を参照してください。
