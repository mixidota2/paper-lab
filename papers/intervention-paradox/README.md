# 介入の逆説：失敗を当てても、止めるほど成功が減ることがある

Accurate Failure Prediction in Agents Does Not Imply Effective Failure Prevention

Writerの著者はエージェントの失敗を予測できれば、実行途中に巻き戻したり助言を加えたりして成功率を上げられるかを調べました。失敗を見分けるモデルのAUROCは約0.94でした。著者は同じ課題を介入ありとなしで比べ、介入で失敗から成功に変わった件数と、逆に成功を崩した件数を数えました。

質問応答のHotPotQAではMiniMax-M2.1の実行を途中で巻き戻すと、成功率は64%から38%に下がりました。一方、ALFWorldでQwen-3-8Bに助言を加えた設定では、成功率は5.8%から8.6%に上がりました。どちらもベンチマークでの結果です。失敗予測の精度だけでは、介入で成功が増えるかは判断できません。

一次資料：[arXiv 2602.03338v1](https://arxiv.org/pdf/2602.03338v1)。判定：Worth Reading。

## 同じ課題の最後の結果を比べる

介入が役立ったかを調べるには、介入で失敗から成功に変わった課題と、成功から失敗に変わった課題を同じ実験で数える。前者が後者を上回ると、成功する課題が増える。失敗を高い精度で見分けられても、回復しやすさや成功を崩しやすさは別に調べる必要がある。

`lab.yaml` は記事と図の原稿、`method.md` は論文の手法、`mapping.md` は論文とLabの計算の対応を記す。

## 検証の範囲

Labでは、同じ課題の結果から成功率の差を数えた。また、介入なしで失敗した課題や成功した課題が1件もないとき、対応する割合を計算できないことを確かめた。観測された変化がなく、回復率と成功を崩す割合がともに0の場合も境界は決まらない。

仮定した確率で50課題の試験を繰り返すと、平均的には介入が有利でも、観測した成功率の差が正にならない場合がある。論文の失敗予測器の学習、AUROC、LoRA、温度調整、巻き戻し時の環境復元、警告後のモデルの反応、p値は再現していない。50課題で安全を保証できるわけではなく、別の環境やAgentTetherのような別の修復手法にも同じ割合が当てはまることは確かめていない。
