# UniVA：生成した広告候補を価値と配信条件で選ぶ

UniVA: Unified Value Alignment for Generative Recommendation in Online Advertising at Tencent

Tencentの研究チームは、広告の内容が似ていても、入札額や広告主の目標が違えば、表示したときに見込まれる価値は変わると考えました。UniVAは、その違いを広告の識別子（SID）の末尾に表します。モデルが候補を選ぶときは、識別子を出す確率と、その候補がもたらす価値の予測を組み合わせます。その時点で配信できない広告につながる候補は、探索の途中で外します。

WeChat ChannelsのA/Bテストで、著者は完全な構成の取引総額（GMV）が従来方式より1.50%増えたと報告しています。この構成では学習方法と候補の選び方を一緒に変えており、どちらか片方の効果ではありません。同じ実験のトラフィックの割合は初版に5%、第2版に20%と記載され、変更の理由は本文からは分かりません。

一次資料は[arXivの第2版](https://arxiv.org/pdf/2605.05803v2)。Labの読む価値の判定はMust Read。

## 読み方

記事本文と図のデータは `lab.yaml` にある。モデルの構成や数式は `method.md`、論文とLabの実装の対応は `mapping.md` で確認できる。Labは `run.py` で計算した結果を `results.json` に保存する。Webページはビルド時に `site` に生成される。

## 実行

```sh
uv run papers/univa-commercial-sid-gar/run.py
uv run paper-lab build
```

## 検証の範囲

Labは合成した広告を使い、商用属性で分けた各グループに、件数が等しくなるよう入札額の区間を作った。また、2段の人工の探索木で、固定の価値予測を生成ロジットに足す処理と、途中まで選んだトークン列ごとに確率を正規化する処理を実行した。無効な枝を除く時点と探索幅を変えたときの候補を `results.json` で比べられる。

LabはRQ-KMeans+、HSTU、MoE/MoR、PPO、MCTS、商用語彙の最適配分を学習・再現していない。実際の入札、配信条件の判定、eCPMのシミュレーター、本番のGMVや遅延も検証していない。従来の順位付けの工程をすべて除けるか、入札額の変動に対応できるか、利用者の長期満足度や広告主の公平性がどう変わるかも未検証だ。
