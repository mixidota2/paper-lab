# 論文と教材の対応

論文と教材は、得点が下がったときに操作の変化と採点の変化を分けます。Labでは在庫を8から5へ直す架空の例を使い、著者のベンチマークやモデルは動かしません。

| 論文の箇所 | Labでの説明 | 結果の範囲 |
|---|---|---|
| §2、図1 | 元と変更後を実行して点差を測り、操作と状態を比べてから、同じ記録を再採点します。 | 原論文の図版は転載していません。 |
| §3.1、図2 | `run.py` の `rollout` は別名でも同じ操作をする例、`score(normalize=True)` は名前を読み替えて採点する例です。 | 論文の0.250という点差は再現していません。 |
| §3.2、表2 | いつも書き込みを省く例では、両方の条件で失敗し、点差が0になります。 | 点差が小さいだけでは仕事に成功したと言えません。 |
| §2.2 | VRGは元の点数から変更後を、表6のΔは変更後の点数から元を引きます。 | MTRの分母は元の条件が合格した組だけです。元がすべて不合格なら定義できません。 |
| §5、付録Eの表6 | `evidence.md` と `results.json` の `reported` は主な比較の88課題×3回と、差が出るかをみる対照の158課題×2回を分けています。 | 90%と95%の区間を取り違えないようにし、Qwenの表示変更は判断保留としています。 |
| §5、付録Eの表8 | 著者は118件の固定した記録に対し、二つの採点モデルが同じ判定を出すか調べました。 | 既存の採点との一致率は正答率ではありません。 |
| Labの合成例 | `run.py` が `results.json` の `synthetic` と `experiment.md` を生成します。 | 操作列と状態のSHA-256が一致しても、別の環境でも操作の意味が同じとは限りません。 |
