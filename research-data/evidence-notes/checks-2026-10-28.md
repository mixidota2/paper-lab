### Author evidence and source mapping

- §III: DeepSeek-V4-Flash, mini-SWE-agent and Trae, 100 fixed SWE-bench Verified tasks. 42 configurations = 3 scopes × (4 whole-turn deletion amounts + 3 token-deletion amounts) × 2 timings. 8,400 single intervention runs + 1,000 baseline runs (5 × 2 × 100) = 9,400. **Interventions were not repeated five times.**
- Table I / §IV: delayed deletion: 37/42 evaluations have no significant success decrease, but 21/42 longer runs. This is not equivalence. Immediate deletion loses significantly in 19/42 and lengthens 34/42. All Table I rows read; cap marker means median reaches200, not missing data or automatic failure.
- Table II / §VI: manually counted all42 delayed cache-cost point ratios >1; flat ratios <1 in26 (mini14, Trae12). Authors report26 significant cache increases and6 significant flat decreases; significance is from their bootstrap, not independently reproduced. Example mini/tool-output/turn100/delay2: success69 versus baseline72.6; turns+19%; flat0.71, cache1.20. Trae/both/token75/delay2:60 successes, median cap, flat3.73/cache4.94.
- Table III / §V: every rounded deleted-output percentage exceeds retained-output percentage; the denominator is original read outputs later re-fetched, unlike Table II's re-fetches/read calls. Maximum rounded ratio38/7≈5.4: say **about fivefold**, not a strict upper bound5. Authors find23/24 paired differences significant.
- §§III-D,VII: task-paired bootstrap10,000,95%; intervention randomness is not separately resampled. One model, public100-task subset, unequal token mass across scopes, fixed200-turn cap. Scope effects are not isolated from deletion volume; test passing is not manual verification of every patch. Learned selection/summarization and longer-delay policies are not tested.

### Exact pricing semantics (our mathematical transcription, not a numbered author equation)

For prompt token sequence `P_t`, output-token count `O_t`, and `K_t = LCP(P_t,P_(t−1))`, with `K_1=0`:

`C_flat = Σ_t (|P_t| + 5 O_t)`

`C_cache = Σ_t (|P_t| − K_t + 0.1 K_t + 5 O_t)`

This is §III-C's relative input:cached:output pricing **1:0.1:5**. Compare with the **previous prompt**, not previous prompt plus completion, a bag of previously seen strings, or a global cache over arbitrary earlier prompts. Prefix matching is token-for-token and stops at the first mismatch. Rewrite position matters; after a rewrite, a later append-only call can reuse the new prefix again (Fig1).

§III-E uses self-hosted inference with **no metered API charges**. Cache estimates assume every matching prefix is available and omit cache-write premiums, minimum cache length, TTL and eviction. The authors call absolute estimated cost a lower bound; that does not prove their relative ratio is a lower bound for all providers. Do not label these estimates actual bills or universal savings/losses.

For costs/turns, §III-D uses `mean_j(median_i(intervention_i) / median_i(baseline_ij))`, j=1…5. It is not ratio of pooled medians, not mean of per-task cost ratios, and not cost per successful task. Success and re-fetch comparisons instead use per-task baseline means. Cost-per-success is explicitly future work (§VI), not an author result to invent.

### Our changed understanding

Existing2609.29875 asks whether state can be externalized before forgetting; this paper asks whether the agent buys that missing state back and whether the accounting still favors deletion. The substantive update is **semantic recoverability ≠ zero recovery work ≠ cached-price savings**. Success plus total tokens alone is an inadequate compression scorecard. The controlled random-deletion study supports a measurement requirement, not a conclusion that all useful compression loses money.
